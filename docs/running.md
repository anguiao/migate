# 运行 MiGate

当前支持 macOS / Apple Silicon，需要 Rust 1.96 和 Cargo。仅支持中国大陆服务区，一次运行接入一个米家自有家庭。首次绑定时，Mac 与该家庭的小米主中枢须处于同一局域网。

## 启动

在仓库根目录执行：

```sh
cargo run --locked -- auth login
cargo run --locked
```

首次登录按下方「米家账号」完成授权，之后日常启动只需第二条命令。仓库的 Cargo 配置默认使用项目下的 `.migate/` 保存数据；重启时继续使用同一目录，即可保留账号、名称和 Apple Home 配对。

程序在前台运行，使用 Ctrl-C 或 SIGTERM 停止；终端输入结束（EOF）不会停止服务。同一数据目录只能由一个进程使用，执行认证命令前也需先停止网桥。

也可以构建后直接运行：

```sh
cargo build --locked --release
./target/release/migate --data-dir .migate
```

直接运行构建产物不会读取仓库的 Cargo 环境配置，请明确指定原数据目录。

## 米家账号

以下命令在 shell 中执行。登录和账号检查需要联网。

### 登录

```sh
cargo run --locked -- auth login
```

1. 打开终端显示的授权链接，登录米家账号并授权 HA 应用，无须安装或运行 Home Assistant。
2. 浏览器跳转到 `http://homeassistant.local:8123/api/webhook/…` 后，即使页面显示无法访问，也复制地址栏中的完整网址。
3. 将完整网址粘贴回等待中的终端并回车。若授权已失效，重新执行登录命令，从新的授权链接开始。
4. 终端显示 `Xiaomi: authenticated (cn).` 和 `Gateway certificate: valid until …` 后，登录完成。

### 检查与退出登录

```sh
cargo run --locked -- auth check
```

检查会显示账号与证书状态，并在需要时自动更新。提示 `sign-in required` 时，重新执行 `auth login`，再使用原数据目录启动；网络故障时待恢复后重试。

退出登录：

```sh
cargo run --locked -- auth logout
```

该命令删除本地米家账号凭据，保留 Apple Home 配对，也不会撤销远端 HA 应用授权。

## 添加到 Apple Home

Mac 与 iPhone / iPad 须处于同一局域网，并保持 Mac 唤醒。网络需允许 mDNS 发现和 Matter UDP 通信，默认端口为 5540。

1. 启动 MiGate，等待终端显示二维码和手动配对码。暂无受支持设备时，也可以先添加网桥。
2. 在「家庭」App 中添加配件，扫描二维码或输入手动配对码。
3. 当前尚未通过 Matter 认证。如提示配件未认证且提供继续入口，可选择继续添加。
4. 完成 App 中的房间与名称配置。

配对窗口为 15 分钟。超时后用 Ctrl-C 停止，再以同一数据目录启动即可重新打开。

设备初始名称来自米家，之后可在 Apple Home 中独立改名。多路插座可能显示同名或默认编号，请逐路操作、核对实际通道后分别改名，不要根据显示顺序判断通道。

## 设备接入

MiGate 自动接入当前家庭中受支持的插座和单灯，用 `list` 查看设备状态或未接入原因。插座提供基础开关；灯具按实际具备的能力提供开关、亮度、色温和彩色控制，调光和调色在 Apple Home 中操作。代表型号见 [README](../README.md)，兼容性与功能边界见[已知限制](known-limitations.md)。

缺少开关能力或色温量程无法映射为 Matter 标准灯时，MiGate 保留设备已保存的能力、名称和身份，但不会在 Apple Home 中创建配件；`list` / `status <DID>` 会显示未发布原因。读取或解析暂时失败不会删减已保存的能力，也不会改变已确认的灯组关系。已有灯具收到不兼容描述时保持不可用，使用 `status <DID>` 查看原因并核对设备固件及 MIoT 描述；保留原数据目录和配对。

米家灯组按当前家庭内非空、扁平且成员全部可作为单灯发布的关系接入；成员能力可以不同，同一盏灯可以加入多个组，物理组和虚拟组规则相同。用 `list` 查看组名称、成员 DID、派生能力和共同色温范围；用 `status <组 DID>` 查看实际聚合状态、成员控制路径与已有请求诊断，以及未发布原因。成员增删和关系变化跟随目录同步，通常等待下一次约五分钟的同步；成员加入或退出不改变成员的身份、名称或配对；仅调整目录顺序不改变成员关系。某组读取失败时保留它最后确认的关系，其他组继续更新。关系未发布时，`list` / `status` 会显示待确认原因，等待自动同步恢复即可；Apple Home 中的组入口与控件是否按预期显示，需按[已知限制](known-limitations.md)在 `review` 阶段真机验收。

用 `status <成员 DID>` 查看成员的全部所属组。共享成员变化会更新各组状态；成员只有退出最后一个已发布组后，才恢复 Apple Home 中的独立入口。

成员失去全部可用路径后，其离线缓存按未知参与组聚合；路径恢复本身不会让旧值重新有效，相应字段取得新的有效状态后才重新纳入。此规则只影响组聚合，独立单灯仍显示原有缓存值。

在米家家庭中加入或移出设备后，通常等待自动同步即可，必要时等待下一次五分钟同步；同步需要云端可用。家庭绑定后，新设备加入及重新加入不再依赖中枢本地接口。断电、断网、改名或换房间不会删除设备，有可用控制路径后会自动恢复。

设备增删、灯组成员关系或发布能力变化时，MiGate 自动重建 Matter 服务，整座桥上的灯具及插座可能短时无响应。请等待服务恢复和 Apple Home 展示自行收敛，无须重启程序、重新配对或手动刷新；身份、名称和配对信息会保留。米家连接和状态同步继续运行，未完成的渐变／Move／Step 可能中断；服务恢复后按需重新操作，程序不会续跑或重放旧动作。成员关系变化或设备从家庭删除后重新接纳，即使未改变对外发布内容也会重建；普通状态变化、断线重连、原设备的绑定更新及相同关系的重复同步不会触发重建。

重启或重新加入的设备保留 MiGate 保存的身份与名称，后续米家改名不会覆盖已保存名称。设备移出后重新加入时，Apple Home 中原有的房间、场景或自动化可能需要重新设置。

灯组首次出现在 Apple Home 时，组入口名称可能沿用米家名称，可用 `list` / `status <组 DID>` 核对组身份、成员 DID 与名称，再在「家庭」App 中按需改名。

## 日常操作

在运行 MiGate 的终端中，每行输入一个命令：

| 命令 | 操作 |
| --- | --- |
| `list` | 查看设备与组、DID、通道、派生能力与共同范围、状态及未发布原因 |
| `status [DID]` | 查看能力与组关系、实际聚合、成员控制路径与请求诊断、通知来源及账号和中枢状态 |
| `on DID [channel]` | 开启指定设备通道或整个已发布灯组（组不带通道） |
| `off DID [channel]` | 关闭指定设备通道或整个已发布灯组（组不带通道） |
| `help` | 查看命令帮助 |

先用 `list` 查找 DID 和通道键。单路设备可省略通道，多路设备必须指定。以下 DID 为示例，请替换为实际值：

```text
list
status 123456789
on 123456789
off 123456789 main
on 987654321 outlet_1
off 987654321 outlet_2
on 987654321 usb
status group.123456789
on group.123456789
```

终端输出使用英文，设备名称原样显示。`unknown` 表示尚未获得有效状态；设备不可用时，显示值可能是断线前状态。`command accepted` 表示请求已受理，不保证物理动作已完成。命令超时后也可能已经执行，请先核对设备状态；MiGate 不会自动重放该命令。

`on` / `off` 对独立单灯接受 DID（单路可省略通道），对已发布的组 DID 直接整组执行且不带通道；组命令按触发时的成员集合分发，至少一个成员完整受理即返回成功，其余成员继续执行，用 `status <组 DID>` 查看成员当前状态、路径及已有请求诊断。仍在等待配置应用（未发布）的组会被拒绝。成员 DID 仍可用于单控诊断。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 没有发现设备 | 用 `list` 查看原因，确认登录账号、米家家庭及云端连接；首次绑定还需 Mac 与中枢处于同一局域网。程序会继续同步，无须反复重启。 |
| 灯没有出现在 Apple Home | 用 `list` / `status <DID>` 查看是否缺少开关能力或色温量程无法映射为标准灯。此时 MiGate 保留设备的能力、名称和身份但不发布配件；保留原数据目录和配对，等后续具备可映射能力的完整描述同步后会自动按原身份恢复。读取或解析失败不会删减已保存的能力，等待自动同步即可。 |
| 灯组显示待确认或未组合 | 用 `list` / `status <组 DID>` 查看原因。嵌套组、成员重叠、存在无法作为单灯发布的成员，或派生共同色温范围无法表达为整数 mired 时不会组合，可发布的成员仍作为独立单灯；读取失败或信息未就绪时等待下一次约五分钟同步。保留原数据目录和 Apple Home 配对即可，无须重新配对。 |
| 灯组命令被拒绝 | 只存在于待应用配置中的组尚未发布，对组 DID 执行 `on` / `off` 会被拒绝；等待目录确认并完成配置应用后重试。成员 DID 仍可用于单控诊断。 |
| 配置应用失败 | `list` / `status` 会显示最近一次失败原因，此时仍使用已应用的组关系和发布集合；程序会自动重试。保留原数据目录，按错误信息排查，无须重新配对、删除数据或手动刷新。 |
| 设备显示不可用 | 检查设备供电、中枢和网络，用 `status DID` 查看当前路径与请求结果，恢复后等待自动重连。 |
| 米家主中枢切换 | 程序会自动连接新的主中枢，无需重新配对 Apple Home。若米家已正常但 MiGate 持续不可用，参见[已知限制](known-limitations.md)。 |
| 云端暂时不可用 | 等待网络或服务恢复。已有设备在本地连接和证书有效时仍可控制，新设备接入与移除同步可能延迟。 |
| 提示需要重新登录 | 停止网桥，执行 `auth login`，然后用原目录重启。 |
| 提示数据目录正在使用 | 停止使用该目录的另一个 MiGate 进程，再重试；不要删除锁文件。 |
| Apple Home 无法发现网桥 | 确认配对窗口仍有效、Mac 未休眠，且网络允许 mDNS 和 Matter UDP 通信。 |

本地不可用时，MiGate 会尝试使用可用的云端路径。云端仍可能依赖设备所用的物理网关，不能保证网关断电后仍可控制。

需要详细日志时：

```sh
RUST_LOG=info,migate=debug cargo run --locked
```

日志写入标准错误，终端命令结果和配对信息写入标准输出。组关系或发布变化后，`Directory configuration confirmed` 表示目录已确认，`Matter configuration pending` 表示配置待应用，`Matter configuration applied` 表示配置已提交；需要重建时，以随后出现的 `Matter UDP listening` 确认服务重新就绪。服务已恢复但 Apple Home 未变化时，继续观察 Home 自行收敛。

若默认端口被占用，可通过 `MIGATE_MATTER_PORT` 设置其他端口；设为 `0` 时由系统分配，启动日志会显示实际端口。运行多个网桥时，分别使用独立数据目录和不同端口。

## 数据目录与重新配对

数据目录包含账号凭据、证书、设备名称与配对信息，请妥善保留，避免提交或共享。首次使用的目录须为空或尚不存在。

目录选择顺序为：

1. `--data-dir <PATH>`，该参数须放在 `auth` 之前。
2. `MIGATE_DATA_DIR` 环境变量；仓库的 Cargo 配置默认将其设为项目下的 `.migate/`。
3. `~/.migate/`。

相对路径按命令执行目录解析，启动日志会显示实际路径。异常退出后可直接使用原目录重启，无须删除 `instance.lock`。当前程序仅打开当前格式的数据，不自动升级旧版数据库。若提示数据库版本不受支持或读取失败，请保留原目录，使用对应版本的程序或单独处理数据兼容问题；不要删除原数据。

在线从「家庭」App 移除配件后，可使用原目录重新配对。若离线移除后无法重新配对，或需要全新实例，可选择与原目录并列的新目录：

```sh
cargo run --locked -- --data-dir .migate-trial-1 auth login
cargo run --locked -- --data-dir .migate-trial-1
```

新实例需要重新登录米家账号并添加到 Apple Home，原目录的数据会保留。
