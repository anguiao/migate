# 运行 MiGate

当前支持 macOS / Apple Silicon，使用 Rust 1.96 和 Cargo 构建。MiGate 通过本地小米中枢桥接本轮选定的一个真实插座，提供基础开关、状态通知、Matter 桥接与米家账号认证。产品不再提供虚拟灯或失败时的替代设备。

以下命令在仓库根目录执行。仓库的 Cargo 配置默认使用项目下的 `.migate/` 保存数据；继续使用已有实例时，保持同一数据目录。

## 启动

```sh
cargo run --locked -- auth login
cargo run --locked
```

Mac 与小米中枢必须处于同一局域网，中枢所属家庭须为当前账号的自有家庭，目标插座须支持中枢的 MIoT 属性读写和主动通知。网桥根据本地发现的家庭范围读取设备描述，不提供云端控制、远程家庭接入或持续轮询替代推送。

首次接入需完成能力解析、认证连接、订阅和初始读取才启动 Matter 拓扑；失败会报告原因并退出。已有同一账号的静态缓存时，可先提供原拓扑，开关为 `unknown`、设备不可达，随后通过当前局域网中枢重新订阅和读取。缓存不保存当前在线状态或开关值，也不保存可供远程连接的地址。

程序在前台运行，使用 Ctrl-C 停止，同一数据目录一次只运行一个网桥进程。中枢断线或设备离线时保留 Matter 拓扑并报告不可达，重新发现、连接、订阅和读取成功后恢复控制；不会重发断线前结果不明的写入。

Matter 默认使用 UDP 5540。可通过 `MIGATE_MATTER_PORT` 设置端口（`0`–`65535`），设为 `0` 时由系统分配空闲端口；启动日志显示实际端口。运行多个网桥时，分别使用独立数据目录和不同端口。

也可以构建后直接运行：

```sh
cargo build --locked --release
./target/release/migate --data-dir .migate
```

直接运行构建产物不会读取 Cargo 的环境配置；未指定目录时，依次使用 `MIGATE_DATA_DIR` 和 `~/.migate/`。因此直接运行时请明确复用原实例目录。

### 调试构建

默认开发构建仅为项目代码保留回溯所需的行号信息，第三方依赖不生成调试信息。需要使用 LLDB/GDB 检查变量或进入依赖源码时，使用 `debugging` profile：

```sh
cargo build --locked --profile debugging
```

产物位于 `target/debugging/migate`，项目和第三方依赖均启用完整调试信息。首次使用该 profile 会重新构建并额外占用磁盘空间。也可通过以下命令构建并启动：

```sh
cargo run --locked --profile debugging
```

## 米家账号认证

认证需要联网，目前仅支持中国大陆服务区（`cn`），每个数据目录保存一个账号。以下认证命令在 shell 中执行。

### 登录

```sh
cargo run --locked -- auth login
```

1. 打开终端显示的授权链接，在浏览器中登录米家账号并授权 HA 应用，无须安装或运行 Home Assistant。
2. 浏览器跳转到 `http://homeassistant.local:8123/api/webhook/…` 后，即使页面显示无法访问，也直接复制地址栏中的完整网址。
3. 将包含 `code` 和 `state` 的完整网址粘贴回等待中的终端并回车。使用本次授权得到的网址；若回调已失效，重新执行登录命令，从新的授权链接开始。
4. 等待终端显示 `Xiaomi: authenticated (cn).` 和 `Gateway certificate: valid until …`，即完成登录。

### 检查与退出登录

```sh
cargo run --locked -- auth check
```

检查分别显示账号认证与证书状态，并在需要时刷新令牌和续期证书。两项均正常才表示独立检查成功；提示 `sign-in required` 时按显示的命令重新登录，网络故障时待网络恢复后重试。

网桥启动也复用令牌刷新与证书准备，但设备目录读取限定为本地匹配家庭。具备同一账号的静态缓存、有效证书并通过本地中枢认证和设备访问检查时，云端暂时故障或要求重新登录不会阻止本地控制；登录提示仍会保留。云端认证状态和中枢连接状态分别展示，不能仅凭认证成功判断设备可用。

运行期间没有定时云端检查或跨进程凭据同步。同一数据目录的认证操作应依次执行，避免与网桥启动准备重叠；通过独立命令更新凭据后，重启网桥加载。

退出登录：

```sh
cargo run --locked -- auth logout
```

该命令删除本地米家账号凭据，保留网桥身份与 Apple Home 配对，也不会撤销远端 HA 应用授权。

## 添加到 Apple Home

Mac 与 iPhone / iPad 需处于同一局域网，网络允许 Matter 使用的 UDP 端口（默认 5540）与 mDNS 发现，并保持 Mac 唤醒。

1. 启动网桥；完成设备准备或加载静态缓存后，尚未配对的实例会显示二维码和手动配对码。
2. 在「家庭」App 中添加配件，扫描二维码或输入终端显示的手动配对码。
3. 当前使用测试认证材料。如提示配件未认证且提供继续入口，可选择继续添加。
4. 真实子设备声明 On/Off Plug-in Unit（`0x010A`，revision 3），默认标签来自型号和 DID，可通过 Matter 修改标签；标签不决定身份。

当前只实现基础 On、Off、Toggle 与 Reachable，不包含 Lighting、计时关闭、全局场景或 Scenes Management。标准插座类型要求这些功能，因此当前存在已知符合性限制，不能声称完整符合标准插座要求；Apple Home 的基础链路兼容性仍需真机验证。Identify 与 Groups 保留通用协议行为。

配对窗口为 15 分钟，超时后用 Ctrl-C 停止，再以同一数据目录启动即可重新打开。

## 日常操作与退出

在运行网桥的终端中，每行输入一个命令：

| 命令 | 操作 |
| --- | --- |
| `on` | 请求开启真实插座 |
| `off` | 请求关闭真实插座 |
| `status` | 查看当前开关值、可用性、认证及中枢连接状态 |
| `help` | 查看命令帮助与认证及中枢连接状态 |

终端和 Matter 使用同一个设备状态与命令入口。首次读取前开关值为 `unknown`，Reachable 为 false，Matter 开关读取返回错误。不可用时可以显示最近的内存快照，但它不代表设备此刻的实际状态。

`command accepted` 仅表示中枢已受理。受理后立即乐观更新目标值，后续合法属性通知或恢复读取覆盖同一快照；不能把成功输出当作真实动作已确认。实体按键和米家 App 的变化依赖主动通知，同值不重复报告。推送缺失时，乐观值可能保持到后续通知或恢复读取，不提供固定期限纠正、自动回滚或每次写入后的定时读回。

命令拒绝、超时和发送失败会显示错误，终端仍可继续操作。Ctrl-C 停止网桥并取消未完成请求；输入 EOF 只停止终端读取，桥接服务仍继续运行。重启时开关重新从 Unknown 开始，经中枢读取恢复，不持久化运行期开关值。

## 数据目录与重新配对

数据目录保存账号凭据、网桥与真实设备身份、静态能力缓存和 Matter 协议数据，请妥善保留，避免提交或共享。首次使用的目录必须为空或尚不存在。

通过 `--data-dir <PATH>` 选择目录时，该参数须放在 `auth` 之前。未指定时依次使用 `MIGATE_DATA_DIR` 环境变量和 `~/.migate/`；仓库的 Cargo 配置会在未设置该环境变量时使用项目根目录的 `.migate/`。相对路径按命令执行目录解析，启动日志会显示实际使用的路径。

同一数据目录的正常重启保持网桥、真实插座身份和配对；地址或中枢变化不会改变身份。虚拟灯时期的拓扑与配对不保证兼容，旧数据不会因此自动清除。在线从「家庭」App 移除配件后，可使用原目录重新配对；离线移除后网桥可能仍保留配对，此时可用并列的新目录开始独立实例：

```sh
cargo run --locked -- --data-dir .migate-trial-1
```

新目录代表独立实例，需要重新登录米家账号和添加到「家庭」App。请选择与原目录并列的新目录，原目录的数据会保留。
