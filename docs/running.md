# 运行 MiGate

当前支持 macOS / Apple Silicon，使用 Rust 1.96 和 Cargo 构建。MiGate 通过一个本地小米主中枢桥接当前米家自有家庭的受支持插座，提供独立通道开关、状态通知、动态 Matter 拓扑与米家账号认证。

以下命令在仓库根目录执行。仓库的 Cargo 配置默认使用项目下的 `.migate/` 保存数据；继续使用已有实例时，保持同一数据目录。

## 启动

```sh
cargo run --locked -- auth login
cargo run --locked
```

Mac 与小米中枢必须处于同一局域网，中枢所属家庭须为当前账号的自有家庭。MiGate 先按本地发现的 `group_id` 确定一个当前家庭，再处理该家庭的设备；家庭确定后保持固定，不因某个 DID 转入其他家庭而跟随切换。WiFi 与 BLE Mesh 插座使用同一中枢连接，接入依据家庭成员关系、完整能力描述及中枢的 MIoT 读写与主动通知访问条件。不提供云端控制、远程家庭接入或多家庭管理。

已完成账号准备但暂无可接入设备时，网桥允许仅以 root 和 Aggregator 运行。首次本地发现等待 30 秒后显示当前原因，随后继续发现或连接恢复，失败按 1 秒至 30 秒退避重试。一台候选设备准备失败会保留待接入原因，其余设备继续接入；家庭范围确定前不发布子设备。

具备当前账号和家庭的有效静态缓存时，启动先恢复其中仍标记为已发布的拓扑，各路电源值为 `unknown`、物理设备不可用；已确认删除的记录不会重新暴露。新设备完整描述与访问条件确认后，以整台物理设备为单位发布全部端点，再异步订阅和读取，发布不等待订阅应答或首次读取成功。缓存不保存当前在线状态、开关值、未完成请求或可供远程连接的地址。

程序在前台运行，使用 Ctrl-C 或 SIGTERM 停止。同一数据目录由一个 MiGate 进程独占，再次启动或执行认证命令会提示目录正在使用。中枢断线或设备离线时保留 Matter 拓扑并报告不可达；本地连接、设备在线与访问条件恢复后即可恢复可用性，订阅和属性刷新独立进行。不会重发断线前结果不明的写入。

Matter 默认使用 UDP 5540。可通过 `MIGATE_MATTER_PORT` 设置端口（`0`–`65535`），设为 `0` 时由系统分配空闲端口；启动日志显示实际端口。运行多个网桥时，分别使用独立数据目录和不同端口。

也可以构建后直接运行：

```sh
cargo build --locked --release
./target/release/migate --data-dir .migate
```

直接运行构建产物不会读取 Cargo 的环境配置；未指定目录时，依次使用 `MIGATE_DATA_DIR` 和 `~/.migate/`。因此直接运行时请明确复用原实例目录。

### 调试构建

默认开发构建仅为项目代码保留回溯所需的行号信息，第三方依赖不生成调试信息。需要使用 LLDB/GDB 检查变量或进入依赖源码时，使用 `debugging` profile：

```sh
cargo build --locked --profile debugging
```

排查启动或中枢通信问题时，可通过 `RUST_LOG` 调整日志。以下命令保留一般运行日志，并显示 MiGate 的连接阶段、请求编号和协议解析诊断：

```sh
RUST_LOG=info,migate=debug cargo run --locked
```

日志写入标准错误，终端命令结果和配对信息写入标准输出。

产物位于 `target/debugging/migate`，项目和第三方依赖均启用完整调试信息。首次使用该 profile 会重新构建并额外占用磁盘空间。也可通过以下命令构建并启动：

```sh
cargo run --locked --profile debugging
```

## 设备范围与生命周期

当前支持以下五个型号，自动处理当前家庭内满足条件的全部设备，不使用固定 DID 或当前样本数量作为容量上限。

| 型号 | 通信类别 | 稳定通道键 |
| --- | --- | --- |
| `cuco.plug.v3` | WiFi | `main`：主电源 |
| `xiaomi.plug.04` | WiFi | `main`：主电源 |
| `zimi.plug.zncz01` | BLE Mesh | `main`：主电源 |
| `qmi.plug.psv3` | BLE Mesh | `main`：主电源 |
| `cuco.plug.cp7pd` | WiFi | `outlet_1`：开关 1；`outlet_2`：开关 2；`usb`：USB |

`cp7pd` 的总控通知只触发三个实际通道的读取，不把总控值复制给各路，也不暴露第四个控制通道。功率、电量、指示灯、童锁及其他设备类别不在当前范围。

启动、中枢重连和设备列表变化通知会触发同步，每 5 分钟再同步一次当前家庭的完整成员关系。这个周期用于发现加入和删除，不轮询各路电源。订阅与读取在加入、上线或连接恢复时执行；物理设备内的刷新依次读取，重复触发合并为一轮追加刷新。订阅首次失败后最多追加 3 次、每次间隔 100 毫秒，读取首次失败后最多追加 3 次、每次间隔 3 秒，均只重试失败项。耗尽后记录原因，等待后续事件，不永久重试；断连或移除设备会取消相关工作。

| 变化 | 网桥行为 |
| --- | --- |
| 家庭新增受支持插座 | 补齐描述与访问条件，一次发布整台设备，再订阅并读取各路。 |
| 候选缺少描述、能力不支持或中枢访问不满足 | 显示待接入原因，后续同步继续准备，不阻止其他设备。 |
| 已接入设备离线或中枢列表暂时遗漏 | 保留拓扑与身份，报告不可用。 |
| 完整当前家庭列表确认设备已移出 | 撤下整台设备及全部通道，取消请求、订阅和任务，保留历史身份及名称。 |
| 同 DID 与同功能重新加入 | 重新确认条件后复用原身份、端点与名称，再刷新状态。 |

只有账号、家庭均匹配且完成全部分页的云端列表可以确认删除；失败、部分页、游标无进展或其他家庭的响应不能当成空列表。改名、换房间、断电、断网和中枢遗漏都不构成删除依据。MiGate 只更新自己的桥接表达，不修改米家侧设备；云端失败期间不承诺成员变化何时收敛。同一设备能力不兼容时不会热改原端点，已有拓扑保留并显示不可用原因。

## 米家账号认证

认证需要联网，目前仅支持中国大陆服务区（`cn`），每个数据目录保存一个账号。以下认证命令在 shell 中执行。

### 登录

```sh
cargo run --locked -- auth login
```

1. 打开终端显示的授权链接，在浏览器中登录米家账号并授权 HA 应用，无须安装或运行 Home Assistant。
2. 浏览器跳转到 `http://homeassistant.local:8123/api/webhook/…` 后，即使页面显示无法访问，也直接复制地址栏中的完整网址。
3. 将包含 `code` 和 `state` 的完整网址粘贴回等待中的终端并回车。使用本次授权得到的网址；若回调已失效，重新执行登录命令，从新的授权链接开始。
4. 等待终端显示 `Xiaomi: authenticated (cn).` 和 `Gateway certificate: valid until …`，即完成登录。

### 检查与退出登录

```sh
cargo run --locked -- auth check
```

检查分别显示账号认证与证书状态，并在需要时刷新令牌和续期证书。两项均正常才表示独立检查成功；提示 `sign-in required` 时按显示的命令重新登录，网络故障时待网络恢复后重试。

网桥启动和成员同步复用令牌刷新与证书准备，但设备目录读取限定为当前固定家庭。具备同一账号与家庭的静态缓存、有效证书并通过本地中枢认证和设备访问检查时，云端暂时故障或要求重新登录不会阻止已有本地控制，也不会把已有设备当作已移除。云端认证状态和中枢连接状态分别展示，不能仅凭认证成功判断设备可用。

云端准备或证书续期遇到暂时网络故障、服务错误时，会从 1 秒开始退避重试，逐次翻倍至 30 秒；本地连接与控制独立恢复。需要认证的云端请求遇到 401 时先尝试一次令牌刷新，明确要求重新登录后保留提示并暂停使用该凭据的云端同步。

提示 `sign-in required` 时，先停止使用同一数据目录的网桥，再独立执行 `auth login`，之后以原数据目录重启加载更新后的凭据。目录锁使认证命令不能与该网桥同时运行。

退出登录：

```sh
cargo run --locked -- auth logout
```

该命令删除本地米家账号凭据，保留网桥身份与 Apple Home 配对，也不会撤销远端 HA 应用授权。

## 添加到 Apple Home

Mac 与 iPhone / iPad 需处于同一局域网，网络允许 Matter 使用的 UDP 端口（默认 5540）与 mDNS 发现，并保持 Mac 唤醒。

1. 启动网桥；账号准备完成或加载有效静态缓存后，尚未配对的实例会显示二维码和手动配对码，空网桥也可等待设备加入。
2. 在「家庭」App 中添加配件，扫描二维码或输入终端显示的手动配对码。
3. 当前使用测试认证材料。如提示配件未认证且提供继续入口，可选择继续添加。
4. 单路设备在同一端点承载 Bridged Node 与 On/Off Plug-in Unit（`0x010A`，revision 3）。`cp7pd` 使用一个 Bridged Node 父端点与三个 On/Off Plug-in Unit 子端点；父节点不提供总控开关，子节点不额外声明 Bridged Node。父节点的 `PartsList` 列出三路，子节点的 `TagList` 提供稳定且可区分的通道标签。实际卡片数量、分组、顺序和标签呈现以客户端表现为准。

新设备首次接入时导入米家名称，按 UTF-8 字符边界截断到最多 32 字节；缺少有效名称时使用型号与 DID 的原有生成规则。多路父节点使用设备名称，各路提供“开关 1”“开关 2”“USB”标签。后续米家改名不会覆盖已保存名称；控制器写回支持的名称属性时按设备或功能持久化。仅存于「家庭」App 内的名称由控制器管理，不一定等于 MiGate 的 NodeLabel。

当前只实现基础 On、Off、Toggle 与 Reachable，不包含 Lighting、计时关闭、全局场景或 Scenes Management。标准插座类型要求这些功能，因此当前存在已知符合性限制，不能声称完整符合标准插座要求或已通过 Matter 认证。Identify 与 Groups 保留通用协议行为。Apple Home 基础控制、通知、恢复与动态拓扑呈现在 `review` 阶段进行真机验收，不能由能力描述或在线标记推断全部型号已经验证。

配对窗口为 15 分钟，超时后用 Ctrl-C 停止，再以同一数据目录启动即可重新打开。

## 日常操作与退出

在运行网桥的终端中，每行输入一个命令：

| 命令 | 操作 |
| --- | --- |
| `list` | 列出已接入和待接入设备的 DID、名称、通道键、状态或原因 |
| `status [DID]` | 查看全部或指定已接入设备的通道快照，以及账号和中枢连接状态 |
| `on DID [channel]` | 请求开启指定设备的通道；单路可省略通道，多路必须指定 |
| `off DID [channel]` | 请求关闭指定设备的通道；单路可省略通道，多路必须指定 |
| `help` | 查看命令帮助、通道键用法及账号和中枢连接状态 |

终端输出使用英文，设备名称原样显示。先用 `list` 查找 DID 和稳定通道键，再输入命令。以下 DID 为示例，运行时替换成自己的设备 DID：

```text
list
status 123456789
on 123456789
off 123456789 main
on 987654321 outlet_1
off 987654321 outlet_2
on 987654321 usb
```

单路通道键为 `main`，多路为 `outlet_1`、`outlet_2`、`usb`，与名称和列表顺序无关。无目标的 `on`、`off`、缺少必需通道、未知 DID、未知通道或多余参数只返回用法提示，不产生写入。设备被确认移除后，旧 DID 也不能继续控制。

终端和 Matter 使用同一份设备状态与命令入口。物理设备的 Reachable 由共享中枢连接、设备在线及本地访问条件决定，与是否已读到某路电源值无关。首次读取前开关值为 `unknown`，Matter 开关读取返回错误，不伪造关闭；设备可用时仍可执行明确的 On、Off，Toggle 需要已知值。不可用时可以显示最近的内存快照，但它不代表设备此刻的实际状态。

中枢返回成功码 `0` 或 `1` 时显示 `command accepted`，仅表示请求已受理。受理后立即乐观更新目标值，后续合法属性通知或恢复读取覆盖同一快照；不能把成功输出当作真实动作已确认。实体按键和米家 App 的变化依赖主动通知，同值不重复报告。推送缺失时，乐观值可能保持到后续通知或恢复读取，不提供固定期限纠正、自动回滚或每次写入后的定时读回。

一次读写失败会显示错误并保留原值或未知，不把设备判为离线，写入不自动重发。每个通道的命令按顺序执行，不同设备和通道可以并发；中枢设备列表与属性读写使用 10 秒网络请求超时，排队与应答不再叠加合计 5 秒的业务期限。Ctrl-C 或 SIGTERM 停止网桥并取消未完成请求；输入 EOF 只停止终端读取，桥接服务仍继续运行。重启时开关重新从 `unknown` 开始，经中枢读取恢复，不持久化运行期开关值。

## 数据目录与重新配对

数据目录保存账号凭据与证书、当前家庭范围、网桥和设备身份、静态能力缓存、名称和 Matter 协议数据，请妥善保留，避免提交或共享。首次使用的目录必须为空或尚不存在。

目录中的 `instance.lock` 用于进程互斥，退出后由系统释放锁，文件本身会保留，无须删除。异常退出后也可直接使用原目录重启。

通过 `--data-dir <PATH>` 选择目录时，该参数须放在 `auth` 之前。未指定时依次使用 `MIGATE_DATA_DIR` 环境变量和 `~/.migate/`；仓库的 Cargo 配置会在未设置该环境变量时使用项目根目录的 `.migate/`。相对路径按命令执行目录解析，启动日志会显示实际使用的路径。

已有运行数据会以事务迁移到存储版本 4，保留原单路设备的 endpoint `2`、UniqueID、凭据与证书、网桥身份、配对及其他 Matter 数据。已保存的旧 NodeLabel 优先迁移；没有已保存标签时固化旧型号与 DID 默认值，不在升级时自动替换成米家名称。迁移失败会报告错误并回滚，不清空数据或创建替代身份。

根 endpoint `0` 与 Aggregator endpoint `1` 保留。正常重启、改名、换房间、IP 或主中枢变化不会改变设备身份；设备移除后历史端点永久保留，不分配给其他设备或功能。同 DID 与同功能重新加入时复用身份、端点及名称，但不保证「家庭」App 自动恢复原房间、场景或自动化。端点编号耗尽时拒绝新增，已有设备继续运行。

虚拟灯时期的拓扑与配对不保证兼容，旧数据不会因此自动清除。在线从「家庭」App 移除配件后，可使用原目录重新配对；离线移除后网桥可能仍保留配对，此时可用并列的新目录开始独立实例：

```sh
cargo run --locked -- --data-dir .migate-trial-1
```

新目录代表独立实例，需要重新登录米家账号和添加到「家庭」App。请选择与原目录并列的新目录，原目录的数据会保留。
