# 运行 MiGate

当前支持 macOS / Apple Silicon，需要 Rust 1.96 和 Cargo。首次接入设备时，Mac 与小米主中枢须处于同一局域网，中枢所属米家家庭须为当前账号的自有家庭。目前仅支持中国大陆服务区，一次运行接入一个家庭。

## 启动

在仓库根目录执行：

```sh
cargo run --locked -- auth login
cargo run --locked
```

首次登录的具体步骤见下方「米家账号」。登录成功后，日常启动只需第二条命令。

仓库的 Cargo 配置默认使用项目下的 `.migate/` 保存数据。重启或升级时继续使用同一目录，即可保留账号、名称和 Apple Home 配对。

程序在前台运行，使用 Ctrl-C 或 SIGTERM 停止。关闭终端输入（EOF）后，桥接服务仍会继续运行。同一数据目录只能由一个进程使用；执行认证命令前也需先停止网桥。

也可以构建后直接运行：

```sh
cargo build --locked --release
./target/release/migate --data-dir .migate
```

直接运行构建产物时，请明确指定原数据目录；它不会读取仓库的 Cargo 环境配置。其他目录设置方式见下方「数据目录与重新配对」。

## 米家账号

登录和账号检查需要联网。以下命令在 shell 中执行。

### 登录

```sh
cargo run --locked -- auth login
```

1. 打开终端显示的授权链接，在浏览器中登录米家账号并授权 HA 应用，无须安装或运行 Home Assistant。
2. 浏览器跳转到 `http://homeassistant.local:8123/api/webhook/…` 后，即使页面显示无法访问，也复制地址栏中的完整网址。
3. 将完整网址粘贴回等待中的终端并回车。若授权已失效，重新执行登录命令，从新的授权链接开始。
4. 等待终端显示 `Xiaomi: authenticated (cn).` 和 `Gateway certificate: valid until …`，即完成登录。

### 检查与退出登录

```sh
cargo run --locked -- auth check
```

检查会显示账号与证书状态，并在需要时自动更新。两项均正常才表示检查成功。

提示 `sign-in required` 时，停止网桥，执行 `auth login`，再使用原数据目录启动。网络故障时待网络恢复后重试。

退出登录：

```sh
cargo run --locked -- auth logout
```

该命令删除本地米家账号凭据，保留 Apple Home 配对，也不会撤销远端 HA 应用授权。

## 添加到 Apple Home

Mac 与 iPhone / iPad 须处于同一局域网，并保持 Mac 唤醒。网络需允许 mDNS 发现和 Matter 使用的 UDP 端口，默认端口为 5540。

1. 启动 MiGate，等待终端显示二维码和手动配对码。暂无受支持设备时，也可以先添加网桥。
2. 在「家庭」App 中添加配件，扫描二维码或输入手动配对码。
3. 当前使用测试认证材料，尚未通过 Matter 认证。如提示配件未认证且提供继续入口，可选择继续添加。
4. 继续完成 App 中的房间与名称配置。

配对窗口为 15 分钟。超时后用 Ctrl-C 停止，再以同一数据目录启动即可重新打开。

新接入设备使用米家中的初始名称，之后可在 Apple Home 中独立改名。已有设备升级后保留原名称。

若多路插座的通道显示同名或“插座 2”等默认名称，先逐路操作并核对实际通道，再在「家庭」App 中为各路分别改名，例如“开关 1”“开关 2”“USB”。不要根据显示顺序或默认编号判断实际通道。实际卡片和分组以 App 显示为准。

## 设备接入

MiGate 自动接入当前家庭中具备基础开关能力且可通过中枢访问的插座。下表是当前明确覆盖的型号，并非型号白名单；其他单路插座也可自动接入，但不保证兼容。加入后用 `list` 查看设备状态或未接入原因。

| 型号 | 通信类别 | 终端通道键 |
| --- | --- | --- |
| `cuco.plug.v3` | WiFi | `main`：主电源 |
| `xiaomi.plug.04` | WiFi | `main`：主电源 |
| `zimi.plug.zncz01` | BLE Mesh | `main`：主电源 |
| `qmi.plug.psv3` | BLE Mesh | `main`：主电源 |
| `cuco.plug.cp7pd` | WiFi | `outlet_1`：开关 1；`outlet_2`：开关 2；`usb`：USB |

已接入设备重启后保留原身份与名称。本地中枢可用时优先通过本地接口控制；本地不可用时，确认当前家庭成员关系与设备在线信息后，可通过云端 HTTP 继续开关控制。初始开关状态未知时，可明确执行开启或关闭。

本地业务请求已发送但等待应答超时时，后续命令优先使用可用的云端路径；超时命令不自动补写。程序保留仍正常工作的中枢连接，首次等待60秒后只读取设备列表检查恢复；检查失败后，从该轮结束再等待300秒。当前中枢返回合法列表后恢复本地优先，新主中枢或重连后的列表刷新也可提前恢复。

属性通知使用相同的路径优先级。切换时先确认新来源所需的全部属性订阅；部分订阅成功期间保留仍有效的旧来源。云端 MQTT 连接、订阅或重连缓慢时，本地控制和补读继续工作。云端在线通知单独更新云端访问条件，云端离线不会使仍可本地控制的设备离线。

设备恢复、通知来源切换及多路总控变化会合并触发通道补读。补读独立更新各通道，不阻塞明确的开关命令；已发布设备缺少通知权限时仍可使用有效路径读取和控制。云端缓存读取可能比设备真实状态旧，后续有效通知或读取会继续更新状态。

云端 HTTP 临时失败后暂停该账号的云端读写，等待完整同步恢复；仍有效的云端 MQTT 通知可以继续更新状态，但不会解除暂停。全部控制路径失效时，设备保持不可用，即使还能收到通知。认证拒绝会共用令牌刷新协调；当前写入失败后不自动补发。

令牌按保存的刷新时间独立维护，不等待家庭目录或证书请求结束。更新成功后，HTTP 立即使用新令牌，云端 MQTT 重新连接并建立订阅。临时刷新失败时，尚未过期且未遭拒绝的旧令牌可继续使用；到期后停止新的云端操作及通知连接。证书续期独立进行，续期失败不阻断云端，云端认证失败也不阻断仍由有效证书支持的本地路径。新令牌再次遭认证拒绝时，需要停止网桥、重新登录，再使用原数据目录启动。

当前提供基础开关控制，不提供功率、电量、指示灯或童锁。`cp7pd` 的三路分别控制，总控不作为额外开关显示。其他多路插座暂不保证能分别控制各路。

在米家家庭中加入或移出设备后，MiGate 会自动同步，必要时等待下一次五分钟同步。同步需要云端可用。断电、断网、改名或换房间不会删除设备；连接及中枢本地接口恢复后会自动恢复服务。

同一设备移出后重新加入，会复用 MiGate 保存的身份和名称，但 Apple Home 中原有的房间、场景或自动化可能需要重新设置。

## 日常操作

在运行 MiGate 的终端中，每行输入一个命令：

| 命令 | 操作 |
| --- | --- |
| `list` | 列出设备、DID、通道及状态；未接入设备显示原因 |
| `status [DID]` | 查看全部或指定设备的状态，以及账号和中枢连接状态 |
| `on DID [channel]` | 开启指定通道；单路设备可省略通道 |
| `off DID [channel]` | 关闭指定通道；单路设备可省略通道 |
| `help` | 查看命令帮助 |

先用 `list` 查找 DID 和通道键，再输入命令。以下 DID 为示例，运行时替换成自己的设备 DID：

```text
list
status 123456789
on 123456789
off 123456789 main
on 987654321 outlet_1
off 987654321 outlet_2
on 987654321 usb
```

多路设备必须指定通道。终端输出使用英文，设备名称原样显示。

`unknown` 表示尚未读到开关状态，可稍后再次查看。`command accepted` 表示中枢已受理命令；若实际设备未响应，请检查设备和中枢连接。设备不可用时，显示的开关值可能是断线前的状态。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 没有发现设备 | 用 `list` 查看原因；确认登录账号、米家家庭以及 Mac 与中枢的局域网连接。程序会继续尝试发现，无须反复重启。 |
| 设备显示不可用 | 检查设备供电、中枢和网络，恢复后等待自动重连。 |
| 米家主中枢切换 | 程序会自动连接新的主中枢。若米家已正常但 MiGate 持续不可用，参见[中枢已知限制与恢复经验](known-limitations.md)。无需重新配对 Apple Home。 |
| 云端暂时不可用 | 等待网络或服务恢复。已有设备在本地连接和证书有效时仍可控制，新设备接入与移除同步可能延迟。 |
| 提示需要重新登录 | 停止网桥，执行 `auth login`，然后用原目录重启。 |
| 提示数据目录正在使用 | 停止使用该目录的另一个 MiGate 进程，再重试；不要删除锁文件。 |
| Apple Home 无法发现网桥 | 确认配对窗口仍有效、Mac 未休眠，且网络允许 mDNS 和 Matter UDP 通信。 |

需要详细日志时：

```sh
RUST_LOG=info,migate=debug cargo run --locked
```

日志写入标准错误，终端命令结果和配对信息写入标准输出。需要用 LLDB/GDB 调试时，可运行 `cargo build --locked --profile debugging`，产物位于 `target/debugging/migate`。

若默认端口被占用，可通过 `MIGATE_MATTER_PORT` 设置其他端口（`0`–`65535`）；设为 `0` 时由系统分配，启动日志会显示实际端口。运行多个网桥时，分别使用独立数据目录和不同端口。

## 数据目录与重新配对

数据目录包含账号凭据、证书、设备名称与配对信息，请妥善保留，避免提交或共享。首次使用的目录须为空或尚不存在。

目录选择顺序为：

1. `--data-dir <PATH>`，该参数须放在 `auth` 之前。
2. `MIGATE_DATA_DIR` 环境变量；仓库的 Cargo 配置默认将其设为项目下的 `.migate/`。
3. `~/.migate/`。

相对路径按命令执行目录解析，启动日志会显示实际路径。异常退出后可直接使用原目录重启，无须删除其中的 `instance.lock`。

升级时会自动迁移已有数据。若迁移或读取失败，请保留原目录并根据错误排查。

在线从「家庭」App 移除配件后，可使用原目录重新配对。若离线移除后无法重新配对，或需要一个全新的实例，可选择与原目录并列的新目录：

```sh
cargo run --locked -- --data-dir .migate-trial-1 auth login
cargo run --locked -- --data-dir .migate-trial-1
```

新实例需要重新登录米家账号并添加到 Apple Home，原目录的数据会保留。

协议、身份和生命周期设计见[多设备与多路插座桥接方案](specs/2026-10-04-multi-device-channel-bridge/spec.md)。
