# 运行 MiGate

当前支持 macOS / Apple Silicon，需要 Rust 1.96 和 Cargo。首次绑定米家家庭时，Mac 与小米主中枢须处于同一局域网，中枢所属家庭须为当前账号的自有家庭。绑定后，新设备加入及重新加入不再依赖中枢本地接口。目前仅支持中国大陆服务区，一次运行接入一个家庭。

## 启动

在仓库根目录执行：

```sh
cargo run --locked -- auth login
cargo run --locked
```

首次登录的具体步骤见下方「米家账号」。登录成功后，日常启动只需第二条命令。

仓库的 Cargo 配置默认使用项目下的 `.migate/` 保存数据。重启或升级时继续使用同一目录，即可保留账号、名称和 Apple Home 配对。

程序在前台运行，使用 Ctrl-C 或 SIGTERM 停止。关闭终端输入（EOF）后，桥接服务仍会继续运行。同一数据目录只能由一个进程使用；执行认证命令前也需先停止网桥。

也可以构建后直接运行：

```sh
cargo build --locked --release
./target/release/migate --data-dir .migate
```

直接运行构建产物时，请明确指定原数据目录；它不会读取仓库的 Cargo 环境配置。其他目录设置方式见下方「数据目录与重新配对」。

## 米家账号

登录和账号检查需要联网。以下命令在 shell 中执行。

### 登录

```sh
cargo run --locked -- auth login
```

1. 打开终端显示的授权链接，在浏览器中登录米家账号并授权 HA 应用，无须安装或运行 Home Assistant。
2. 浏览器跳转到 `http://homeassistant.local:8123/api/webhook/…` 后，即使页面显示无法访问，也复制地址栏中的完整网址。
3. 将完整网址粘贴回等待中的终端并回车。若授权已失效，重新执行登录命令，从新的授权链接开始。
4. 等待终端显示 `Xiaomi: authenticated (cn).` 和 `Gateway certificate: valid until …`，即完成登录。

### 检查与退出登录

```sh
cargo run --locked -- auth check
```

检查会显示账号与证书状态，并在需要时自动更新。两项均正常才表示检查成功。

提示 `sign-in required` 时，停止网桥，执行 `auth login`，再使用原数据目录启动。网络故障时待网络恢复后重试。运行中的令牌维护与证书续期独立进行；账号检查的整体结果不代表所有控制路径都不可用，桥接期间用 `status` 查看各设备当前路径。

退出登录：

```sh
cargo run --locked -- auth logout
```

该命令删除本地米家账号凭据，保留 Apple Home 配对，也不会撤销远端 HA 应用授权。

## 添加到 Apple Home

Mac 与 iPhone / iPad 须处于同一局域网，并保持 Mac 唤醒。网络需允许 mDNS 发现和 Matter 使用的 UDP 端口，默认端口为 5540。

1. 启动 MiGate，等待终端显示二维码和手动配对码。暂无受支持设备时，也可以先添加网桥。
2. 在「家庭」App 中添加配件，扫描二维码或输入手动配对码。
3. 当前使用测试认证材料，尚未通过 Matter 认证。如提示配件未认证且提供继续入口，可选择继续添加。
4. 继续完成 App 中的房间与名称配置。

配对窗口为 15 分钟。超时后用 Ctrl-C 停止，再以同一数据目录启动即可重新打开。

新接入设备使用米家中的初始名称，之后可在 Apple Home 中独立改名。已有设备升级后保留原名称。

若多路插座的通道显示同名或“插座 2”等默认名称，先逐路操作并核对实际通道，再在「家庭」App 中为各路分别改名，例如“开关 1”“开关 2”“USB”。不要根据显示顺序或默认编号判断实际通道。实际卡片和分组以 App 显示为准。

## 设备接入

MiGate 根据云端家庭成员关系及完整功能描述，自动接入当前家庭中受支持的插座和单灯。下表是插座的代表型号，并非型号白名单；其他符合完整能力描述的单路设备也可自动接入，但不保证兼容。加入后用 `list` 查看设备状态或未接入原因。

| 型号 | 通信类别 | 终端通道键 |
| --- | --- | --- |
| `cuco.plug.v3` | WiFi | `main`：主电源 |
| `xiaomi.plug.04` | WiFi | `main`：主电源 |
| `zimi.plug.zncz01` | BLE Mesh | `main`：主电源 |
| `qmi.plug.psv3` | BLE Mesh | `main`：主电源 |
| `cuco.plug.cp7pd` | WiFi | `outlet_1`：开关 1；`outlet_2`：开关 2；`usb`：USB |

单灯使用一个 `main` 通道和一个灯具端点。以下七个 MIoT 描述样本用于能力解析与自动化回归；表内范围是描述声明的原始数值，不表示这些型号均已完成真机验证。准入还检查属性类型、读写通知权限、量程和步长，不能只凭型号接入。

| 型号 | 通信类别 | 原始亮度范围 | 色温范围 | 彩色 |
| --- | --- | --- | --- | --- |
| `devcea.light.ls2307` | WiFi | 1–100 | 2700–6500 K | 24 位 RGB |
| `yeelink.light.light3` | BLE Mesh | 1–65535 | 2700–6500 K | 无 |
| `yeelink.light.ml9` | BLE Mesh | 1–100 | 3000–6400 K | 无 |
| `yeelink.light.spot2` | BLE Mesh | 1–100 | 2700–6500 K | 无 |
| `xiaomi.light.ceil04` | WiFi | 1–100 | 2700–5700 K | 无 |
| `xiaomi.light.bar2` | WiFi | 1–100 | 2700–6500 K | 无 |
| `lemesh.light.wy0c15` | BLE Mesh | 1–100 | 2700–6500 K | 无 |

六种色温灯提供开关、亮度与色温控制，`ls2307` 还支持彩色控制，包括色相与饱和度调节。亮度与色温按每台灯支持的实际量程调节。仅有厂商场景或传感器服务的设备不会因此显示为彩灯；Matter 能力声明与符合性边界见[已知限制](known-limitations.md)。

Apple Home 按能力提供灯具开关、亮度、色温及彩色控制。选择色温或颜色时，MiGate 自动完成相应模式和目标的写入；同一盏灯不会拆成白光与彩光两个开关。只调整亮度保持当前模式。实际控件布局和 Home 发送的命令由 App 版本决定，具体呈现及固件模式行为在 `review` 阶段核对。

已接入设备重启后保留原身份与名称。本地中枢可用时优先通过本地接口控制；本地不可用时，确认当前家庭成员关系与设备在线信息后，可通过云端 HTTP 继续控制。开关状态未知时，可明确执行开启或关闭；灯具缺少必要起点时，相对 Move/Step 返回状态未知，不从默认亮度或颜色开始。明确目标不依赖旧起点时仍可按有效路径执行。

云端读写与通知仍可能依赖设备使用的物理网关及其互联网链路，不能保证网关断电后仍可控制。具体边界见[已知限制](known-limitations.md)。

本地业务请求已发送但等待应答超时时，后续命令优先使用可用的云端路径；超时命令不自动补写。程序保留仍正常工作的中枢连接，首次等待 60 秒后只读取设备列表检查恢复；检查失败后，从该轮结束再等待 300 秒。当前中枢返回合法列表后恢复本地优先，新主中枢或重连后的列表刷新也可提前恢复。

若中枢明确返回某台设备离线，则仅撤销该设备的本地候选，后续命令使用仍可用的云端；当前失败命令不补发，其他设备继续正常选路。

属性通知使用相同的路径优先级。切换时先确认新来源所需的全部属性订阅；部分订阅成功期间保留仍有效的旧来源。云端 MQTT 连接、订阅或重连缓慢时，本地控制和补读继续工作。云端在线通知单独更新云端访问条件，云端离线不会使仍可本地控制的设备离线。

若云端持续不确认订阅、导致当前连接无法继续准备通知，程序会按已有退避重建云端通知连接；有效的控制路径继续工作。

设备恢复、通知来源切换及多路总控变化会合并触发通道补读。补读独立更新各通道，不阻塞明确的开关命令；已发布设备缺少通知权限时仍可使用有效路径读取和控制。云端缓存读取可能比设备真实状态旧，后续有效通知或读取会继续更新状态。

云端 HTTP 临时失败后暂停该账号的云端读写，等待完整同步恢复；仍有效的云端 MQTT 通知可以继续更新状态，但不会解除暂停。全部控制路径失效时，设备保持不可用，即使还能收到通知。认证拒绝会共用令牌刷新协调；当前写入失败后不自动补发。

令牌按保存的刷新时间独立维护，不等待家庭目录或证书请求结束。更新成功后，HTTP 立即使用新令牌，云端 MQTT 重新连接并建立订阅。临时刷新失败时，尚未过期且未遭拒绝的旧令牌可继续使用；到期后停止新的云端操作及通知连接。证书续期独立进行，续期失败不阻断云端，云端认证失败也不阻断仍由有效证书支持的本地路径。新令牌再次遭认证拒绝时，需要停止网桥、重新登录，再使用原数据目录启动。

插座提供基础开关控制，不提供功率、电量、指示灯或童锁。`cp7pd` 的三路分别控制，总控不作为额外开关显示。其他多路插座暂不保证能分别控制各路。单灯的标准能力与符合性缺项见[已知限制](known-limitations.md)。

灯具支持目标设置、带 `TransitionTime` 的软件渐变、Move 持续调整、Step 步进与 Stop，以及 Level 的 WithOnOff 变体。MiGate 生成中间目标，按设备步长量化、去重，并合并网络来不及发送的旧步骤；每盏灯最多一个写请求在途，亮度和色温／彩色分别保留最新目标，最终目标保留。Home 是否发送非零过渡时长不由 MiGate 决定，协议命令支持不等于 App 提供时长设置入口。

普通 Level 命令保持开关状态；WithOnOff 变体按标准联动开关，到有效最小亮度时关闭。普通 On/Off 遵循 OnLevel；OnLevel 非空且开关值改变时，On 使用该亮度，Off 的目标包含最小亮度与关灯，OnLevel 为空时保留原亮度。重复 On 不重新应用预设，重复 Off 仍停止旧动作而不重施亮度预设。终端 `on`/`off` 使用通用开关行为，不应用 Matter OnLevel。

较新的有效同维度命令或可识别的米家 App／实体操作接管旧动作，亮度与颜色维度分别处理，外部关灯终止整盏灯的动作。可关联的写入回声和回执、普通补读及云端缓存不作为新的用户指令；非当前模式的数值只更新缓存。无效或按协议忽略的请求不先取消旧动作。Stop 丢弃对应未发送步骤，保持最后已受理值；已发送写入无法撤回，其原回执或超时仍需完成，不保证光学状态瞬时冻结。失败、设备删除、绑定更新、离线和进程重启不会自动续播旧动作或重放目标。

设备通知不足以还原各客户端的原始发令时间。MiGate 直接收到的有效指令按接收顺序协调，外部变化按排除旧工作与写入反馈后的有效观察顺序接管，不承诺全局原始发令顺序。

在米家家庭中加入或移出设备后，MiGate 会自动同步，必要时等待下一次五分钟同步。同步需要云端可用。断电、断网、改名或换房间不会删除设备；有可用控制路径后会自动恢复服务。

家庭绑定后，云端确认设备归属及完整受支持功能即可接入；设备暂时离线时会显示不可用，等待有效路径恢复。首次导入云端设备名称，后续米家改名不覆盖已保存名称。

同一设备移出后重新加入，会复用 MiGate 保存的身份和名称，无需等待中枢本地接口恢复，但 Apple Home 中原有的房间、场景或自动化可能需要重新设置。

## 日常操作

在运行 MiGate 的终端中，每行输入一个命令：

| 命令 | 操作 |
| --- | --- |
| `list` | 列出设备、DID、通道及状态；灯具附能力、亮度、色温、RGB 和模式，未接入设备显示原因 |
| `status [DID]` | 查看设备状态、控制路径、通知来源、实际请求与灯具动作记录，以及账号和中枢恢复状态 |
| `on DID [channel]` | 开启指定通道；单路设备可省略通道 |
| `off DID [channel]` | 关闭指定通道；单路设备可省略通道 |
| `help` | 查看命令帮助 |

先用 `list` 查找 DID 和通道键，再输入命令。以下 DID 为示例，运行时替换成自己的设备 DID：

```text
list
status 123456789
on 123456789
off 123456789 main
on 987654321 outlet_1
off 987654321 outlet_2
on 987654321 usb
```

多路设备必须指定通道。终端输出使用英文，设备名称原样显示；新导入单灯的默认功能名称为 `Light`，已有保存名称保留。终端只提供明确的开关命令，不新增调光、色温或彩色命令。

`unknown` 表示该项尚未获得有效状态。亮度、色温、RGB 与模式可以分别未知，模式已知也不会虚构对应颜色值。仅色温灯的模式由能力确定为 `temperature`；双模式灯保留非当前模式的缓存，以 `mode` 判断当前发光方式。已观察到的 0% 是有效值，不能据此推断关灯。设备不可用时，显示值可能是断线前状态；云端缓存读取也可能返回较旧的值。

`command accepted` 表示请求已受理，不能确认物理动作完成；等值目标可以在本地完成而无需写入。Matter 渐变在启动所需写入受理后应答，后续步骤仍可继续或失败，不能把启动受理当作最终目标完成。快照反映有效观察和已受理属性，包含没有更新观察时的乐观写入结果，不是光学测量。

命令超时后，远端可能已经执行写入。MiGate 不会因路径切换、令牌更新或连接恢复而自动重放这条命令；后续有效通知或读取继续更新显示的状态。

用 `status` 核对路径和恢复进度：

| 诊断内容 | 含义 |
| --- | --- |
| 共享路径优先级 | 正常时本地优先，业务降级后云端优先；各设备仍按自己的访问条件选择可用路径 |
| 本地连接与业务降级 | 中枢连接仍为 `connected` 时，业务请求也可能已降级；连接建立不等于业务应答正常 |
| 当前控制路径 | 当前用于新命令选路的 `local`、`cloud` 或 `none`；不代表此前已发送命令所走的路径 |
| 生效通知来源 | 新来源的必要订阅全部就绪后才切换；部分就绪期间仍保留有效旧来源 |
| 状态同步受限原因 | 通知连接、订阅或访问条件不足时说明原因；仍有控制路径时可执行明确的开启或关闭 |
| 最近切换原因与恢复检查 | 检查已安排时显示 UTC 时间，末尾 `Z` 表示 UTC；`running` 表示正在检查，`none` 表示当前没有已安排的检查 |
| 各通道的请求记录 | 在途命令与最近完成命令记录各自的实际路径和结果；路径切换后，旧命令仍由原请求完成 |
| 灯具请求属性 | 显示明确目标与全部实际 `siid.piid=value`，包括模式；`properties none` 表示没有写属性，不使用默认开关绑定冒充写入 |
| 灯具动作记录 | 独立显示 brightness/color 是否 active、等待的启动回执和最近动作结果；尚未出队便被取代或停止的动作也会显示 |

例如，当前控制路径已经变为 `cloud` 时，在途命令仍可能显示 `local`。核对该命令的实际路径应查看请求记录，或日志中同一请求关联编号对应的开始与结果。灯具状态示例：

```text
main (Light): on
  Capabilities: on/off, brightness, temperature 2700–6500 K, RGB.
  Brightness: 72.5%; temperature: 4000 K; RGB: #FF8040; mode: temperature.
main last command #42: target temperature=4000 K; properties 2.3=4000, 4.2=0; actual path local; accepted.
main actions: brightness idle; color active; awaiting startup receipt none; last color accepted.
```

请求的 `accepted` 表示实际写入受理；`unchanged (no write)` 表示该帧量化后或开关已等值而无需写入，不表示服务器受理或整个动作已启动受理。`actions` 中的 `accepted` 是逻辑动作的受理结果，动作仍可能 active；`failed`、`superseded`、`stopped` 分别表示失败、被较新操作取代、已停止。`awaiting startup receipt ... (previous action)` 表示原动作虽然已失效，已发送的启动请求仍在等原回执，不会以新路径重发。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 没有发现设备 | 用 `list` 查看原因，确认登录账号、米家家庭及云端连接；首次绑定家庭还需 Mac 与中枢处于同一局域网。程序会继续同步，无须反复重启。 |
| 设备显示不可用 | 检查设备供电、中枢和网络，恢复后等待自动重连。 |
| 米家主中枢切换 | 程序会自动连接新的主中枢，用 `status` 核对当前路径与恢复检查。若米家已正常但 MiGate 持续不可用，参见[中枢已知限制](known-limitations.md)。无需重新配对 Apple Home。 |
| 云端暂时不可用 | 等待网络或服务恢复。已有设备在本地连接和证书有效时仍可控制，新设备接入与移除同步可能延迟。 |
| 提示需要重新登录 | 停止网桥，执行 `auth login`，然后用原目录重启。 |
| 提示数据目录正在使用 | 停止使用该目录的另一个 MiGate 进程，再重试；不要删除锁文件。 |
| Apple Home 无法发现网桥 | 确认配对窗口仍有效、Mac 未休眠，且网络允许 mDNS 和 Matter UDP 通信。 |

需要详细日志时：

```sh
RUST_LOG=info,migate=debug cargo run --locked
```

日志写入标准错误，终端命令结果和配对信息写入标准输出。命令日志在实际发送或提交时记录路径，并以同一请求关联编号记录结果；灯具列出全部实际属性和值，未写入时为 `property=none`，不将排队目标或计划插值当作已接受状态。需要用 LLDB/GDB 调试时，可运行 `cargo build --locked --profile debugging`，产物位于 `target/debugging/migate`。

若默认端口被占用，可通过 `MIGATE_MATTER_PORT` 设置其他端口（`0`–`65535`）；设为 `0` 时由系统分配，启动日志会显示实际端口。运行多个网桥时，分别使用独立数据目录和不同端口。

## 数据目录与重新配对

数据目录包含账号凭据、证书、设备名称与配对信息，请妥善保留，避免提交或共享。首次使用的目录须为空或尚不存在。

目录选择顺序为：

1. `--data-dir <PATH>`，该参数须放在 `auth` 之前。
2. `MIGATE_DATA_DIR` 环境变量；仓库的 Cargo 配置默认将其设为项目下的 `.migate/`。
3. `~/.migate/`。

相对路径按命令执行目录解析，启动日志会显示实际路径。异常退出后可直接使用原目录重启，无须删除其中的 `instance.lock`。

升级时会自动迁移已有数据。v5 保存灯具类别、完整能力量程和 MIoT 转换绑定，迁移保留已有设备身份、端点、名称与配对。灯具重启时数值状态从未知重建，不用上次目标补齐。兼容的绑定或量程更新保留端点、刷新能力并取消旧动作；不兼容描述保留已发布身份但暂停服务，等待兼容描述恢复。若迁移或读取失败，请保留原目录并根据错误排查。

在线从「家庭」App 移除配件后，可使用原目录重新配对。若离线移除后无法重新配对，或需要一个全新的实例，可选择与原目录并列的新目录：

```sh
cargo run --locked -- --data-dir .migate-trial-1 auth login
cargo run --locked -- --data-dir .migate-trial-1
```

新实例需要重新登录米家账号并添加到 Apple Home，原目录的数据会保留。

协议、身份和生命周期设计见[多设备与多路插座桥接方案](specs/2026-10-04-multi-device-channel-bridge/spec.md)，云端恢复与路径协调见[云端接入与统一选路方案](specs/2026-10-06-cloud-access-routing/spec.md)，灯具行为见[单灯照明方案](specs/2026-10-08-single-light-control/spec.md)。
