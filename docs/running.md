# 运行 MiGate

当前运行范围为 macOS / Apple Silicon，需要 Rust 1.96 和 Cargo；Linux 部署暂缓。仅支持中国大陆服务区，一次运行接入一个米家自有家庭。首次绑定时，Mac 与该家庭的小米主中枢须处于同一局域网。

## 启动

在仓库根目录执行：

```sh
cargo run --locked -- auth login
cargo run --locked
```

首次登录按下方「米家账号」完成授权，之后日常启动只需第二条命令。仓库的 Cargo 配置默认使用项目下的 `.migate/` 保存数据。日常重启继续使用同一目录，保留账号、设备名称和 Apple Home 配对。

程序在前台运行，使用 Ctrl-C 或 SIGTERM 停止；终端输入结束（EOF）不会停止服务。同一数据目录只能由一个进程使用，执行认证命令前也需先停止网桥。

启动时程序先采集设备状态，Matter 服务最多等待 20 秒；家庭中已配对的网桥在此期间可能暂时不可用。未完成或失败的设备继续在后台恢复，可用 `status` 和 `status DID` 查看状态及读取问题。新设备尚未接入时，`list` 中的 `DID (名称): pending (原因)` 表示当前待处理问题；用同一 DID 执行 `status DID` 可查看相同原因。等待描述获取或配置问题恢复后再检查，完全未知的 DID 才会提示 `Unknown device DID.`。

已配对网桥重启后，Home 还需恢复控制连接和状态订阅。首次从旧版升级时，Home 可能仍按旧订阅等待约 10 分钟；新订阅使用 120 秒的最大报告间隔上限。等待期间保留原数据目录和 Home 配对，可用米家及 `status DID` 核对设备状态。

也可以构建后直接运行：

```sh
cargo build --locked --release
./target/release/migate --data-dir .migate
```

直接运行构建产物不会读取仓库的 Cargo 环境配置，请明确指定原数据目录。

## 米家账号

以下命令在 shell 中执行。登录和账号检查需要联网。

### 登录

```sh
cargo run --locked -- auth login
```

每次执行都会显示新的米家登录二维码；二维码过期后重新执行 `auth login`。使用米家 App 扫码并确认，程序会用本次账号会话自动完成 HA OAuth 授权，不需要安装或运行 Home Assistant。米家会话用于设备云端 HTTP，HA OAuth 是小米账号对官方 `Xiaomi Home (Home Assistant Integration)` 应用的授权，用于云端 MQTT 和中枢客户端证书。

两套服务凭据和账号恢复凭据全部验证后才一起保存；取消或此前失败会保留已有记录，可用下方 `auth check` 查看当前状态。证书准备或续期在凭据保存后进行：若证书步骤失败或取消，执行下方 `auth check` 查看状态并重试证书维护。再次执行 `auth login` 总会重新扫码并重新取得两套服务凭据，不能从上次的进度续办。

HA OAuth 授权失败时，错误会标明失败步骤和类别，可用这些信息排查登录问题；诊断不包含登录票据或授权参数。

如果登录提示图形验证码、短信、邮箱或其他身份验证，本次尝试会结束。请在手机或电脑浏览器登录[小米官网](https://www.mi.com/)完成所需验证，优先使用与网桥同一网络，然后重新执行完整的 `auth login`。网桥所在机器无需桌面；官网验证不保证下次不再要求验证。

### 检查与退出登录

```sh
cargo run --locked -- auth check
```

检查分别显示小米账号、米家会话、HA OAuth 和中枢证书状态，并在需要时执行免交互恢复、令牌刷新或证书续期。各项独立：HA OAuth 异常会影响云端 MQTT 和需要该授权的证书操作，但不等于米家设备 HTTP 失效；米家会话异常也不等于 HA OAuth 或中枢证书失效。已有有效中枢连接和已确认直连按各自条件使用。

若明确提示需要重新登录，停止网桥并执行 `auth login`，完成后使用原数据目录启动。`Account recovery: stopped` 或 HA OAuth 停止恢复会跨 `auth check` 和进程重启保留；只有同账号重新登录并成功保存新凭据才会清除对应状态。若提示需要额外验证，先按上面的官网验证步骤处理；网络、限流或服务临时错误不直接要求重新登录，等待恢复后重试 `auth check`。 HA OAuth 检查或刷新失败时，本次不会继续续证，已有证书仍按自身有效期使用。已经确认并保存直连凭据的设备，可在云端登录或中枢证书过期时按下文离线恢复直连。

退出登录：

```sh
cargo run --locked -- auth logout
```

该命令删除本地米家账号及已保存的设备直连凭据，保留 Apple Home 配对，也不会撤销远端 HA 应用授权。

## 添加到 Apple Home

Mac 与 iPhone / iPad 须处于同一局域网，并保持 Mac 唤醒。网络需允许 mDNS 发现和 Matter UDP 通信，默认端口为 5540。

1. 启动 MiGate，等待终端显示二维码和手动配对码。暂无受支持设备时，也可以先添加网桥。
2. 在「家庭」App 中添加配件，扫描二维码或输入手动配对码。
3. 当前尚未通过 Matter 认证。如提示配件未认证且提供继续入口，可选择继续添加。
4. 完成 App 中的房间与名称配置。

配对窗口为 15 分钟。超时后用 Ctrl-C 停止，再以同一数据目录启动即可重新打开。

设备初始名称来自米家，之后可在 Apple Home 中独立改名。多路插座可能显示同名或默认编号，请逐路操作、核对实际通道后分别改名，不要根据显示顺序判断通道。

## 设备接入

MiGate 自动接入受支持的插座、墙壁开关负载回路、灯光、米家原生灯组、窗帘、风扇、空调、浴霸，以及只读环境温度、相对湿度、CO₂、照度、门窗开合、运动检测和整机人体存在状态。同一设备可接入多个控制或同类功能，以及测量和状态组合；共享电量按设备能力提供。插座提供开关，灯光按能力提供亮度、色温和彩色控制，窗帘提供位置控制，风扇提供开关、风速及设备支持的水平摇头，空调提供开关、模式、温度、风速及设备支持的上下摆风，浴霸提供暖风及两路风扇。用 `list` 查看实际功能和识别问题，代表型号见 [README](../README.md)，功能边界见[已知限制](known-limitations.md)。

在米家加入、移出设备或调整灯组后，等待自动同步，必要时等待下一次五分钟同步；同步需要米家设备 HTTP 可用。断电、断网、改名或换房间不会删除设备。重启或重新加入时保留 MiGate 已保存的名称，米家后续改名不会覆盖；移出后重新加入，Home 中的房间、场景或自动化可能需要重新设置。

使用受支持的数据目录启动新版 MiGate 后，可用 `list` 或 `status DID` 查看已有设备和灯组的重新识别结果。已配置设备的型号或实例 URN 变化时，MiGate 会等待云端返回匹配的描述。已配置灯组缺少设备类型时也会等待更新。等待期间加入的新设备可能暂时不会出现在 Home 中。用 `list` 找到待处理的设备或灯组，用 `status DID` 查看原因，等云端补齐资料后再检查新设备。固件号变化本身不会触发重新获取描述，详见[已知限制](known-limitations.md#home-显示与恢复)。

### 直连与路径

首次仍按米家账号与家庭接入流程取得目录中的设备候选。当前 IP 直连支持 `dmaker.fan.p5c` 的标准 MIoT 属性、`lumi.acpartner.mcn02` 的旧 miIO 映射，以及 `yeelink.bhf_light.v13` 的标准 MIoT 属性、低挡 `set_bh_mode` 和共享 `get_prop` 读组；设备须属于当前家庭，且目录提供有效地址和 token。程序验证设备身份及 token，并完成只读业务确认后，才使用和保存直连凭据。局域网发现只提供地址线索，不单独授予访问资格。BLE 和代理子设备继续通过现有中枢或云端路径接入。

保留同一数据目录后，已确认资格及凭据的设备可在外网不可用、HA OAuth 令牌或中枢证书过期时重启并重新认证直连，不必等待云端登录刷新或中枢上线。已知的访问撤销、设备移除、退出账号及家庭范围变化仍会生效；正常目录同步可提供更新的地址或 token，新候选通过验证后才替换已保存记录，无效候选不会覆盖有效记录。地址变化或连接断开时等待该设备自动发现和恢复，其他设备各自恢复；健康闲置时不会持续扫描。

控制与读取正常按中枢（`hub`）→ 直连（`direct`）→ 云端（`cloud`）选择可用路径。单设备读写或单次目录请求超时不切换其他设备的中枢路径；设备被中枢明确报告离线时，仅该设备选择其他合格路径。中枢连接失效时使用可用的备用路径并重连，重连后等待目录成功再恢复中枢优先。完整中枢目录请求超时后约 60 秒重试；其他完整目录失败沿用 3 秒重试间隔。通知独立选择可用中枢或云端；不要把直连读取成功当作通知已就绪。

用 `status DID` 查看直连协议或映射、地址、身份是否确认、可用候选、选中的读取和控制路径、通知来源、恢复进度及最近命令的实际路径。路径显示 `cloud` 时，设备 HTTP 后端为 `mijia`；云端 MQTT 通知需单独查看连接和订阅诊断。读取可用不代表通知也已就绪。正常同步或连接变化后等待自动恢复；若提示凭据无效，检查账号和目录同步，等待连接信息更新。命令超时的结果可能不确定，先核对设备实际状态，程序不会自动重放已经发出或可能发出的控制。

若 `status DID` 显示 `device access forbidden`，在米家检查该设备是否仍属于当前家庭。普通设备的访问资料或灯组的成员关系在后续同步中确认后，云端路径才会恢复。

`list`、`status` 和 `status DID` 每次都显示执行命令时的当前路径。若中枢优先级已降级，且没有可用直连或云端，自动读取会暂停：读取候选仍可能含 `hub`，但 `Selected read` 显示 `none`。此时中枢控制和已就绪的有效通知仍可能可用；分别查看控制、读取和通知栏目，等待目录恢复。

mcn02 若个别反馈无法解析，可在 `status DID` 查看对应属性的读取诊断，其中包含旧 miIO 字段名、原始 JSON 值及预期格式。排查时记录该诊断和当时米家的对应状态；后续有效读取会清除该属性的读取诊断。电源或整体响应异常且没有可用直连时等待退避重试，其他有效路径仍按实际资格使用。

浴霸 v13 使用来源计划中的有效布尔属性完成只读确认。标准属性与共享旧读组各自建立基线和记录结果。`status DID` 的 `Legacy feedback group` 分别显示共享组当前候选与选中的读取路径、最后一次成功观测来源、是否等待回读及读取问题；`Low-speed control` 显示吹风和换气低挡的当前候选与选中路径，不含中枢；即使旧值仍保留，也能看出当前两路是否都不可用。`Standard 3.1 mode` 和 `bh_mode` 是两种独立原始输入，不互相覆盖，也不用于推断暖风、吹风或换气开关。单项业务拒绝或字段异常只影响对应观测或操作；连接故障、请求超时或访问资格失效按共用规则处理。

浴霸共享组读取路径为 `none` 时，内置温度显示来源不可用；`Last reading (diagnostic only)` 和 `temperature: raw` 仍可能保留上次从 `direct` 读到的温度。这些旧值仅供排障，查看当前选中的读取路径并等待路径恢复后的新读数。

对有可读反馈的控制功能，整次命令的步骤处理结束且至少一步明确受理时，若有直连受理或当前没有可用通知，会安排反馈刷新；即使后续步骤失败也适用。读取复用既有队列，失败后有限重试；无读取路径时等待恢复。用 `status DID` 查看功能读取诊断，控制回执不等待刷新，也不重放控制。灯光、灯组写后和渐变帧回读继续保留。

可读状态还会按实际读取路径周期更新：窗帘状态和位置约 10 秒，风扇电源、模式和速度及浴霸标准属性与共享旧读组约 16 秒，其他状态约 60 秒。云端读取向设备请求当前值；请求失败时保留最近有效值，尚无读数时保持未知，用 `status DID` 查看读取问题。路径不可用、请求较慢或服务限流时可能延迟；云端临时失败后自动退避。读取取得的是上游快照，不能保证补回瞬时事件或设备未更新的状态。

### 墙壁开关回路

用 `list` 查找面板的整机 DID、各路 `relay:SIID`、名称、模式和映射。每路直控默认在 Home 显示为普通开关；在 MiGate 正在运行的终端中输入 `map-type DID relay:SIID light` 可改为只能开关的灯，输入 `map-type DID relay:SIID switch` 可改回开关。将 DID 和功能标识替换为 `list` 显示的值。命令确认 `mapped to` 后配置已保存，重复设置显示 `already mapped`；等待 Home 恢复连接并检查显示。配置只改变 Home 表达，不操作负载或切换米家按键模式。

`status DID` 显示各路通断、当前模式、映射、端点、唯一标识、可见原因、on 和 mode 绑定，以及选中的读取与通知路径和各属性的订阅状态。无线回路在 Home 隐藏，仍可保存映射；模式尚未读到时可能显示 `unknown`，并说明使用了已保存的模式。读取或连接失败会保留最近有效值，读取成功不代表通知已就绪；检查各属性订阅、连接及读取问题，等待恢复或约 60 秒周期回读。Home 入口或状态仍未更新时可重开家庭 App。

重启后若米家家庭目录暂时不可用，当前家庭的中枢恢复该设备的读写权限后，Home 即可控制原已发布的直控回路。`status DID` 显示 `mapping access unavailable` 时，待家庭目录同步成功后再用 `map-type` 更改映射。

终端 `on DID relay:SIID` 和 `off DID relay:SIID` 即使在无线模式也会直接通断该路真实继电器，并非模拟按键；操作前确认实际接线和负载。命令受理后仍以设备反馈为准，不能将未知状态当作关闭。

### 功能操作

空调在同一端点声明温控器和风扇类型，Home 中的入口与图标仍需真机核对。保留原数据目录可继续使用已有的设备身份、名称、端点和配对。

可接入的灯组在 Home 中显示为一盏灯，已唯一匹配的成员灯光入口隐藏，仍可在米家单独控制，也可在终端用 `on DID FUNCTION`、`off DID FUNCTION` 控制；成员的其他控制、测量和状态继续发布，有其他可见功能时，如有共享电量也随父端点保留。成员有多个灯光而无法确定归属时，不会任意隐藏，独立可用的原生组功能仍可接入。用 `status` 查看组的原生能力、成员派生的 RGB、状态来源及成员关系问题。组解散后，受支持且不属于其他已发布组的成员恢复独立入口；Home 的具体显示与分组以客户端为准。

窗帘可在 Home 中设置位置；是否提供独立停止入口取决于客户端。若 Home 没有停止入口，可使用标准 Matter 客户端发送 `StopMotion`。实际位置、设备目标和运动状态以设备报告为准；`status DID` 显示各项的来源时间、接收时间、读取与通知诊断，以及最近命令和回执。首次读取前为未知，读取或连接中断时保留最近有效值；运行时由通知和周期读取更新。一次读取可能只读到中途位置，不据此推断动作完成。重启或恢复后不重放之前的目标或停止命令。

空调可选择制冷、制热、自动、送风和除湿，以及自动／低／中／高风速；温度按整度设置，上下摆风只在设备支持时提供。独立开关保留设备记忆的模式、温度和风速；切换模式或设置非零及自动风速时会在必要时先开机。单独调温不会开机或切换模式，风速设为零会关机，上下摆风只调整摆风。可设值取决于当前控制范围；例如 mcn04 的代表配码在自动模式下不允许调温，实际配码请以 `status DID` 为准。终端对空调只提供开关控制；模式、温度、风速和摆风由支持对应功能的 Matter 客户端操作。

Home 选择“自动”用于切换设备的原生自动模式。若当前配码不允许自动模式调温，拖动 Home 显示的温度范围会被拒绝，界面可能回到原值；需要调温时先选择允许调温的模式，再设置整数温度。

用 `status DID` 查看空调的 `Power`、`Mode`、`Target temperature`、`Speed`、可选 `Vertical swing`、各模式控制范围、读取与通知来源及最近命令。mcn04 的 `Control range source` 显示范围来源和诊断；显示 `Control range is awaiting source confirmation` 时，等待来源恢复并重新确认，依赖范围的模式、温度和风速设置暂不可用，独立开关与支持的上下摆风仍按各自命令处理。mcn04 状态以伴侣整包反馈为准；mcn02 直连使用其旧 miIO 映射，其他符合契约的标准空调以设备属性反馈为准，mcn04 的状态及范围补丁不用于 mcn02。命令受理不代表状态已更新。首次读取前状态未知，来源中断保留最近有效值，恢复后重新读取。自动风下若显示 `Current fan level: unknown (automatic speed)`，表示设备未提供实际挡位；恢复或重启不重放之前的空调命令。

空调开机并选择自动风时，Home 的风速数字使用 `33%`（或 1 挡）作为显示占位，使控制界面保持可操作；实际模式仍为 Auto，终端显示当前风速未知是预期行为。不要用这个占位数字判断实际出风强弱或配置依赖真实风速的自动化。切换普通风后显示设备报告的设定，关机后显示零。

为指定空调手动绑定一个已接入的环境温度功能。先用 `list` 查找空调和传感器的 DID 与功能标识，再在运行 MiGate 的终端输入：

```text
bind-sensor 234567890 air-conditioner:3 345678901 temperature:3:7
status 234567890
```

以上标识仅为示例，请替换为 `list` 中的实际值。一个空调功能最多绑定一个温度功能，同一个温度功能可供多个空调使用；再次执行 `bind-sensor` 并指定另一来源即可更换。解除绑定时执行 `unbind-sensor 234567890 air-conditioner:3`。两端须属于当前家庭且具备访问资格，传感器暂时离线也可绑定；环境温度仅供显示，不参与空调控制，独立传感器继续展示。绑定随数据目录保存，重启后等待温度来源重新取得读数；切换米家账号或家庭会清空绑定。

`status 空调DID` 中的 `Target temperature` 是空调设定温度，`Ambient source` 和 `Ambient temperature` 是绑定的来源及环境温度，并显示来源时间和接收时间。未绑定、尚待有效读数、来源不可用或来源不在目录时，环境温度显示 `unknown` 及原因。若来源失效，`Last reading (diagnostic only)` 是仅供排障的旧读数；查看 `Ambient source synchronization` 以及传感器的 `status DID`，核对读取和通知诊断。若显示 `Matter mapping unsupported: native ambient temperature cannot be represented`，来源读数无法用 Matter 温度表示，原始读数仍保留，Matter 返回空值。恢复访问后等待新的有效读数；正常静默及单次同步失败不会自动丢弃已有有效读数。来源移除或撤权时绑定仍保留，也可直接按空调标识解除。

独立温度传感器自动读取暂停且通知也不可用时，即使诊断仍保留最近温度，绑定空调的环境温度也会显示 `unknown`；仅有温度功能的传感器会在 Home 中显示不可达。通知或读取恢复后，等待新的有效温度读数，再检查空调显示。

Home 在没有当前有效环境温度时，仍可能显示 `0℃` 或保留旧温度。用 `status 空调DID` 的 `Ambient temperature` 判断读数是否有效；出现 `unknown` 时按原因排查绑定及来源，不将 Home 的数值当作当前有效温度。

风扇的百分比风速映射到设备实际可达的挡位；满足识别条件的普通数值范围（含步长）或有序离散挡位可接入，不表示设备支持连续调速。`0%` 表示关机，非零调速会先确保开机。水平摇头只调整摇头，不改变电源或风速。Home 的具体风速和摇头入口以及何时发送写入，以客户端实际提供的控件为准。

已支持的 `dmaker` 风扇自然风在米家中设置；自然风运行时显示的是设备记忆的直吹风速设定，不是自然风瞬时风速。Home 或其他 Matter 客户端发送非零风速会切回直吹，即使写入的百分比与当前显示值相同也会接管。独立开机保留设备记忆的模式和风速；关机或设置 `0%` 保留原生模式和直吹设定，设备确认关机后显示关闭及零风速。

用 `list` 和 `status DID` 查看风扇状态与诊断；`status DID` 可查看开关、风速、设备支持的摇头、最近命令结果及读取和通知来源，适用时还显示原生模式和直吹设定。各项首次取得有效值前为未知，单次读取失败或来源断连时保留最近有效状态，不将未知或断连推断为关机。恢复时重新获取状态，恢复或重启均不重放之前的开关、调速或摇头命令。

### 浴霸

浴霸 v13 在原有物理父端点和 `light:2` 照明之外，提供 `heater:3` 暖风、`fan:3:2` 吹风和 `fan:3:4` 换气。暖风只提供 Off / Heat，目标温度范围为 25–45°C。吹风和换气在 Matter 中只有关闭、50% 和 100%。从关闭直接选择 50% 会以低挡启动。单独按开默认使用高挡，风道已经运行时再次按开会保留当前挡位。需要从低挡升到高挡时，直接选择 100%。终端可用 `on`／`off` 控制开关，用 `mode DID FUNCTION off|heat` 切换暖风模式，用 `temperature DID FUNCTION VALUE` 设置目标温度。

吹风或换气开机提示状态未知时，用 `status DID` 检查对应风道开关的读取问题，恢复后再次按开。

```text
on 743765151 heater:3
off 743765151 heater:3
mode 743765151 heater:3 heat
temperature 743765151 heater:3 30
on 743765151 fan:3:2
off 743765151 fan:3:2
status 743765151
```

暖风功率请在米家调整。改档可能启动暖风，Home 会更新实际启停状态。需要停止时，在 Home 关闭暖风或执行 `off 743765151 heater:3`。暖风和吹风互斥，换气可与任一功能同时使用。

共享 `get_prop` 读组返回 `bh_mode`、`fan_speed_idx` 和 `temperature`，供两路挡位及暖风当前温度共同使用；它不是标准属性通知。`status DID` 会显示共享组当前候选与选中的读取路径、最后成功来源、原始 `bh_mode`、`fan_speed_idx`、`temperature`、两路挡位及各自的未知原因；标准 `3.1 mode` 和功能原生属性分别显示。挡位等待回读时保留最近有效挡位和原观测时间，并标记待刷新；只有设备明确报告无效挡位才把相应挡位置为未知。读取失败保留最近有效值，业务拒绝或单字段异常不影响其他有效接口。

暖风及两路风扇控制受理后，或已发送但结果不确定时，都会安排只读核对；该核对与通知是否已就绪无关，原命令的受理或不确定结算不变。

各项测量、状态与电量分别更新，首次取得有效值前显示未知，正常静默时保留最近观测，重启后重新获取。用 `status DID` 查看读数或状态、来源时间、接收时间、当前读取路径、通知来源和诊断。门窗、运动与存在功能还显示参与判定的原生属性值或事件标识、解释后的状态、最近观测来源，以及各属性和事件绑定的订阅状态。读取成功不代表通知同步已就绪；运动同步受限时，分别检查事件订阅和无移动时长属性订阅。单项读取或订阅失败不影响其他功能，电量失败也不影响测量与状态。除通知和恢复读取外，可读属性也周期更新；Home 是否显示电量及如何分组，以客户端为准。

在同一米家家庭内改回路类型或调整设备后，网桥会恢复 Home 已保存的有效订阅，已有配件的端点保持不变。若 Home 显示旧值，用 `status` 确认配置已应用，再用 `status DID` 核对该路的实测值和通知来源。如果 MiGate 已收到新值而 Home 仍未更新，可重新打开「家庭」App。更换米家账号或家庭后，需等 Home 重新订阅。详情见[已知限制](known-limitations.md#home-显示与恢复)。

## 日常操作

在运行 MiGate 的终端中，每行输入一个命令：

| 命令 | 操作 |
| --- | --- |
| `list` | 查看设备、DID、功能标识、能力及识别和发布信息 |
| `status [DID]` | 查看账号、中枢、设备及各功能读数、状态、时间、当前路径和诊断 |
| `on DID FUNCTION` | 开启指定功能 |
| `off DID FUNCTION` | 关闭指定功能 |
| `map-type DID FUNCTION switch\|light` | 设置墙壁开关单路在 Home 中显示为开关或灯 |
| `mode DID FUNCTION off\|heat` | 切换仅制热暖风模式 |
| `temperature DID FUNCTION VALUE` | 设置仅制热暖风目标温度（25–45°C） |
| `bind-sensor TARGET_DID TARGET_FUNCTION SENSOR_DID SENSOR_FUNCTION` | 为空调绑定或更换环境温度来源 |
| `unbind-sensor TARGET_DID TARGET_FUNCTION` | 解除空调的环境温度绑定 |
| `help` | 查看命令帮助 |

先用 `list` 查找 DID 和功能标识，单功能设备也必须指定功能。控制功能以服务为锚点，例如 `relay:2`、`light:2`、`fan:3`、`air-conditioner:3`、`outlet:9`；测量和状态功能以属性为锚点，例如 `temperature:3:7`。以下 DID 和功能标识均为示例，请替换为实际值：

```text
list
status 123456789
on 123456789 light:2
off 123456789 light:2
on 987654321 outlet:9
off 987654321 fan:3
status 234567890
on 234567890 air-conditioner:3
off 234567890 air-conditioner:3
mode 743765151 heater:3 heat
temperature 743765151 heater:3 30
on 743765151 fan:3:2
off 743765151 fan:3:2
bind-sensor 234567890 air-conditioner:3 345678901 temperature:3:7
status 234567890
unbind-sensor 234567890 air-conditioner:3
```

`list` 和 `status DID` 显示设备品类、功能能力、绑定与生效补丁；其中 `mcn02` 和 `v13` 的直连适配说明可用于检查型号映射，实际路径及是否可用以 `status DID` 为准。浴霸还会显示标准 `3.1 mode`、共享旧字段、两路挡位和各功能的读取路径。`core` 是用途说明，可有多个或没有，不影响功能接入和控制；必须明确指定控制目标。`Recognition issue` 提示候选功能、可选能力或补丁的识别问题，需与已接入功能的连接、读取和通知故障区分。灯组的 `Native capabilities`、`Repaired` 和 `State source` 分别说明原生能力、成员派生的增强和状态来源，`Member relation` 提示成员定位问题。

终端输出使用英文，设备名称原样显示。`unknown` 表示尚无确定状态，可能是尚未取得有效输入，也可能是设备明确上报未知。`on`／`off` 可控制受支持的插座、墙壁开关回路、灯光、风扇、空调和暖风；窗帘、测量与状态功能不支持 `on`／`off`，同机其他受支持的控制功能仍可操作。`upstream time` 是来源提供的时间，缺失时为 `unknown`；`received at` 是 MiGate 收到数据的时间。门窗、运动与存在功能显示的最近观测来源与时间仍对应保留状态，来源切换后可能与当前读取路径或通知来源不同。

`command accepted` 表示请求已受理，不保证物理动作或灯组所有成员均已完成。命令超时后也可能已经执行，请先核对设备状态，MiGate 不会自动重放。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 没有发现设备 | 用 `list` 查看原因，确认账号、米家家庭及云端连接；首次绑定还需 Mac 与中枢处于同一局域网。 |
| 设备不可用或主中枢切换后未恢复 | 检查供电、中枢和网络，用 `status DID` 查看路径与请求结果，等待自动恢复；持续异常时参见[已知限制](known-limitations.md)。 |
| 某项测量长期不更新 | 用 `status DID` 检查该功能的读取路径、通知来源及同步受限原因，再核对米家读数和实际网关。周期读取可能返回上游缓存，不能代替设备采样。 |
| 门窗、运动或存在显示 `unknown` | 用 `status DID` 区分首次读取失败、设备明确上报未知和订阅问题，核对米家状态并等待有效读取或通知；不要将未知当作关闭或无人。 |
| 状态保持旧值或显示同步受限 | 用 `status DID` 检查该功能的读取路径、通知来源，以及各属性和事件订阅；来源中断时保留最近观测，周期读取无法补回瞬时事件。 |
| 运动长时间保持检测到移动 | 用 `status DID` 检查最近输入是运动事件还是原生无移动时长，并检查时长属性订阅，再核对米家状态。恢复由设备原生报告决定，MiGate 不自行倒计时。 |
| 没有电量或电量不更新 | 用 `status DID` 查看电量能力及错误，核对米家读数。并非所有设备都提供可自动更新的电量；失败时保留已有读数，不影响其他测量与状态。 |
| 提示 Matter 映射不支持 | 用 `status DID` 查看对应功能的原生读数和映射诊断；MiGate 保留原生值，无法表示为协议数值的项目不能正常发布读数。 |
| 云端暂时不可用 | 等待网络或服务恢复。中枢或已确认的设备直连可用时，已有设备仍可使用；新设备接入与移除同步可能延迟。 |
| 直连不可用或地址变化 | 用 `status DID` 检查协议、身份、地址、候选和恢复进度，确认设备供电及局域网连接；等待自动重新发现。凭据无效时检查账号和目录同步，等待地址或 token 更新。其他路径可按各自资格继续使用。 |
| 窗帘位置或运动状态不更新 | 用 `status DID` 分别检查当前位置、目标、运动状态的读取和通知诊断，核对米家状态；读取成功不代表通知已就绪。来源恢复后等待重新读取与通知。 |
| 窗帘停止或目标命令报错 | 查看 `status DID` 中的请求结果并核对实际窗帘；回执超时后命令仍可能执行，MiGate 不会重放。 |
| 风扇状态未更新或调速报错 | 用 `status DID` 检查开关、风速、适用的模式与直吹设定及读取和通知诊断，再核对米家与实际设备。请求受理不代表状态已经回传；超时后命令仍可能执行，MiGate 不会重放。 |
| 空调环境温度显示 `unknown` | 用 `status 空调DID` 确认绑定对象与未知原因，再查看来源设备的 `status DID` 和同步诊断。等待来源恢复并取得新的有效读数；仅供诊断的旧读数不代表当前温度。 |
| 浴霸暖风、吹风或换气状态未更新 | 用 `status DID` 查看对应功能的标准属性读取、共享 `get_prop` 组的选中路径、最后成功来源和待刷新状态，再核对米家与实际设备。单次读取失败保留最近有效值；业务拒绝或单字段异常不一定表示整机断连。 |
| 浴霸当前温度不更新 | 用 `status DID` 查看 `Legacy feedback group` 的 `temperature` 原始值、选中路径和读取问题。直连与云端共用同一逻辑温度来源；单个路径失败时保留最近有效读数，全部获取路径不可用时旧读数仅用于诊断，恢复后等待新读数。 |
| 空调状态未更新或设置报错 | 用 `status DID` 检查当前模式、各模式控制范围、读取及通知诊断和最近命令，再核对米家与实际设备。范围未知或等待来源确认时检查连接并等待恢复；已列出的范围可能不允许当前模式下调温或所选风速。受理或超时都不能代替反馈，超时后先核对状态，MiGate 不会重放。 |
| 功能未接入或设备不可用 | 用 `list` 或 `status DID` 查看识别问题和实际功能；没有可发布功能时会显示 `not published` 和原因。已接入但不可用时检查连接、路径、读取与通知诊断。 |
| 灯组未出现或成员仍独立显示 | 用 `status DID` 检查组和成员的接入原因及 `Member relation`，等待云端同步；多个灯光无法定位时不会任意隐藏。 |
| 灯组状态延迟或未知 | 查看组及成员的 `status DID`，确认成员可用且通知正常；组内各成员的状态可能不同。 |
| 灯组关闭的成员没有跟随派生 RGB 颜色 | 成员派生的 RGB 只影响发送时确认开启的成员；先开灯，再重新选择颜色。 |
| 米家调整成员后又被组渐变覆盖 | 先在 Home 停止或替换组动作，再调整成员。 |
| 描述获取或配置保存失败 | 用 `list`、`status` 和错误日志查看原因，检查网络、数据目录权限与可用空间；程序保留上次配置并继续重试。 |
| 启动后提示缓存识别失败 | 用 `list` 或 `status DID` 查看原因并保留原数据目录。该设备继续使用旧配置，其他设备仍可更新；等待目录提供新描述，或更新 MiGate 后重启。相同输入不会定时重试。 |
| 启动失败 | 检查错误日志、数据目录权限、可用空间、端口与网络；修复后用原目录启动，无须清空数据。 |
| 日志提示忽略了无法加载的 Matter 数据 | 保留数据目录，等待 Home 恢复订阅；若重新出现配对窗口，按下节使用原目录重新配对。恢复范围见[已知限制](known-limitations.md#home-显示与恢复)。 |
| 提示需要重新登录 | 停止网桥，使用原数据目录执行 `auth check` 查看受影响的凭据，再用同一目录执行 `auth login` 并重启。遇到额外安全验证时先按「米家账号」处理。 |
| 提示 `Stored Xiaomi credentials are invalid` | 停止网桥，在原数据目录执行 `auth logout` 后重新 `auth login`；Matter 身份与 Home 配对会保留，直连凭据需重新获取。 |
| 提示 `Database version is not supported` | 保留原目录，用 `--data-dir` 指向新的空目录。按下方「数据目录与重新配对」重新登录并配对。 |
| 提示数据目录正在使用 | 停止使用该目录的另一个 MiGate 进程，再重试；不要删除锁文件。 |
| Apple Home 无法发现网桥 | 确认配对窗口仍有效、Mac 未休眠，且网络允许 mDNS 和 Matter UDP 通信。 |

需要详细日志时：

```sh
RUST_LOG=info,migate=debug cargo run --locked
```

日志写入标准错误，终端命令结果和配对信息写入标准输出。

Matter 属性读取失败日志显示端点、簇和属性编号及处理阶段，不包含属性值。排查中枢请求超时时，可用 `RUST_LOG=info,migate::xiaomi::central::session::dispatch=debug` 启动，在 `Gateway request completed` 中查看操作、设备、请求编号及阶段。

排查 Home 重启恢复时，可用 `RUST_LOG=info,rs_matter_im=debug` 启动，核对订阅的 `max_int_secs` 和 `primed` 日志。控制回执与状态订阅分别检查：从 Home 操作后核对米家状态，再从米家改变状态，观察 Home 是否自行更新。

若默认端口被占用，可通过 `MIGATE_MATTER_PORT` 设置其他端口；设为 `0` 时由系统分配，启动日志会显示实际端口。运行多个网桥时，分别使用独立数据目录和不同端口。

## 数据目录与重新配对

数据目录包含账号凭据、证书、设备名称与配对信息，请妥善保留，避免提交或共享。首次使用的目录须为空或尚不存在。

目录选择顺序为：

1. `--data-dir <PATH>`，该参数须放在 `auth` 之前。
2. `MIGATE_DATA_DIR` 环境变量；仓库的 Cargo 配置默认将其设为项目下的 `.migate/`。
3. `~/.migate/`。

相对路径按命令执行目录解析，启动日志会显示实际路径。异常退出后可直接使用原目录重启，无须删除 `instance.lock`。重启会恢复设备配置并重新识别已有设备，再同步目录和实际状态，不继续执行上次未完成的灯光动作，也不重放窗帘、风扇或空调命令。

若需要全新实例，可停止 MiGate 并选择一个为空或尚不存在的新目录，依次登录和启动。例如：

```sh
cargo run --locked -- --data-dir .migate-new auth login
cargo run --locked -- --data-dir .migate-new
```

在「家庭」App 中按新显示的配对码添加网桥。新目录建立新的配对身份，需要重新登录米家；原网桥的 Home 名称、房间、场景和自动化不会自动带入新网桥。原数据目录和原配对会保留，请自行整理 Home 中的旧网桥。

在线从「家庭」App 移除配件后，可使用原目录重新配对。若离线移除后无法重新配对，或需要全新实例，同样可选择与原目录并列的新目录：

```sh
cargo run --locked -- --data-dir .migate-trial-1 auth login
cargo run --locked -- --data-dir .migate-trial-1
```

新实例需要重新登录米家账号并添加到 Apple Home，原目录的数据会保留。
