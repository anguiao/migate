# MiGate 米家登录与中枢访问凭据

## 目标与范围

在现有 Rust 程序中实现米家账号登录、令牌持久化与刷新，以及中枢客户端证书的申请、保存和按需续期。设备列表请求用于验证云端认证，不作为独立的设备发现或管理功能交付。

使用中国大陆服务区 `cn`，每个数据目录保存一个账号的凭据。沿用当前 macOS / Apple Silicon 环境、SQLite 存储、前台网桥运行方式和英文终端输出。

后续希望尽量通过中枢网关实现本地控制，因此认证方案以官方 HA 的中枢接入链路为参考，为后续本地接入准备凭据。[官方本地化说明](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/doc/README_zh.md)

本轮交付独立认证命令、浏览器授权与完整回调网址粘贴、账号令牌管理、中枢客户端身份与证书管理，以及网桥终端的状态展示。中枢网关发现、家庭选择、MQTT 连接、设备控制和真实设备的 Matter 映射留到后续阶段。证书准备完成不等于网关连接成功。

其他服务区、多账号管理、账号密码登录、完整设备清单及其持久化、管理界面和常驻 HTTP 服务不在本轮范围。设备信息不进入现有 `device` 模型，也不分配 Matter endpoint。

## 认证方案与云端依赖

采用官方 Home Assistant 集成对应的 OAuth 应用和米家云入口。MiGate 自己实现所需协议，不依赖运行 Home Assistant 或 Miloco。

| 方案 | 取舍 |
| --- | --- |
| 官方 HA OAuth 与中枢客户端证书 | 选用。上游具备证书签发、续期和本地中枢连接流程，符合后续本地化方向。终端授权采用手动粘贴完整回调网址。 |
| Miloco OAuth 与官方回调展示页 | 不选用。复制授权结果较方便，但尚未验证该应用的令牌能够用于中枢客户端证书申请。 |
| 米家账号会话 | 不选用。需要处理另一套身份验证与请求签名；单设备局域网凭据不能直接代替中枢客户端证书。 |

参考：[HA 配置](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/const.py)、[HA 云端协议](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_cloud.py)、[Miloco 云端协议](https://github.com/XiaoMi/xiaomi-miloco/blob/main/backend/miot/src/miot/cloud.py)、[米家会话实现](https://github.com/al-one/hass-xiaomi-miot/blob/master/custom_components/xiaomi_miot/core/xiaomi_cloud.py)。

## 命令与数据目录

命令形式为 `migate [--data-dir <PATH>] [auth <login|check|logout>]`。显式数据目录参数位于 `auth` 之前。

| 命令 | 行为 |
| --- | --- |
| `migate` | 启动现有网桥与终端，并异步执行一次凭据检查。 |
| `migate auth login` | 发起新的浏览器授权，验证云端访问，准备中枢客户端证书，整体保存凭据后退出。 |
| `migate auth check` | 检查云端认证和本地证书，必要时刷新令牌、续期证书，显示两项结果后退出。 |
| `migate auth logout` | 删除本地账号令牌、中枢客户端身份、私钥和证书后退出。没有记录时同样成功。 |

认证子命令不启动 Matter 服务、配对窗口或终端灯控制。它们通过同一个 `Store` 使用数据目录；新目录沿用现有初始化规则，已有目录复用身份和 Matter 数据。

数据目录优先级保持为 `--data-dir`、`MIGATE_DATA_DIR`、`~/.migate/`，相对路径按启动工作目录解析。开发时继续使用 Cargo 注入的数据目录：

```sh
cargo run --locked -- auth login
cargo run --locked -- auth check
cargo run --locked -- auth logout
```

直接运行构建产物时可显式指定目录：

```sh
./target/release/migate --data-dir .migate auth login
./target/release/migate --data-dir .migate auth check
```

交互提示和状态结果写入标准输出，诊断日志写入标准错误。登录只有在云端验证、证书准备和保存全部完成后才返回成功。检查只有在云端验证、本地证书检查及本次需要的更新全部完成后才返回成功；未登录、认证或证书操作失败返回非零状态。

EOF 或 `Ctrl-C` 结束尚未完成的登录，返回非零状态且不覆盖原记录。网桥正常 `Ctrl-C` 退出仍返回成功。

## 浏览器授权与首次保存

### 授权交互

1. 为本次授权生成独立、不可预测的随机回调路径标识。完整回调地址使用上游的 `/api/webhook/<标识>` 路径形式，基址为 `http://homeassistant.local:8123`。
2. 使用应用标识、完整回调地址、`response_type=code`、`ha.<uuid>` 形式的 OAuth 设备标识及按上游规则计算的 `state` 生成授权链接。有记录时复用其中的 OAuth 客户端 UUID，无记录时生成新的随机 UUID。
3. 终端显示授权链接和输入指引。用户手动打开浏览器登录并授权，随后复制地址栏中的完整回调网址，粘回等待中的终端。
4. MiGate 不提供回调 HTTP 服务，不修改 hosts 或发布回调域名。因此回调页面可能显示无法访问；输入指引应提前说明，并明确要求复制包含 `code` 和 `state` 的最终网址。
5. 输入边界去除首尾空白并解析网址，核对协议、主机、端口、路径和本次 `state`，拒绝缺失或重复的必要参数及 OAuth 错误结果。只从网址提取授权参数，不访问用户粘贴的网址。
6. 只接受与当前授权尝试对应的完整回调网址，每份授权回调仅对生成它的授权尝试有效。

`state` 按上游公式计算：对 `d=<device_id>` 的 UTF-8 字节求 SHA-1，输出为 40 位小写十六进制字符串，其中 `device_id` 为实际提交的 `ha.<uuid>`。复用同一 OAuth 客户端 UUID 时 `state` 相同；每次随机生成的回调路径用于区分授权尝试，完整回调地址和预期 `state` 必须同时匹配。

授权时与令牌交换时使用完全相同的 OAuth 设备标识和回调地址；保存成功后继续保留该回调地址，供刷新令牌使用。`state` 和授权码只保留在本次流程内存中，不持久化、不写日志。[上游授权与回调实现](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/config_flow.py)、[OAuth 参数与刷新接口](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_cloud.py)

### 云端验证与证书准备

授权码交换得到令牌后，按以下顺序完成登录：

1. 校验访问令牌、刷新令牌和 `expires_in`，计算实际到期时间及提前刷新时间。
2. 通过下述最小设备读取路径验证云端访问，并从账号自有家庭信息中取得账号 UID。
3. 按下述复用规则准备客户端虚拟设备标识 `virtual_did`、本地私钥和证书；需要签发证书时生成 CSR，再向证书接口申请。
4. 校验证书可解析、有效期、账号与客户端身份，以及证书公钥和本地私钥是否匹配。
5. 在一个事务中保存账号身份、OAuth 配置、令牌、客户端标识、私钥和证书，提交成功才报告登录完成。

`virtual_did` 是 MiGate 用于中枢连接的客户端虚拟设备标识，使用随机 64 位整数的十进制字符串，与实物网关标识、OAuth UUID 和 Matter 身份分别管理。客户端证书关联账号 UID、`virtual_did` 和公钥，不绑定某一台具体网关。

证书申请只提交 CSR，无须提供网关 DID。上游连接不同网关时复用同一组 `virtual_did`、私钥和证书，连接目标通过家庭 `group_id` 和发现的网关地址另行确定。因此本轮证书准备不依赖网关发现或连接；实际能否接入网关由后续连接流程验证。[上游证书申请](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_cloud.py)、[上游中枢连接](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_client.py)

重新登录同一 UID 时复用已有客户端身份和私钥；使用仍有效且未进入续期窗口的证书，否则申请新证书。更换 UID 时建立新的客户端身份、私钥和证书，不能把旧账号证书关联到新账号。

本次新登录的全部候选数据在最终事务提交前不覆盖已有凭据。取消、输入错误、云端验证失败、证书申请或校验失败均保留原有本地记录。保留本地记录不代表能够保证旧授权在云端继续有效。

## 中枢连接的客户端证书格式与续期

参考上游使用 Ed25519 私钥，以 PKCS#8 PEM 保存；只将包含公钥的 CSR 发送给云端，不发送私钥。

CSR 的主体包含：

| 字段 | 值 |
| --- | --- |
| Country | `CN` |
| Organization | `Mijia Device` |
| Common Name | `mips.<uid>.<did_hash>.2` |
| `did_hash` | `virtual_did` 的 UTF-8 字符串经 SHA-1 得到的十六进制摘要 |

证书必须与当前 UID、`virtual_did` 和私钥匹配，并根据证书自身的 `notBefore`、`notAfter` 判定有效性，不写死证书寿命。保留上游提供的小米 CA 公共证书材料，供后续中枢 TLS 连接使用；网关握手不在本轮范围内，证书准备完成不作为网关身份验证的依据。[上游证书实现](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_storage.py)

启动检查和 `auth check` 在证书已到期或剩余有效期不超过三天时尝试续期，沿用上游的提前续期窗口。续期复用当前客户端身份和私钥，新证书校验通过后单独事务替换旧证书。续期失败保留原证书，按其真实有效期显示有效、即将到期或已到期，并报告续期失败原因。[上游续期逻辑](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_client.py)

本轮仅在登录、启动和 `auth check` 的流程中进行云端更新，不增加周期任务。后续实现长期运行的网关连接时，再设计连接期间的证书续期与重载。

## 令牌复用与检查顺序

启动和 `auth check` 复用同一流程：

1. 没有凭据时返回未登录，不访问云端。存在凭据时，先根据本地证书内容得出证书状态。
2. 访问令牌尚未到刷新时间时直接进行云端读取；到达刷新时间则先刷新令牌。
3. 受保护请求被明确判定为访问令牌无效时，若本次检查尚未刷新，则刷新一次后重试失败的操作。设备读取和证书申请共享这次刷新额度，一次检查最多刷新一次。
4. 有效刷新结果立即通过事务保存整组新令牌及有效期，再继续后续检查。后续设备读取或证书操作失败时仍保留新令牌，避免刷新令牌轮换后只保存旧值。
5. 云端读取完成后，检查返回的 UID 与记录一致，并在需要时续期证书。云端验证无法完成时保留本地证书状态，不将其改为已失效。
6. 分别输出云端认证结果和证书状态；某项检查失败不抹去另一项已得到的结果。

依据 `expires_in` 保存实际到期时间，并将有效期经过 70% 时作为刷新时间。该时间只是提前刷新阈值，不表示令牌已经失效。

刷新令牌被明确拒绝，或刷新后的访问令牌仍被明确拒绝时，云端状态为需要重新登录。网络错误、限流、服务错误或响应协议异常为暂时无法确认。证书接口的业务权限错误单独报告，不能仅凭证书申请被拒绝就把已验证的账号令牌判为无效。

每个 HTTP 请求使用 30 秒超时，不无限重试。取消流程不等待网络请求完整超时，也不产生取消后的凭据写入；取消前已经提交的有效刷新结果保留。

## 最小设备读取与云端边界

MiGate 直接向 `https://ha.api.io.mi.com` 请求账号资源，不调用运行中的 HA 或 Miloco 服务。设备读取仅验证认证并提供证书所需的 UID，不输出设备目录或账号设备总数。

先调用 `/app/v2/homeroom/gethome` 获取第一页家庭和设备归属信息，关闭共享家庭与共享设备扩展。从自有家庭中提取账号 UID，并将该页家庭和房间的设备标识去重，最多取 150 个，再调用 `/app/v2/home/device_list_page` 读取一页设备结果。无设备标识时不继续请求设备详情；不追踪分页，不请求图标、MIoT spec 或设备属性。

设备为空是正常结果，不以设备型号或设备是否能桥接决定登录成败。若没有自有家庭信息而无法获得 UID，应明确报告无法确定证书所需的账号身份，不将共享家庭所有者的 UID 当成本人 UID，也不把这种情况描述为令牌失效。新登录在证书准备完成前不提交凭据。

云端成功须同时满足 HTTP 与业务状态成功、必要响应字段可解析。设备请求若已发起，也必须成功；只有 HTTP 成功状态不足以判定认证成功。

云端适配层按 HA 上游协议封装请求：令牌接口使用 GET 与 `data` JSON 查询参数；设备和证书接口使用 JSON 请求体，证书请求中的 CSR 使用 Base64 编码。受保护请求使用 `X-Client-BizId: haapi`、对应应用标识，以及上游的 `Authorization: Bearer<access_token>` 格式，并保持 HTTPS 证书校验。[HA 云端实现](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_cloud.py)

## 网桥终端状态

云端认证和中枢证书分别展示，状态文字继续使用英文。证书时间采用 UTC RFC 3339 格式，精确到秒。

| 云端状态 | 英文输出 |
| --- | --- |
| 没有记录 | `Xiaomi: not signed in (cn).` |
| 正在检查 | `Xiaomi: checking authentication (cn)...` |
| 云端访问验证通过 | `Xiaomi: authenticated (cn).` |
| 明确需要重新授权 | `Xiaomi: sign-in required (cn).` |
| 暂时无法确认 | `Xiaomi: authentication unavailable (cn).`，附简短原因。 |

| 证书状态 | 输出语义 |
| --- | --- |
| 未准备 | `Gateway certificate: not prepared.` |
| 尚未生效 | `Gateway certificate: not valid before <UTC timestamp>.` |
| 有效 | `Gateway certificate: valid until <UTC timestamp>.` |
| 即将到期 | 展示真实到期时间及 `renewal due`。 |
| 已到期 | `Gateway certificate: expired at <UTC timestamp>.` |

例如，网络不可用而本地证书仍有效时，保留两项独立结果：

```text
Xiaomi: authentication unavailable (cn). Network request failed.
Gateway certificate: valid until <UTC timestamp>.
```

续期失败时额外报告失败操作和原因，保留证书有效期的真实状态。输出不使用“网关已连接”或“本地控制可用”等尚未验证的结论。

无凭据时给出登录指引，使用当前可执行文件路径和实际数据目录，按 shell 规则引用路径，形成可复制的命令。已有凭据时直接展示状态及必要原因，不追加 `auth check` 或 `auth logout` 建议。

启动时执行一次异步检查；终端命令帮助展示最近一次云端检查结果，证书日期状态按当前时间计算。现有 `on`、`off`、`status` 继续用于虚拟灯，认证命令在 shell 中执行。

认证请求等待、失败或正常结束均不终止网桥，也不阻塞配对、灯控制和退出处理。存储故障仍作为应用错误停止运行。其他进程更新凭据不会自动刷新运行中的终端，本轮不增加跨进程同步。


| --- | --- |
| `main.rs` | 分派网桥模式与独立认证命令，组装依赖，管理异步任务、退出信号和运行生命周期。 |
| `config.rs` | 解析命令与参数，按既定优先级确定数据目录。 |
| `terminal/mod.rs` | 组织终端接口，提供两种运行方式共用的认证状态格式化与输出。 |
| `terminal/bridge.rs` | 处理虚拟灯命令、终端帮助和认证状态展示。 |
| `terminal/auth.rs` | 处理独立认证命令的交互，显示授权链接与指引、接收回调网址并展示结果。 |
| `xiaomi/auth.rs` | 编排登录、检查、刷新和退出，组织云端认证与证书的独立结果，不依赖 Matter 或终端文本。 |
| `xiaomi/cloud.rs` | OAuth 链接和令牌请求、最小设备读取、证书签发请求，以及响应与错误解析。HTTP 和 JSON 类型限制在此边界。 |
| `xiaomi/certificate.rs` | 生成客户端身份、私钥和 CSR，校验证书身份、公钥匹配与有效期，计算续期时间。密码库类型限制在此边界。 |
| `storage/xiaomi.rs` | 读取完整认证记录、整体替换新登录、分别更新令牌或证书，以及删除凭据。SQLite 操作集中在存储模块。 |
| `storage/migration.rs` | 管理数据库版本与迁移，保留已有身份和 Matter 数据。 |

独立认证命令与网桥启动检查复用同一套 `xiaomi` 认证逻辑。`matter/`、`device.rs` 和 `virtual_device.rs` 保持现有职责；通用设备模型随真实设备接入设计，后续中枢连接归入 `xiaomi/`。

网络请求不得阻塞现有执行器。一次性检查任务结束不能通过现有运行时的并发等待逻辑提前结束网桥生命周期。

### 持久化

沿用 `rusqlite`，通过参数化 SQL 和显式事务完成存储操作，本轮不引入 ORM。SQL 与字段映射集中在 `storage/` 内，对外提供明确的 Rust 结构体和操作方法，认证流程通过这些接口读取及更新凭据。

在 SQLite 中增加独立的单账号认证存储，包含 UID、服务区、OAuth 客户端 UUID、完整回调地址、访问令牌、刷新令牌、令牌实际到期与刷新时间、客户端 `virtual_did`、私钥 PEM 和客户端证书 PEM。证书日期从证书本身解析；不持久化“已认证”或“已连接”布尔值。

认证记录与现有 `identity`、Matter `blobs` 分开。首次迁移使用有版本标识的事务创建认证存储，新数据库直接使用新版本。迁移完整保留已有网桥、虚拟灯身份与 Matter 数据；必要表缺失、字段损坏、未来版本或迁移失败时明确报错，保留原数据，不重新初始化修复。

凭据不存在表示未登录；已保存的私钥或证书无法解析、身份不匹配属于存储数据损坏。证书已到期或按当前时间尚未生效属于凭据状态，不属于数据库损坏；检查结束后仍处于这些状态时返回非零状态。

加载已有认证记录时发现内容损坏，登录与检查均报错并保留原记录，不以重新登录为由静默重建客户端身份。用户可显式执行 `auth logout` 清除认证记录，再重新登录；退出登录的删除操作不以旧令牌、私钥或证书可解析为前提。数据库本身无法访问、结构损坏或版本不支持时，仍按存储错误处理。

账号凭据、私钥和证书均保存在现有受限数据目录内的数据库中，不额外导出私钥文件。沿用目录 `0700`、数据库 `0600` 的权限。公开 CA 材料随程序提供，不作为账号秘密保存。敏感值不进入命令行参数、日志或状态输出。

网络等待不占用数据库事务。新登录整体提交；令牌刷新只更新令牌字段；证书续期只更新证书字段。沿用 SQLite 普通事务，不增加进程锁、IPC、文件监控或同时修改时的合并机制，也不要求执行认证命令前先停止网桥。

同一数据目录的认证流程（包括网桥启动检查）按不重叠执行的正常使用方式设计；重叠执行时的凭据一致性不在本轮保证范围内，接受由此可能产生的凭据覆盖或重新登录需要，不新增冲突检测与恢复机制。网桥启动检查结束后，可保持网桥运行并执行独立认证命令。

## 退出登录与错误处理

`auth logout` 在事务中删除本地账号凭据及其客户端身份、私钥和证书，不请求撤销远端 HA 应用授权，不删除数据库。网桥身份、虚拟灯身份和 Matter 配对数据保留；再次登录建立新的认证记录。

退出登录直接删除认证记录，无须先访问云端或校验待删除的认证内容；这也是认证内容损坏时的显式清理入口。

| 边界 | 处理 |
| --- | --- |
| 参数无效 | 显示用法，返回非零状态。 |
| 回调网址无效、必要参数缺失或重复、`state` 不匹配 | 不交换令牌、不修改记录，登录失败。 |
| 授权被拒绝、授权码失效或用户取消 | 本次登录失败，保留原记录。 |
| 检查时访问令牌被明确拒绝 | 启动检查或 `auth check` 尚未刷新时，刷新一次并重试失败的受保护操作。 |
| 刷新令牌或刷新后的访问令牌被明确拒绝 | 云端状态为需要重新登录，保留已有证书。 |
| 网络、限流、服务或响应协议异常 | 报告具体失败操作，保留凭据与已经完成的更新；网桥继续运行。 |
| 新登录时证书准备失败 | 不提交本次候选凭据，保留原记录。 |
| 证书续期失败 | 保留旧证书，显示其实际有效期及续期失败原因，检查返回非零状态。 |
| 存储读取、迁移或写入失败 | 报告操作与路径；命令失败，网桥模式停止并返回非零状态。 |

认证错误必须有明确的 HTTP 或业务错误依据。本轮按上游已明确的映射，将受保护接口的 HTTP `401` 视为访问令牌无效，将令牌刷新接口的 HTTP `401` 视为刷新被拒绝。不将 `403`、未明确含义的非零业务码或解析失败视为令牌失效；这些结果归入对应操作失败，保留其 HTTP 状态或业务码。[上游错误映射](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_cloud.py)

令牌交换和刷新接口返回非零业务码时，若 `message` 为可解析的 JSON 字符串且含整数 `error`，额外显示该内层 OAuth 错误码。`96002` 使用固定英文说明 `missing or invalid request parameters`，`96013` 使用 `invalid authorization code`；未知内层码只显示数值，详情缺失或格式不符时仍保留外层业务码。这些诊断信息不改变认证状态分类、刷新次数或凭据保留规则，也不用于解释设备或证书接口的业务错误。[OAuth 错误码定义](https://dev.mi.com/docs/passport/error-code/)

诊断保留操作名、HTTP 状态或业务码，不输出完整回调网址、授权参数、认证头、令牌查询串、私钥或原始响应体。登录指引中显示本次生成的授权链接属于必要交互输出，不据此允许诊断日志输出其中的参数。

原始 `message`、`error_description` 和 `traceId` 不进入错误对象、诊断日志或状态输出；内层错误仅保留数字代码，并使用程序内定义的固定说明。

## 验收标准

自动化测试使用隔离的数据目录和可控云端响应，覆盖：

- 独立命令沿用数据目录优先级，认证模式不启动 Matter 服务。
- 完整回调网址必须匹配当前尝试；错误、重复或不属于本次尝试的参数被拒绝；不会访问用户粘贴的网址。
- `state` 符合上游设备绑定摘要；授权和令牌交换的设备标识、回调地址一致。同一 OAuth UUID 的 `state` 可复用，旧尝试的回调路径仍被拒绝，且不交换令牌、不修改凭据。
- 登录完成令牌验证、设备读取、证书准备后才整体提交；失败和取消保留原记录。
- 有账号 UID 的空设备结果能够完成登录；缺少 UID 时明确区分云端认证和证书准备问题。
- 私钥与 CSR 的身份正确；返回证书须匹配 UID、虚拟设备标识和私钥，并处于有效期内。
- 重启复用凭据；同账号重新授权保留客户端身份，不把旧账号证书关联到新账号。
- 到达阈值或令牌被拒绝时能够刷新，一次流程最多刷新一次；刷新结果立即保存。
- 证书到期前按需续期，复用身份和私钥；失败保留旧证书与已经更新的令牌。
- 云端状态和证书状态独立，离线或 OAuth 失效不会自动清除仍有效的证书。
- 数据库迁移和退出登录保留 Matter 数据；损坏的持久化数据不会被静默重建。认证内容损坏时，登录与检查报错，`auth logout` 仍能显式清除该记录，再次登录可建立新记录。
- HTTP `401` 触发对应的认证错误处理；`403`、未知业务码和解析异常不会触发令牌失效判定，证书业务权限错误不会抹去已验证的云端认证结果。
- 令牌接口的内层 OAuth 错误码能够安全显示；未知或格式异常的详情保留外层业务码，不泄露原始错误文字，也不改变认证分类或覆盖已有凭据。
- 除登录所需的授权链接外，敏感认证信息不会出现在程序输出或错误日志中；认证检查不破坏网桥运行和退出行为。

中国区真实账号人工验收：

| 场景 | 通过条件 |
| --- | --- |
| 首次登录 | 完成 HA 应用授权、粘贴完整回调网址、云端读取、证书申请和保存；显示账号已认证及证书有效期。 |
| 独立检查与重启 | 无需再次浏览器授权即可验证账号和证书；已有 Apple Home 配对与虚拟灯控制正常。 |
| 令牌刷新 | 达到刷新时间后取得并保存新令牌，后续检查仍能访问云端。 |
| 证书续期 | 在隔离验证条件下触发续期，取得身份及公钥匹配的新证书并保存。 |
| 网络不可用 | 云端验证或续期失败时保留凭据，证书按本地实际有效期展示；网桥保持运行。 |
| 本地退出登录 | 本地账号令牌、私钥和证书被移除；再次启动显示未登录，原 Apple Home 配对保留。 |

本轮不以中枢 MQTT 连接或真实设备控制作为通过条件，也不将证书申请成功当作实机连接验证。

实现阶段同步更新 `docs/running.md`，说明认证命令、完整回调网址复制方法、数据目录、两类状态、刷新续期及退出登录行为，并在项目文档中注明参考来源。现有已完成的起步 spec 保持冻结。验收结果仅在任务对话中说明，不写入仓库。
