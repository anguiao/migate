# 验证最小设备模型

## 目标

建立协议无关的最小设备模型，并用一个真实米家设备验证：基础能力可以从标准设备描述中识别，无须为特定型号编写适配，就能完成命令下发、状态同步、错误处理和 Matter 桥接。

本轮通过小米中枢控制一个插座，并将其作为标准插座接入 Apple 家庭。插座是验证载体；交付重点是通用能力、状态同步和协议适配之间的边界。

网桥启动与设备接入的家庭范围限定为当前局域网中可发现并通过认证连接的中枢所对应的米家自有家庭。网桥的设备读取围绕该家庭进行；独立认证命令保留既有的少量云端设备访问验证。

| 验证设备信息 | 值 |
| --- | --- |
| DID | `571329355` |
| 型号 | `cuco.plug.v3` |
| 本轮固件版本 | `1.1.3` |
| MIoT 实例类型 | `urn:miot-spec-v2:device:outlet:0000A002:cuco-v3:2` |

本轮以该型号验证基础开关链路，其他型号的兼容性留待后续验证。运行入口暂时固定验证设备的 DID，下层根据 MIoT 描述识别能力。实现和文档不写入个人设备名称。

## 范围与方案

采用“标准能力解析 + 按需型号扩展”的方案：

- 通用模型描述身份、类别、能力、状态、可用性、命令和变化通知。
- 米家适配层从 MIoT 描述识别标准能力，并把通用命令转换为中枢请求。
- Matter 适配层把通用类别和能力映射为标准设备类型与簇，不读取米家属性编号或型号规则。
- 只有标准描述不足以表达真实行为时，才增加具体型号的修正或扩展；修正后的结果仍通过通用能力边界提供。

逐型号编写完整驱动会把基础功能重复实现；直接把全部 MIoT 属性暴露给 Matter，则无法保证设备语义和客户端支持。本轮只实现能通过实际流程验证的基础开关能力，不建立通用插件系统、空的扩展注册表或全量属性翻译框架。

本轮包括：

- 当前局域网中枢发现、对应米家家庭的设备目录读取和证书认证连接。
- 主电源的读取、开启、关闭、切换，以及主动状态通知。
- 中枢受理后的简单乐观更新、后续状态通知同步和断线恢复。
- 一个真实插座的 Matter 映射、身份与配对持久化，以及终端操作。
- 移除产品中的虚拟灯；以测试替身保留必要的协议和存储回归。
- macOS 本机自动化回归与 Apple 家庭真机验收。
- 更新 `docs/running.md` 和 README，说明 macOS 验证范围、默认目录启动、状态含义及虚拟灯移除后的行为。

功率、电量、指示灯、童锁等额外能力，其他设备类别的实际接入，多设备桥接、运行中增删设备、设备管理界面、远程家庭接入、其他米家服务区、共享设备、云端控制、设备直连协议和常驻服务安装不在本轮范围。

型号扩展将来可以修正描述、转换值或提供额外能力；额外能力只有具备标准 Matter 映射且客户端支持时，才能出现在家庭 App 中。本轮不得以验证设备型号或固定的 MIoT 实例编号代替标准能力解析。

## 运行方式

继续使用既有数据目录优先级：`--data-dir`、`MIGATE_DATA_DIR`、`~/.migate/`。仓库中的 Cargo 配置已把开发运行目录设为项目下的 `.migate/`，日常命令无需携带数据目录参数：

```sh
cargo run --locked -- auth login
cargo run --locked
```

直接运行构建产物仍遵循上述优先级，不读取 Cargo 配置。运行指南应明确这一区别，避免把不同目录误认为同一实例。

在程序入口组装真实设备时，使用临时常量 `VALIDATION_DEVICE_DID`，值为 `571329355`。它只承担本轮选定验证设备的作用，后续完善设备接入流程时删除；本轮无需设备选择配置、切换流程或额外的 DID 一致性校验。

具体 DID 仅在入口声明，下层通过普通设备标识接收它。通用模型、能力解析和 Matter 映射保持独立，主电源属性仍从 MIoT 描述中识别。

保留前台运行、Ctrl-C 正常退出和 stdin EOF 后继续提供桥接服务的行为。终端的 `on`、`off`、`status`、`help` 转为操作或展示该真实设备；终端与 Matter 使用相同的命令和状态边界。`status` 展示当前开关值、可用性，以及认证和中枢连接状态。当前值可能来自乐观更新，命令成功只表示中枢已受理，不能表述为实际动作已确认完成。终端输出继续使用英文。

## 模块与最小模型

保持单个 Cargo 包，优先使用普通结构体、枚举和直接调用。网络执行细节留在适配与运行模块内，不把 MQTT、MIoT、Matter 或 SQLite 类型传入通用模型。

| 单元 | 职责 | 依赖与边界 |
| --- | --- | --- |
| `device` | 定义设备描述、开关能力、命令、状态快照、可用性和变化通知，提供统一状态与命令入口。 | 不知道型号特例、SIID/PIID、Matter endpoint 或协议错误码。 |
| `xiaomi/cloud` | 读取自有家庭信息以关联本地中枢，处理匹配家庭的设备目录和详情。 | 复用既有 OAuth、HTTP 与分页边界；不决定 Matter 拓扑。 |
| `xiaomi` 的能力解析部分 | 读取 MIoT 描述，识别设备类别和主电源能力，生成通用描述及米家属性绑定。 | 属性编号和可能的型号修正在此收敛。 |
| `xiaomi` 的中枢部分 | 发现中枢，管理认证连接、请求应答、通知、超时和重连。 | 将中枢协议转换为通用操作结果和属性观测。 |
| `matter` | 生成标准插座拓扑，转发命令，映射属性、可达性和报告。 | 仅依赖通用设备边界与 Matter 存储。 |
| `storage` | 保存网桥与真实设备身份、静态能力缓存、账号凭据和协议数据。 | 封装 SQL 与持久化格式，不保存运行期设备状态。 |
| 运行入口与终端 | 组装上述单元，管理生命周期，呈现可理解的状态和错误。 | 不另存一份业务开关状态。 |

通用模型至少表达：

| 信息 | 语义 |
| --- | --- |
| 稳定设备键 | 由来源与来源内稳定标识组成；米家来源使用 DID。显示名称、地址、房间和中枢均不是设备身份。 |
| 类别与能力 | 本轮实际支持插座类别和基础开关能力；类别决定 Matter 设备类型，能力决定可执行操作。 |
| 当前开关状态 | 未知、开启或关闭；首次读取前为未知。中枢受理后可更新为目标值，后续属性通知或读取结果更新同一状态。 |
| 可用性 | 初始化中、可用或不可用，并带有可诊断的原因。 |
| 状态修订与通知 | 状态或可用性变化后递增修订并通知消费者；允许合并通知，但最新快照必须可读。 |

对外显示的开关值直接来自统一快照，不另设已确认值和待确认目标。不得为 Matter、终端和米家适配各维护一个可独立修改的开关副本。

设备命令包含开启、关闭和切换。同一设备的命令按接收顺序处理；切换在轮到该命令执行时，基于当前快照计算为绝对开关目标。状态未知时切换失败，不猜测初始值。可用设备重复设置同一目标仍允许成功，不制造额外的值变化通知。

## 设备发现与能力解析

### 家庭与中枢

以当前局域网的中枢发现结果确定设备接入的家庭范围，云端目录补充对应家庭和设备的信息，本地中枢负责控制及状态同步。沿用中国大陆服务区及现有 OAuth 配置，不要求安装或运行 Home Assistant。

独立 `auth login` 和 `auth check` 沿用既有认证流程，以少量云端设备读取验证访问，可能涉及其他自有家庭，但不据此建立桥接设备目录。独立认证命令不要求本地存在中枢，可用于提前登录和检查凭据。以下发现与目录范围约束适用于网桥启动和设备接入。

1. 在当前局域网发现 `_miot-central._tcp.local.` 服务。同一中枢在多个网卡上的公告去重；同家庭多个中枢不等于多个家庭。
2. 读取账号自有家庭信息，按上游规则计算家庭的 `group_id`，与本地发现的中枢关联。已有缓存的家庭信息可用于这一关联。
3. 在匹配到的本地家庭目录中查找验证设备，按接口游标处理分页，并只请求该家庭所需的设备详情和能力描述。云端接口可能一并返回其他家庭的记录，这些家庭的设备不进入本轮候选目录，也不继续加载其详情。
4. 连接设备所属家庭在本地发现的当前主中枢。复用已保存的客户端身份、私钥和证书，校验中枢证书的 CA 链、有效性及协议规定的身份条件。mDNS 公告用于确定本地候选，访问授权由认证连接确认。
5. 从该中枢获取设备访问能力，建立状态订阅并读取初始状态。主中枢变更只改变通信路由，不改变设备身份。

分页中的合法空列表或 `null` 列表、无效响应和无进展分页在云端协议边界处理。

当前局域网没有对应中枢时，按首次准备失败或运行期不可用处理；不尝试云端控制、远程家庭或缓存的远端地址。中枢模式不要求每个被桥接设备都拥有 IP 地址或设备 token；设备可用性由本地中枢访问能力和实际操作结果决定。

家庭分页、家庭与中枢分组、发现和连接协议参考小米官方的 [云端实现](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_cloud.py)、[mDNS 实现](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_mdns.py)及[客户端实现](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_client.py)。依据协议独立实现本轮所需链路。

### 基础开关能力

能力解析依据设备、服务和属性的 MIoT 语义类型，以及数据类型和访问权限。主电源必须是对应设备功能服务中的布尔 `on` 属性，并具备读取、写入和通知能力；不能通过属性名称恰好相同、编号较小或列表中的位置识别。

验证型号的[公开 MIoT 描述](https://miot-spec.org/miot-spec-v2/instance?type=urn:miot-spec-v2:device:outlet:0000A002:cuco-v3:2)同时包含主电源和指示灯开关。本轮应解析出主电源的 `siid=2`、`piid=1`，该结果用于验收解析器，不得成为实现中的固定路由。指示灯服务的布尔开关不能被误认为主电源。

目标设备需满足中枢的 MIoT 属性访问与推送条件，订阅成功且初始读取成功后才标记可用。在线标记、`specV2Access`、`pushAvailable` 和订阅应答本身不代表真实通知链路已经通过验收；实际变化的主动推送另行验证。[中枢请求与通知实现](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_mips.py)

必要语义缺失、类型或访问权限不符，以及存在无法消除的主电源歧义时，返回明确的能力不支持原因。不增加该型号的特殊分支来绕过本轮的通用解析验收。

## 命令与状态同步

采用小米官方开关实体的简单乐观更新方式：中枢受理后更新目标值，后续属性通知直接同步状态。参考[官方写入处理](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_client.py#L608-L638)和[实体状态更新](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_device.py#L1284-L1341)。

1. Matter 或终端提交通用命令，检查能力和可用性后，由米家适配层写入解析得到的主电源属性。提交命令本身不改变状态。
2. 中枢明确受理后，命令返回成功，并把统一快照更新为目标值；值发生变化时通知 Matter 和终端。受理依据写入应答的成功业务码（`0` 或 `1`），不能以 MQTT 发布完成代替。
3. 当前连接的合法属性通知直接更新同一快照，包括实体按键和米家 App 引起的变化。收到不同值时同步为该值，相同值不重复报告；不把通知关联为某条命令的确认。启动和连接恢复时主动读取状态。

乐观值会通过 Matter 属性向全部订阅者公开，也可能影响自动化。命令成功只表示中枢已受理；本轮不维护待确认目标、确认期限或自动回滚，也不在每次写入后安排定时读回。推送缺失时，当前值可能停留在乐观目标，直到后续通知或恢复读取更新；不承诺在固定时间内纠正，也不因未收到通知就判定设备离线。

米家适配层保留请求关联和会话隔离，丢弃已结束请求的迟到应答及旧连接消息。当前会话内的成功应答和属性通知按处理顺序更新状态，不推断设备事件的严格先后关系。

拒绝、超时和发送失败返回错误，不因失败更新或回滚开关值，也不自动重发结果不明的写请求。命令失败后仍接纳后续合法属性通知。连接中断、设备离线或必要推送能力失效时标记不可用；恢复后重新订阅和读取，再恢复可用。

请求与恢复采用统一时限，不增加用户可调参数：

| 等待 | 上限与行为 |
| --- | --- |
| 命令受理 | 从提交起最多 5 秒，包含串行等待及中枢应答；尚未发送且已超时的请求不得继续发送。 |
| 中枢读取 | 设备列表、初始读取和恢复读取每次最多 5 秒。 |
| 首次中枢发现 | 最多等待 30 秒；已接入设备的恢复发现则随退避流程持续进行。 |
| 临时断线重连 | 从 1 秒开始退避，逐次翻倍，上限 30 秒；连接稳定后重置。 |

变化通知只提示消费者重新读取统一快照。Matter 属性版本和订阅状态可以留在适配层内，但不得成为另一套开关状态来源。

## Matter 映射与虚拟灯移除

真实设备使用标准 On/Off Plug-in Unit 和 Bridged Node 语义，并提供所需标准簇。主电源映射到 On/Off 属性及 On、Off、Toggle 命令，可用性映射到桥接基本信息中的 Reachable。协议栈沿用 `rs-matter`。

所有启用的、能够改变开关值的 Matter 路径都必须经过统一设备命令边界。不能让协议栈默认 hook、场景恢复或灯具专用处理器直接修改本地值并绕过真实设备。仅声明所实现插座类型需要且正确支持的功能，不保留虚拟灯的灯具专用功能。

首次状态尚未知时，Reachable 为 false，开关属性读取返回错误，不伪造 `false`。当前不可用时，可以返回最近的内存快照，同时保持 Reachable 为 false；该快照可能包含乐观值，不代表设备此刻的实际状态。命令遇到不可用、超时、拒绝或不支持时返回相应失败，不转换为成功。

拓扑与身份遵循：

| Endpoint | 本轮用途 |
| --- | --- |
| `0` | 根端点。 |
| `1` | Aggregator。 |
| `2` | 本轮真实插座。 |

本轮按新实例设计，无需兼容虚拟灯时期的拓扑、存储格式或配对数据。

为真实插座生成并保存子设备标识，endpoint 固定为 `2`。网桥身份、真实设备身份和 Matter 配对数据持久化保存；正常重启、地址变化、中枢切换和暂时离线不影响身份与配对关系。

默认子设备标签由型号和 DID 生成，仅用于展示。客户端改名不影响寻址。本轮不做运行中设备增删。

删除产品代码中的虚拟灯状态源、固定虚拟灯常量和生产运行入口。协议、订阅、退出和持久化测试改用测试专用替身；替身不作为可配置的产品设备或失败时的替代设备出现。

## 启动、缓存、恢复与持久化

首次接入时，先发现本地中枢并关联家庭，再按入口传入的设备标识读取该家庭内的设备信息，完成能力解析、中枢订阅和初始读取，保存设备描述与身份并启动目标拓扑。首次准备失败时报告原因并退出。

已有设备描述缓存时，重启可据此构建同一 Matter 拓扑，先以状态未知、不可达提供服务。恢复控制仍需在当前局域网发现并认证连接对应中枢，完成订阅和读取；静态缓存不能代替本地发现。

具备同一账号的家庭与设备缓存、有效客户端证书，且本地中枢认证和设备访问成功时，云端暂时故障或明确要求重新登录均不阻止本地控制。云端要求重新登录时保留登录提示；云端认证状态不单独决定设备可用性，也不替代本地认证与访问检查。

静态描述按当前账号与设备键组织，保存家庭信息、型号、MIoT 实例类型、解析后的必要能力与属性映射。Matter 子设备身份单独按稳定设备键保存。缓存不保存“当前在线”“已认证”、运行期开关值或未完成请求。

联网取得新的设备描述时更新缓存；必要能力已不支持时报告不可用。本轮不在运行中重建拓扑。

网桥启动复用已有令牌刷新、证书检查和按需续期机制；设备读取使用处理后的凭据，并限于本地匹配家庭，不额外执行独立认证命令中未按本地家庭筛选的设备探测。认证检查的整体失败不作为阻断本地控制的条件，按上述本地条件判断。独立 `auth check` 仍按既有规则报告云端认证与证书检查结果及退出状态。

运行中不新增定时云端认证任务或跨进程凭据同步。独立认证命令更新凭据后，通过重启加载；令牌刷新或证书续期不改变设备身份。

运行期间发现中枢断线、设备离线或必要推送能力失效，更新可用性并结束相关未完成请求。中枢会话重建以当前局域网发现结果为入口，恢复订阅并读取属性后再恢复可用；不重放之前状态不明的写请求。实体按键与米家 App 的后续变化继续通过主动通知报告，不以持续轮询代替通知链路。

SQLite 保存账号凭据、网桥与真实设备身份、Matter 协议数据和静态能力缓存。网络请求不占用数据库事务；只在系统边界校验启动参数、协议内容和持久化数据，不层层增加兜底分支。

| 失败边界 | 行为 |
| --- | --- |
| 启动参数无效 | 沿用既有参数检查并报告错误。 |
| 登录或首次设备准备失败 | 给出对应原因及必要登录指引。 |
| 运行期网络、中枢或设备暂不可用 | 保留 Matter 拓扑、身份和配对；更新 Reachable，并按上述规则恢复。 |
| 云端暂时不可用或要求重新登录，而本地条件有效 | 记录云端问题，必要时提示登录；继续本地控制，不据此标记设备不可用或证书失效。 |
| 命令拒绝或结果不明 | 返回失败，后续状态通知仍正常处理；不重复执行状态不明的写入。 |
| 数据库初始化、读取或写入失败 | 保留原数据并停止服务，返回非零状态，不初始化一个新实例替代。 |
| Ctrl-C | 停止网络任务，取消未完成请求，完成正常退出；下次启动重新读取状态。 |

日志保留操作、DID、中枢连接阶段、请求关联信息和错误码，禁止记录令牌、认证头、私钥及完整原始账号响应。默认数据目录权限和凭据保护沿用现有实现。

## 验证要求

本轮在 macOS 本机完成自动化回归与 Apple 家庭真机验收。Linux 适配、多平台构建和部署不在本轮范围。

### 自动化回归

测试使用隔离目录、可控时钟和可控协议对端，不依赖个人账号、家庭网络或实际插座：

- **能力解析**：验证主电源与指示灯的区分；用不同型号标识、不同 SIID/PIID 的标准描述验证没有型号或编号硬编码；覆盖权限缺失和语义歧义。
- **目录与发现**：覆盖跨页目标、合法空列表、分页异常、多网卡重复公告、多个中枢及主节点变化；账号含多个家庭时，网桥启动的认证探测与设备接入只读取本地匹配家庭的设备，无本地中枢时缓存不能建立远程控制路径。
- **命令与状态**：覆盖受理成功后的乐观更新、通知覆盖当前值、同值不重复报告、拒绝和超时不改值、命令失败后的状态通知、连续命令及断线恢复；验证迟到应答和旧连接消息被隔离，不要求逐命令确认或固定期限内回滚。
- **中枢边界**：覆盖认证连接、请求关联、订阅、属性解码、拒绝和断线恢复；损坏数据只能在协议边界失败，不能变成有效开关状态。
- **认证与本地控制**：覆盖云端暂时不可用、刷新令牌被拒绝时，凭同一账号缓存和有效证书恢复本地控制；证书无效或中枢拒绝访问时不能恢复可用。独立认证检查仍如实返回失败；独立登录与检查保留原有少量设备读取，在无本地中枢时也能执行。
- **Matter 集成**：覆盖插座设备类型、命令转发、属性和 Reachable 报告、订阅保持及状态未知时的读取；生产与测试复用相同组装路径。
- **存储与进程**：覆盖新实例初始化、身份和配对持久化、正常退出及重启；系统 mDNS 检查使用现有 macOS 工具。

现有认证与 Matter 回归按本轮模型调整，保留认证、命令转发、状态报告、订阅和持久化等仍适用的行为覆盖。测试替身限于测试构建；普通检查不连接或控制实际设备。实现完成后在 macOS 执行 `cargo fmt --check`、`cargo test --locked` 和 `cargo clippy --locked --all-targets -- -D warnings`。

### 真机验收标准

在 Mac 保持唤醒、局域网正常的条件下，以表中的设备完成以下验收：

| 场景 | 通过标准 |
| --- | --- |
| 默认启动 | 使用默认开发数据目录启动，验证设备在家庭中显示为标准插座，虚拟灯已移除。 |
| 家庭范围 | 网桥启动与运行仅处理当前局域网中枢对应家庭的设备；账号中的其他家庭不被接入，本地中枢不可用时没有远程控制替代路径。 |
| 通用能力 | 真实基础开关流程不经过该型号的专用修正；解析结果与公开主电源描述一致。 |
| 家庭 App 控制 | 开启与关闭均改变真实设备；正常网络下，操作后 3 秒内家庭中的状态与实际状态一致。 |
| 外部变化 | 分别通过实体按键和米家 App 改变状态；家庭 App 保持打开且不手动刷新，3 秒内看到变化。 |
| 乐观更新 | 中枢受理后即可报告目标；后续收到不同的属性值时，家庭端随之更新。 |
| 连续操作 | 正常网络下快速交替开启与关闭，命令按接收顺序处理；操作结束并收到后续状态通知后，家庭中的状态与实际状态一致。 |
| 断线恢复 | 中枢或设备不可用时家庭端显示不可达；本地条件恢复后重新订阅、读取并恢复控制，不重复执行断线前的不确定命令。 |
| 同目录重启 | 新实例完成配对后，在同一数据目录重启，保持网桥和插座身份、配对关系；无需再次登录或配对，状态通过重新读取恢复。 |

无法在真机稳定制造的拒绝、超时、迟到应答和断线条件，由可控协议对端的自动化测试补充验证；真实控制、通知、配对及重启结果必须来自真机，不能由在线标记或订阅成功替代。3 秒状态同步标准适用于正常网络下的真实控制和外部变化，不代表逐命令确认期限或推送缺失时的纠正保证。任何时限或兼容性未达到标准时如实记录，不把理论推断当作验收完成。
