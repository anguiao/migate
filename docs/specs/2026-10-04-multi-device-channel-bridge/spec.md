# 多设备与多路插座桥接

## 目标与范围

将当前单个真实插座的桥接能力扩展到当前局域网所属米家家庭中的受支持插座，自动发现并接入，支持一台物理设备上的多路独立控制，以及 MiGate 运行期间的设备加入、删除和重新加入。

本轮合并 WiFi 与 BLE Mesh 插座接入。两者均通过当前局域网的小米主中枢完成属性读写和状态通知，不按通信类别分成两套控制实现。通信类别用于说明覆盖范围，实际接入依据家庭范围、设备能力及中枢访问条件。

采用“通用物理设备与功能模型 + 标准能力解析 + 必要型号修正 + 动态 Matter 拓扑”的方案。保留单个 Cargo 包，以普通结构体、枚举和明确的模块边界实现，不建立插件系统或全量 MIoT 属性翻译框架。

本轮包括：

- 移除入口的固定验证 DID，接入当前家庭中所有满足支持条件的插座，不设置三台设备的数量限制或 DID 白名单。
- 单路插座及 `cuco.plug.cp7pd` 的开关 1、开关 2、USB 独立控制。
- 首次接入导入米家名称，随后允许 Apple Home 独立命名。
- 多设备状态隔离、共享中枢连接、按通道串行命令和断线恢复。
- 自动加入、按家庭成员关系确认删除、同一设备重新加入时复用身份。
- 保留现有真实插座的 Matter 身份、配对、端点编号和名称，迁移已有运行数据。
- macOS 本机自动化检查及 Apple Home 真机验收；随实现更新 README 和 `docs/running.md`。

其他设备类别、功率与电量、指示灯、童锁、设备直连、云端控制、远程家庭接入、多家庭管理、每台设备独立选择中枢、管理界面和常驻服务安装不在本轮范围。Linux 支持与验收留待后续。本轮仍有标准插座功能符合性限制，详见 Matter 映射部分。

## 设备覆盖与验收取样

本轮设计覆盖以下五个型号。数量仅描述当前接入规模，不成为产品上限；型号内的其他设备也应自动加入。

| 型号 | 当前数量 | 通信类别 | 每台暴露的控制通道 | 完整真机验收 |
| --- | --- | --- | --- | --- |
| `cuco.plug.v3` | 4 | WiFi | 主电源，共 1 路 | 选 1 台 |
| `cuco.plug.cp7pd` | 2 | WiFi | 开关 1、开关 2、USB，共 3 路 | 选 1 台，覆盖全部 3 路 |
| `xiaomi.plug.04` | 1 | WiFi | 主电源，共 1 路 | 不单独操作验收 |
| `zimi.plug.zncz01` | 5 | BLE Mesh | 主电源，共 1 路 | 选 1 台 |
| `qmi.plug.psv3` | 2 | BLE Mesh | 主电源，共 1 路 | 不单独操作验收 |

当前规模为 14 台物理设备、18 路控制。全部纳入自动发现、能力解析、身份和初始状态读取检查；完整控制、通知和恢复验收只选三个代表型号。`xiaomi.plug.04` 和 `qmi.plug.psv3` 暂不方便操作，不要求独立完整真机验收；同一通信类别不等于已经证明全部型号的实际行为一致。

动态加入、删除和重新加入只选一台方便操作的设备完成一轮，不要求每台设备重新接入。真机验收的具体设备在执行时选择，不将个人设备名称写入仓库。

## 设备列表与家庭边界

统一使用以下术语：

| 名称 | 来源与用途 |
| --- | --- |
| 中枢设备列表 | 从局域网内的当前主中枢取得；用于发现候选设备、读取型号与访问标记、判断本地访问条件。 |
| 当前家庭设备列表 | 从米家云端读取当前家庭的完整成员关系，包括离线设备；用于限制接入范围、确认加入和删除。 |
| 运行数据 | 本地保存的账号凭据、静态设备信息、身份映射、名称和 Matter 配对等数据。 |

MiGate 定位为当前局域网内的固定网关，本轮不考虑切换网络，也不设计随网络迁移或自动切换家庭的行为。

延续上一阶段的范围：以当前局域网发现并通过认证连接的中枢，关联当前账号的一个米家自有家庭。先按本地发现的 `group_id` 确定家庭，再处理该家庭的设备。上游家庭接口即使返回账号下其他家庭的信息，也不能把其设备混入接入列表或继续加载其详情。

本轮以一个当前主中枢提供共享连接，不为每台设备保存或选择中枢路由。多网卡对同一中枢的发现去重；主中枢变更只更新连接，不改变设备身份、名称和 Matter endpoint。保持仍可用且仍声明为主中枢的现有连接；连接失败后，尝试同一家庭内其他已声明为主中枢且支持本地访问的候选，不等待旧主中枢的发现缓存过期。新主中枢出现时唤醒连接重试，连接成功后重建订阅并读取各通道状态。

家庭范围、账号与中枢关联属于米家适配层及其静态缓存。通用设备模型不携带家庭或中枢归属字段。只有与当前账号、当前家庭匹配的完整响应才能更新成员关系，其他家庭的响应不能用于删除已有设备。

独立 `auth login`、`auth check` 保留原有认证行为；其少量访问检查不决定网桥接入范围。当前家庭设备列表的周期同步可以按请求需要刷新令牌，不提供云端设备控制。

OAuth 协议边界将已保存的客户端 UUID 编码为无连字符的 32 位十六进制，使用 `ha.<32hex>` 作为设备标识；授权链接、`state` 计算与令牌交换使用同一值。存储 UUID、已有令牌刷新及本地中枢身份不因此迁移。

中枢设备列表中使用的 `name`、`model`、`urn`、`online`、`specV2Access`、`pushAvailable` 字段不包含通信类别；这只说明本轮使用的字段集，不断言整个中枢协议都无法提供通信类别。设备是否接入仍取决于可解析的功能以及实际中枢访问，不依赖 WiFi 或 BLE Mesh 标签。

## 通用模型与模块边界

| 单元 | 职责及边界 |
| --- | --- |
| `device` | 描述物理设备、功能、状态快照、可用性、命令和变化通知；不含 MIoT 属性编号、Matter endpoint 或家庭路由。 |
| `xiaomi/catalog` 与 `xiaomi/cloud` | 按当前家庭读取成员关系和设备信息，保留分页完整性与所属范围；向接入协调提供完整结果。 |
| `xiaomi/capability` | 解析 MIoT 语义，应用必要型号规则，形成稳定功能描述和属性绑定。 |
| `xiaomi/source` 与 `xiaomi/central` | 管理共享中枢会话、接入生命周期、按 DID 和属性绑定分发消息、订阅、读取及恢复。 |
| `matter` | 根据通用设备与功能生成端点、路由请求、报告属性及拓扑变化；不读取型号规则。 |
| `storage` | 保存静态描述、身份、端点和名称，迁移旧记录；网络操作不占用数据库事务。 |
| `runtime` 与终端 | 组装服务并管理任务生命周期，呈现设备列表和故障；不另存一份开关状态。 |

物理设备键继续由来源和来源内稳定标识组成，米家使用 DID。功能键由物理设备键和稳定功能标识组成：单路为 `main`，`cp7pd` 为 `outlet_1`、`outlet_2`、`usb`。名称、列表顺序、IP、主中枢和当前 SIID/PIID 都不是永久身份；SIID/PIID 是米家适配层的版本化绑定。

每个控制功能有独立的开关值、状态修订与命令队列。开关值为未知、开启或关闭；终端和 Matter 读取同一个快照。可用性按物理设备维护，各通道共享其连接与在线状态，不为每路增加独立的健康判断或故障恢复状态机。物理设备承载名称、功能集合和公共访问条件，多个通道的开关值保持独立。

`Function` 是独立类型，只能随 `PhysicalDevice` 创建；移除旧单设备 `Device`、隐式 `main` 构造和通道上的物理可用性写入口。MIoT 解析结果分别保存物理设备键与逐功能描述、绑定，不复用单设备描述表示两种层级。

`source` 按 DID 集中保存设备的候选描述、已接纳记录、准备任务和当前访问条件。候选只保存尚未接纳的更新，接纳后清空；当前绑定由命令消费者和会话任务共享。源任务与会话任务使用 `FuturesUnordered` 管理，分别由各自生命周期取消；不再叠加会话 generation 校验。令牌刷新以互斥状态表达，只由云端同步管理。中枢回调只按线序应用访问与属性观察，接纳和数据库事务由源任务执行，不进入传输驱动的同步回调。

共享会话并发关联不同设备或通道的请求，不因一条命令等待应答而阻塞全部其他通道。每个通道的命令按接收顺序执行；切换命令在实际执行时依据当前快照计算绝对目标，未知状态不能执行切换。

## 能力识别与多路插座

单路插座继续按 MIoT 的设备、服务和属性语义识别主电源，要求布尔值及读取、写入、通知权限。不得仅凭属性名称、编号或排列位置识别开关；指示灯、提示音等布尔属性不成为控制通道。具有明确单路标准插座语义的设备可走通用解析；无法消除歧义的设备保持未接入并说明原因。

候选设备必须属于当前家庭，功能描述可解析，且已从中枢确认具备 `specV2Access`、`pushAvailable`。这些信息足以建立完整拓扑；订阅和初始读取随后进行，不以全部通道首读成功作为接入门槛。中枢标记只说明支持条件，实际读写和状态推送仍需独立验收。

解析器需支持本轮型号使用的合法 MIoT 实例 URN 后缀，不因部分实例多一个合法字段而拒绝。本轮应覆盖 `qmi-psv3:1:0000C816`、`zimi-zncz01:2:0000C816`、`xiaomi-04:1:0000D032` 这些实例类型的尾部结构。语法与类型校验集中在描述解析边界，不能简单接收任意后缀或把全部厂商扩展当成标准语义。

以下属性编号是本轮描述解析的预期结果，用于测试和必要型号规则，不替代单路标准能力解析：

| 型号或功能 | SIID / PIID | 处理 |
| --- | --- | --- |
| 四种单路型号的主电源 | `2 / 1` | 从标准开关语义解析为 `main`。 |
| `cp7pd` 总控 | `2 / 1` | 仅在适配层内部观察，不暴露为 Apple Home 控制。 |
| `cp7pd` 开关 1 | `3 / 1` | 映射为 `outlet_1`。 |
| `cp7pd` 开关 2 | `4 / 1` | 映射为 `outlet_2`。 |
| `cp7pd` USB | `9 / 1` | 映射为 `usb`。 |

`cp7pd` 的开关 1、开关 2 使用厂商自定义语义，不能仅靠标准类型扫描可靠地区分总控与独立通道。为该型号的已支持描述增加小范围显式映射，校验对应语义、类型和访问权限后生成三个通用功能，不增加独立的设备驱动体系。

总控虽不暴露给 Matter，仍订阅其变化。收到总控通知时，触发三个子通道的实际状态读取；不能推断总控开启或关闭就代表三路分别处于同一状态。读取结果分别更新通道。事件触发的读取不是周期状态轮询，也不把总控本身作为用户命令入口。

必要属性缺失或新描述不兼容时，只影响相关设备并报告原因。已有端点不得因型号、固件或描述变化而悄悄改成另一种功能；保留身份记录，已有设备保持不可用，新接入或重加则暂不发布不兼容拓扑。

## 命令、状态与可用性

参考小米上游的 [属性实体处理](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_device.py)与[客户端路由](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_client.py)，将设备可用性、当前属性值和单次操作结果分开处理：

1. 向指定通道写入属性，中枢返回成功码 `0` 或 `1` 后更新本地值；后续属性通知或读取结果直接更新同一快照。这保留简单乐观更新，成功表示中枢受理，不另设动作确认、回滚或写后校验流程。
2. 单次读写失败向调用方报错或记录本次刷新失败，保留已有值；尚未取得值则仍为未知。一次失败不把设备或通道判为离线，也不触发整个设备重新接入。写入失败不自动重发。
3. 设备可用性由共享中枢连接、设备在线状态及本地访问能力决定。中枢断连影响其下设备，设备离线只影响该设备；通道是否已读到值不参与在线判断。推送能力与订阅状态由适配层管理，单次订阅失败不额外创建通道离线状态。

加入和恢复时异步建立订阅并刷新属性。属性刷新采用上游本地路径的会话级轮次：首次等待 200 毫秒，每轮每台设备取一个待读属性，不同设备并发；等待本轮全部请求完成后，再间隔 200 毫秒开始下一轮。按设备和属性合并待发请求；在途属性再次收到触发时最多安排一次补读，尚未发送的属性不重复排队，连续触发不延后已安排的轮次。每次刷新读取超时为 6 秒，观察结果仍按中枢消息线序提交。

失败属性单独保留，最多追加 3 次、每次失败后至少间隔 3 秒；新的触发不跳过其退避。耗尽后保留原值或未知，等待后续通知或下次加入、上线、连接恢复事件。这里保留 MiGate 的逐属性重试，不采用上游“同轮任意设备成功就结束其他失败项重试”的处理。此刷新也供多路总控事件使用，不建立持续状态轮询；设备删除取消其待发和在途请求，会话结束取消整轮及所有等待。

属性通知订阅参考上游本地 MIPS 的有界策略：首次调度等待 10 毫秒；首次尝试失败后最多追加 3 次，每次失败后间隔 0.1 秒再试。只重试失败项，保留已成功的订阅，不因单台设备的订阅失败重建共享连接。耗尽后记录问题并停止本轮重试，等待设备加入、上线、共享连接恢复或该设备后续中枢列表同步时重新尝试；不增加永久重试循环或属性轮询。断连时结束本次会话的待重试工作，新连接为仍接入的设备重建所需订阅；移除设备时取消其待重试项，后续同步不能恢复已删除设备的订阅。

上游的成功判据是 Paho `subscribe()` 提交成功，不等于中枢已确认订阅。MiGate 保留现有 MQTT `SUBACK` 校验，以成功应答确认订阅建立，将提交失败、拒绝和请求超时纳入上述有界策略；这是对现有协议边界的适配，不额外引入通道健康状态。连接本身失效时转入共享连接恢复。订阅失败或重试耗尽不改变已定的物理设备可用性，也不保证期间外部状态变化能够同步。

中枢直接读写与设备列表请求采用[上游 MIPS 接口](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/miot_mips.py)默认的 10 秒请求超时；批次属性刷新单独使用上述 6 秒，由同一网络请求层处理。取消原有“排队与应答合计最多 5 秒”的业务总期限；按通道排队和调用者取消使用既有任务生命周期，不再叠加另一套超时、撤回或补偿机制。业务超时本身不重连，写请求不自动重放。本地传输重连采用上游本地客户端的 6、12、24、48、60 秒退避，之后保持 60 秒；连接成功即重置。同一家庭的新主中枢候选出现时仍立即唤醒等待，不改变云端同步自身的退避。

消息按 DID 与属性绑定分发，复用现有会话和请求关联。设备移除时注销订阅并结束其任务，不要求新增设备接入代次协议或为每个状态更新增加重复校验；旧任务不能重新注册已移除设备，重新加入由设备列表同步负责。

消息内容与共享传输分别处理：已经完整接收的 MQTT 帧中，MIPS 内容损坏、属性类型错误或身份不匹配只丢弃该条消息并记录诊断，不断开其他设备共用的连接。MIPS 解包成功后，已关联请求的业务字段解析失败只结束对应请求；解包失败的应答等待原有请求超时。MQTT 帧、确认交换或 TLS 连接本身失效时才进入共享连接恢复。

## Matter 拓扑与运行中更新

采用按物理设备组织的复合端点方案，使多路通道共享明确的物理设备身份：

| 设备 | Matter 表达 |
| --- | --- |
| 单路插座 | 同一 endpoint 同时承载 Bridged Node 与 On/Off Plug-in Unit。 |
| `cp7pd` | 一个 Bridged Node 父 endpoint 表示物理设备，三个 On/Off Plug-in Unit 子 endpoint 分别表示开关 1、开关 2、USB。父 endpoint 不提供总控开关。 |

根 endpoint `0` 和 Aggregator endpoint `1` 保留。现有单路插座保留 endpoint `2` 及原 UniqueID，不额外套父节点。按当前设备数量完整接入时，共有 22 个 endpoint，包括根、Aggregator、12 个单路插座、2 个多路父节点及 6 个功能子节点；22 不是容量上限。

每个功能的开关命令都通过统一命令边界。不得让协议栈默认处理器、场景恢复等路径直接修改本地值而绕过真实设备。

单路设备与多路父节点的 Reachable 均映射物理设备可用性，不附加“已取得开关值”或“至少一路读取成功”的条件。首次读取前开关值未知，Matter 属性读取返回错误，不伪造关闭；设备在线时仍可执行明确的 On、Off，Toggle 需要已有值。离线后可以返回最近的内存值，但它不代表当前真实状态。

复合父节点的 Descriptor `PartsList` 列出三个子 endpoint，三个功能使用稳定且互相区分的 semantic tag，声明 Descriptor 的 TagList 特性并提供通道标签。根与 Aggregator 按协议栈的层次规则声明完整拓扑。以 `rs-matter 0.4.1` 的动态元数据接口建立可变端点注册和处理器路由，保持 endpoint 排序要求，替换固定单设备处理链；不把当前样本数量作为固定容器容量。

同一 endpoint 存续期间不热改其 cluster、属性或命令集合。运行中以一台物理设备为单位增加或删除完整端点集合：多路父节点与三个子节点一次可见，不能短暂发布半台设备。先持久化身份及发布状态，再切换有效拓扑，并通知受影响 endpoint 与仍存在的 root、Aggregator、父节点 Descriptor 属性变化，正确递增 DataVersion、触发报告。

Aggregator 随根处理链固定存在，动态端点只区分单路设备、多路父节点和子通道。各角色使用 rs-matter 原生处理链组合所需簇，不另存启动标记或分发没有处理逻辑的生命周期调用。

动态处理器必须覆盖新加入端点的后台通知任务，并在删除时结束关联任务。异步请求持有有效的功能引用，不跨网络等待占用整个注册表；切换后不再接收已删除端点的新命令。

设备删除不清空全部 Matter 配对或订阅。旧订阅访问具体已删除路径时按协议返回 `UnsupportedEndpoint`，通配路径反映现有端点，其余设备继续报告。存储恢复需覆盖“某个已订阅端点已被删除”的情况。

Apple Home 需能发现并独立控制各路，实际卡片数量、分组、顺序与标签呈现以真机表现为准，不预先承诺固定 UI 布局。

继续声明 On/Off Plug-in Unit（`0x010A`，revision 3），保留上一阶段基础开关与相关通用簇行为。当前缺少标准插座要求的 Lighting、计时关闭、全局场景及 Scenes Management，存在已知符合性限制；基础互操作验收通过不等于完整标准符合性。如这些缺项阻碍本轮基础控制，应明确定位并在本轮范围内修复必要部分，不宣称已经通过 Matter 认证。

## 名称、身份与存储迁移

新设备首次接入时采用米家的设备名称，并持久化该初始名称。单路以此作为设备标签；多路父节点采用设备名称，功能分别提供“开关 1”“开关 2”“USB”等明确标签，并在终端展示设备名称与功能标签的组合。通道标签的协议映射不能通过增加虚假的 Bridged Node 改变已选拓扑。

之后米家改名不覆盖已保存名称，Apple Home 可独立改名。控制器写回 NodeLabel 时持久化物理设备名称；通道标签随首次接纳保存，在当前协议映射中只读。仅保存在 Apple Home 内的名称由控制器管理。现有 NodeLabel 的 32 字节约束继续在协议边界校验，导入时按 UTF-8 字符边界截断；缺少有效米家名称时使用原有型号与 DID 生成规则。

首次接纳和启动恢复均从已提交的身份记录构造运行描述，在存储边界统一校验功能兼容性并应用已保存名称。物理设备运行名称只有一份共享值，Matter 写入持久化成功后更新，终端直接读取；不另外维护处理器名称副本，也不在每次展示设备时重新联表。

设备缓存只通过完整发布事务写入，不保留绕过身份发布的独立缓存写入口。初始化、迁移后的表结构校验共用建表 SQL，避免另行维护一份列定义；迁移失败仍回滚并保留已有数据。

当前已接入插座显示型号与 DID，是因为旧实现没有导入米家名称。本轮对它保留现有名称和配对：有已保存 NodeLabel 时迁移该值；没有时按旧规则计算当前默认值并固化。不会在升级时自动把已有名称替换成米家名称。

持久化分别保存：

- 米家适配缓存：账号与当前家庭范围、型号、MIoT 实例、功能描述和属性绑定。
- 稳定身份：物理设备键、功能键、UniqueID、endpoint、已分配编号及接入状态。
- 名称：首次导入或后来写入的设备、功能标签。
- 既有网桥身份、Matter 配对与订阅数据、账号凭据及证书。

不保存当前在线状态、运行期开关值和未完成请求。设备删除时撤下有效拓扑，保留身份、端点及名称记录。同一 DID 与同一功能重新接入时复用原记录；这些 endpoint 永不分配给其他设备或功能。正常重启、改名、换房间、IP 或主中枢变化均不重新分配身份。编号耗尽时明确拒绝新增并保持已有设备工作。

从当前存储版本迁移时，将单功能静态缓存扩展为物理设备及功能记录，将单个标签存储键迁移到现有设备的名称记录，保留 endpoint `2`、UniqueID、网桥身份、配对与其他 Matter 数据。迁移使用事务，失败时报告错误，不清空运行数据或创建替代身份。

## 自动加入、删除与重新加入

启动、主中枢重连和中枢设备列表变化通知触发同步；每 5 分钟同步一次当前家庭设备列表，补偿遗漏的变化通知。家庭成员新增时补取中枢设备信息和必要描述。此周期只用于设备成员关系同步，不轮询各路电源状态。

同步必须完成当前家庭的全部分页。失败、部分页、游标无进展或所属范围错误的响应不能被当成一个空列表，不能据此删除设备。多个触发合并执行，旧账号、旧家庭或已失效同步任务的响应不能覆盖当前结果。

分页进度以 `has_more` 和游标为准，允许重复成员或空中间页；不要求每页必须增加新的 DID。账号与家庭由单一云端同步任务管理，中枢连接变化不使同一账号和家庭的完整云端结果失效。

中枢设备列表由当前会话持有一个刷新任务。连接后首次全量请求等待 3 秒，失败后再等 3 秒重试；等待期间合并重复全量触发且不延后原期限。设备变化通知保留其 DID 集合，在没有列表请求执行时立即过滤查询；已有请求执行期间合并新的 DID，随后处理。过滤响应只更新请求范围，不能将其他设备判为缺失；过滤查询失败保留已有访问状态，不自动重试。到期的全量请求可覆盖尚未发送的过滤查询。相比上游独立并发处理变化通知，MiGate 保留一个列表请求执行者，避免重复查询及不同范围响应乱序覆盖。

完整云端家庭同步只在成员集合实际变化时补充请求中枢全量列表；相同成员的周期同步、变化通知触发的云端同步不会额外查询全量列表。会话结束时取消全部列表请求与等待，云端目录故障独立保留和恢复。

| 变化 | MiGate 行为 |
| --- | --- |
| 当前家庭新增受支持插座 | 确认家庭范围、支持条件和完整功能描述后，一次发布该设备的全部端点；随后建立订阅并异步读取各通道状态。读取未完成的通道显示未知，不阻止设备加入。 |
| 首次加入缺少必要描述或中枢能力信息 | 保留待接入原因，后续列表同步时继续准备；不因一台候选失败阻止其他设备接入。完整功能描述到齐后才发布，避免缺少某路端点。 |
| 中枢列表暂时没有已有设备，或设备离线 | 保留拓扑和身份，报告不可用并等待恢复。 |
| 完整当前家庭设备列表确认已有设备不再属于该家庭 | 自动撤下该物理设备及所有子功能，结束相关任务和请求，持久保留身份记录。 |
| 同一设备重新回到当前家庭 | 重新确认家庭范围和功能描述，复用原物理和功能身份、endpoint 与名称发布拓扑，再建立订阅并刷新属性。 |

“删除”指设备从当前米家家庭移除或转入其他米家家庭；无需查询它去了哪个家庭。修改房间、改名、断电、断网以及中枢遗漏记录都不构成删除依据。自动处理只影响 MiGate 的桥接表达，不主动删除或修改米家侧设备。

同一设备重加时保证 MiGate 身份复用，不保证 Apple Home 自动恢复删除前的房间、场景或自动化。新增或删除应在下一次成功的触发同步或周期同步后反映到 Matter；云端失败期间不承诺这一收敛时间。

## 启动、恢复与终端

沿用账号登录、证书准备、运行数据位置优先级及进程独占规则，保持前台运行、正常退出与 stdin EOF 后继续服务的行为。启动参数和运行数据损坏仍明确报错；未登录时保留必要登录指引。

已有有效静态记录时，先恢复相同的有效 Matter 拓扑，各通道开关值从未知开始；本地连接建立前设备不可用，连接与设备在线状态恢复后即可恢复可用性，订阅与属性刷新异步进行。已经确认删除的记录只用于保留身份，不在重启时重新暴露。

已经完成账号准备但没有可接入插座时，允许网桥仅以 root 和 Aggregator 运行，等待发现与接入，不以第一台设备失败作为整个网桥退出条件。首次发现的 30 秒等待窗口结束后展示当前原因，并继续按退避机制发现；家庭范围确定前不发布子设备。

具备同一账号与家庭的静态缓存、有效证书，且本地认证与访问成功时，云端暂时故障或要求重新登录不阻止已有本地控制。暂时失败按恢复机制重试；明确要求重新登录时显示提示，暂停需要该凭据的设备列表同步，按现有独立认证流程重新登录后重启加载。不会因认证错误将已有设备当成已移除。

终端统一操作同一通用状态与命令入口，输出继续使用英文，设备名称原样显示：

| 命令 | 行为 |
| --- | --- |
| `list` | 列出已接入和待接入设备、DID、名称、通道键及状态或原因。 |
| `status [DID]` | 展示全部或指定设备的通道快照，并显示账号及中枢连接状态。 |
| `on DID [channel]`、`off DID [channel]` | 操作指定设备与通道；单路可省略 `channel`，多路必须提供。 |
| `help` | 展示命令与稳定通道键的使用方式。 |

多设备情况下不再把无目标的 `on`、`off` 隐式发给某一台设备；缺少目标、通道不明确或不存在时返回用法提示，不产生写入。操作受理仍显示为 accepted，不声称真实动作已经确认完成。

## 验证计划

不能把能力描述、在线标记或订阅成功当作真实控制和通知已经通过。

### 自动化检查

普通检查使用临时运行数据和可控协议对端，不访问个人账号或操作真实插座：

```sh
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

围绕本轮改变的边界补充以下行为验证，并保留认证、进程生命周期和 Matter 存储回归：

- 五个型号的描述解析、合法实例 URN 后缀、指示灯排除及 `cp7pd` 的三路映射；总控事件读取实际通道值。
- 多台同型号与多路设备的寻址、状态隔离、每通道顺序和跨通道并发；复用既有取消、请求超时与会话回归，不新增分层超时机制。
- 设备在线但通道值未知时可执行 On、Off；一次读写失败不改变在线状态，首读失败不阻止完整拓扑加入，属性刷新重试有界。
- 属性订阅提交失败、拒绝和超时的有界重试、耗尽后停止及后续事件恢复；成功项与其他设备不受影响，断连或设备删除取消待重试项，重连只重建仍需的订阅。
- 当前家庭过滤、完整分页、其他家庭隔离；部分列表和云端故障不删除，临时离线不改变拓扑。
- 分页重复成员及空中间页不造成误拒绝；中枢列表失败自动恢复，断连取消待重试任务；坏设备消息不影响其他设备的有效通知和请求。
- 官方请求调度：全量列表首次及失败后固定 3 秒、变化通知按 DID 过滤且不影响其他设备、重复触发合并；每轮每设备一个属性、跨设备并发、整轮完成后 200 毫秒间隔、刷新专用 6 秒超时；触发不跳过失败退避，删除与断连取消待发工作；本地重连 6 至 60 秒并在成功时重置。
- 空网桥后加入、多路端点原子发布、运行中增删、同 DID 重加、陈旧任务不恢复已删除设备、能力不兼容不改写原端点。
- Descriptor 层次、semantic tag、DataVersion 与订阅报告；删除后带旧订阅重启，其他设备继续控制和报告。
- 旧存储事务迁移、endpoint `2` 与原 UniqueID/标签/配对保留、首次米家命名、多设备名称隔离及 UTF-8 限长。
- 重启恢复有效拓扑，删除记录不重新暴露，历史 endpoint 不被其他设备占用；设备数量不受当前样本数限制。

### macOS 与 Apple Home 真机验收

| 项目 | 覆盖及标准 |
| --- | --- |
| 全量自动接入 | 当前家庭内五个型号的插座全部进入相应准备流程；在本地条件正常时完成身份检查和初始读取。以当前规模检查 14 台物理设备、18 路控制，没有总控或指示灯误暴露。只读检查不主动切换未选中的设备。 |
| 三个代表型号 | `cuco.plug.v3`、`cuco.plug.cp7pd`、`zimi.plug.zncz01` 各选一台；多路代表覆盖开关 1、开关 2、USB。 |
| 独立控制 | 通过 Apple Home 对每个代表通道完成 3 轮开启与关闭，核对真实状态；操作一台或一路不改变其他独立通道。正常网络下，操作后 3 秒内 Apple Home 状态与实际状态一致。 |
| 外部变化同步 | 每个代表通道完成 1 轮外部关闭与开启，选用实体按键或米家 App 作为操作来源，不要求重复两条路径。多路设备可通过实际提供的总控触发各路变化；Apple Home 保持打开、不手动刷新，正常网络下 3 秒内反映变化。没有独立实体按键的通道不要求不存在的操作入口。 |
| 多路总控变化 | 通过米家或实体总控改变多路设备，检查三个通道最终反映实际读取值；Apple Home 不出现总控作为第四路。 |
| 名称 | 新接入设备提供米家初始名称与可区分的通道标签；Apple Home 改名后重启不被米家名称覆盖。已有设备升级不重置名称。实际卡片与分组按客户端表现记录。 |
| 保留运行数据后重启 | 停止并重新启动 MiGate，共 3 轮；复用现有运行数据，保持网桥与设备身份、端点、名称及配对，无需再次登录或配对，开关值通过读取恢复。 |
| 断线恢复 | 以三个代表设备观察断线及恢复，共 3 轮；中枢断线可同时覆盖三台，设备侧断线选择方便操作的代表。多中枢环境至少一轮只断开当前主中枢，其他中枢保持运行，确认 MiGate 自动连接新主中枢、恢复控制与通知，设备身份、端点、名称及配对保持不变；再恢复原中枢供电，检查连接稳定，不要求切回原中枢。Mac 断网不能替代主中枢切换验收。恢复后不重放不确定写入；恢复及重启后 Apple Home 最长观察 20 分钟。 |
| 动态加入、删除、重新加入 | 只用一台方便操作的设备完成 1 轮：MiGate 持续运行，设备加入当前米家家庭后自动出现，移出后经完整列表确认自动撤下，同 DID 重加复用身份和 endpoint。检查其他设备继续工作，无需重新配对整个网桥。 |

动态变化需考虑每 5 分钟一次的家庭成员同步，不能套用 3 秒电源状态同步标准；需区分 MiGate 已更新拓扑与 Apple Home 已呈现变化。Apple Home 的拓扑变化从 MiGate 提交相应拓扑更新起，最长观察 20 分钟；断线恢复从本地通信条件恢复起计时，重启从 MiGate 重新提供 Matter 服务起计时。未恢复或未呈现则如实报告未通过，不通过重置配对掩盖问题。

3 秒是正常网络下的人工状态同步验收标准，不是逐命令确认机制或推送丢失后的纠正保证。20 分钟是客户端恢复的最大观察窗口，不是目标延迟。无法稳定制造的异常由可控对端验证补足；未独立完成控制、通知及恢复验收的两个型号，须在对话中的结论明确注明，不宣称全部型号已完整真机验证。
