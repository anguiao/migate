# 单灯照明控制

## 目标与范围

在现有米家设备桥接能力上增加单灯接入，在 Apple Home 中提供开关、亮度、色温，以及设备支持时的彩色控制。支持这些能力对应的目标设置、渐变、连续调整、步进和停止，并同步米家 App、实体操作产生的状态变化。

本轮完成条件是上述单灯功能及 Apple Home 互操作验收，不要求完整 Matter 灯型符合性。沿用现有插座的边界：明确记录标准缺项，实际声明支持的操作必须生效，未支持操作不能假报成功；若缺项阻碍已约定功能，再针对性补齐。

每盏灯保持一个功能和一个控制端点。色温和彩色属于同一灯具：用户直接选择目标，MiGate 自动完成必要的模式切换，不增加独立的白光／彩光开关，也不拆成两个灯。

本轮覆盖下表七个既有单灯型号。设备准入、稳定身份、动态加入与删除、单家庭绑定、本地优先及云端接管，延续[云端接入与统一选路](../2026-10-06-cloud-access-routing/spec.md)。运行范围继续为 macOS / Apple Silicon，保持 Rust 单包结构。

不包含米家灯组、墙壁开关、无线按键、开关负载类型映射、多按键拆分、浴霸等复合设备，也不增加厂商场景、音乐律动、彩色循环或 Apple 自适应照明。开关的负载类型映射和按键拆分保留为独立需求，不为它们预建配置框架。

### `devcea.light.ls2307` 彩色能力适配

`devcea.light.ls2307` 的标准灯服务提供开关、亮度和色温，另一个服务提供颜色及白光／彩光状态：

| 绑定 | 作用 |
| --- | --- |
| `2.1` | 开关 |
| `2.2` | 亮度 |
| `2.3` | 色温 |
| `4.1` | `0xRRGGBB` 颜色 |
| `4.2` | 当前白光／彩光状态，0 为白光、1 为彩光 |

这些属性归入同一个 `main` 功能。`2.4` 的厂商场景枚举不作为白光／彩光状态的替代品，也不暴露为本轮功能。

设置色温时完成白光目标和必要的模式切换；设置颜色时完成彩光目标和必要的模式切换。只改变亮度时保持当前模式。模式与目标值组成一次逻辑操作，按各属性的实际受理结果更新状态，不能因其中一项成功就宣称整次操作成功。

描述能够确认属性存在及其声明含义，尚不能证明固件的自动切换行为、写入先后要求及彩光下的亮度耦合。适配必须验证色温和彩色双向切换、亮度控制及外部模式同步；这些是交付要求，不能以字段解析成功替代，也不能静默降级成只支持色温。

| `xiaomi/central`、`xiaomi/cloud` | 将既有布尔属性读写扩展为受支持的数值属性传输，继续负责各自协议封装与响应关联。 |
| `matter` | 按灯具能力组成端点；复用上游灯光控制器处理本轮支持的目标设置、渐变、连续调整、步进和停止，将状态与操作连接到通用设备接口。 |
| `storage` | 保存恢复灯具所需的静态描述与转换绑定，延续身份、端点、名称和配对存储。 |

控制请求经 Matter 控制器转换成通用设备操作，再由米家适配层在实际发送前选路。回执、读取及通知经适配层判断有效性后更新同一份快照，快照变化同步到 Matter 读属性、订阅报告及后续命令计算状态。

不按本地／云端复制灯具状态或控制器。现有插座继续使用原来的命令顺序和行为，不把照明的连续目标合并规则扩展到插座开关。

### 复用控制器的边界

采用“统一设备快照作为状态依据，复用 Matter 控制器并补充必要接入点”的方案，不重写一套完整灯光状态机，也不更换协议栈。

颜色属性可以从统一快照读取。仅包装读取接口仍不足以完成同步：上游控制器用于 Step、渐变起点及模式判断的内部状态，也必须收到已接受的外部变化。当前 `rs-matter 0.4.1` 的颜色控制器主要使用内部状态，同步设备 hook 也不能直接表达网络异步受理，因此需要针对状态同步、异步下发结果和动作取消补充接入点。

这些调整限于本轮灯光控制所需的接口与行为，并通过相关测试约束。不能通过仅重写 getter、向同步 hook 投递队列后立即成功，或借用场景恢复接口注入普通属性变化，掩盖内部状态和实际设备的不一致。

上游内部状态是计算用投影，不是第二份独立权威状态。控制器可以保存活动目标和过渡进度，但不能在设备尚未受理时，把理论插值或目标终点当作已知设备状态。

## 状态与数值语义

一个灯具快照包含开关、亮度、色温、颜色、当前生效模式、可用性及统一修订号。静态能力和物理范围属于描述，不与运行状态混合。各状态支持未知值；缺少读数不能用固定亮度、默认白光或虚构颜色补齐。

仅支持色温的灯具，其有效模式由能力确定为色温。双模式灯的色温值和彩色值可以同时保留，当前模式决定哪组值用于描述发光。非当前模式的数值通知只更新该值，不自动解释为模式切换；外部模式变化按实际模式属性同步，不能依据通知先后猜测。模式已知但对应颜色或色温未知时，继续保留未知并合并必要补读。

| 数值 | 转换规则 |
| --- | --- |
| 亮度 | 使用统一百分比语义并保留精度，按双方有效非零区间线性换算，落到设备声明的步长；避免先转成整数百分比再换算造成精度损失。零值与开关的关系由命令语义决定，不能把所有零亮度都写成超出设备范围的数值。 |
| 色温 | 通用设备使用 Kelvin，Matter 使用 mireds，以 `1,000,000 / Kelvin` 换算；边界及舍入必须与物理量程一致，反向写入也限定在设备范围和步长内。 |
| 颜色 | 米家适配层处理 `0xRRGGBB` 编解码；Matter XY 与 RGB 的转换采用一致的颜色转换实现。亮度与色度分开处理，不能在转换时重复叠乘亮度。超出可表达颜色的目标进行确定性映射，不承诺校准后的精确色度。 |

外部值在协议边界检查类型、有限数值、范围和步长。非法值不更新快照。Matter 命令参数遵循其规范的校验与裁剪规则，不以静默兜底掩盖无效输入。

### 属性观察顺序

将米家适配层原有按功能维护的观察计数细化到涉及的属性，继续保留设备、绑定及通知来源代次。亮度的新通知只使相关旧结果失效，不应使无关色温读取失效；颜色与模式在同次多属性操作中的关联仍需保留。

同一报告或读取结果中的有效属性共同更新一次功能快照。不同报告可以独立更新，不等待所有灯光属性凑齐后才发布。收到新模式或新属性时，同时校正控制器计算所需的状态；普通写入回声不应被当成新的用户操作反复触发控制。

指令按先后顺序接管，操作来自哪个客户端不参与优先级判断。指令与状态反馈必须区分：渐变步骤的写入回声、回执、普通补读及云端缓存即使较晚到达，也不构成新指令；仅同值通知不能证明发生了新操作。

MiGate 直接收到的有效指令按接收顺序处理。米家 App 或实体操作只能通过设备状态通知观察，排除旧工作及可关联的写入反馈后，相关变化按观察到达顺序参与接管。现有通知缺少可用于完整还原原始发令先后的信息，因此不能把状态通知的到达顺序承诺为各客户端真实发令时间的全局顺序。

迟到读取不能覆盖读取发起后的相关有效通知或成功写入。写入发送后已有相关有效通知时，迟到成功回执仍结束原请求，但不把旧目标覆盖回快照；没有更新观察时，保留现有受理后的乐观更新。快照变化不等于光学测量确认。

通知来源切换继续等待新来源必要订阅就绪；控制可用而通知不足时报告同步受限。云端缓存及跨来源事件仍受既有协议限制，不新增无法获得的全局事件时间顺序保证。

## 连续控制与操作结果

### 目标、渐变与合并

支持直接目标设置、指定时长的渐变、Move 持续调整、Step 步进以及对应 Stop。带时长的动作复用控制器计算，不为每个能力另造计时框架。

Matter 的亮度、色温及 XY 目标命令提供 `TransitionTime` 参数，渐变按实际收到的命令及其参数语义执行。米家 App 或实体操作的状态通知本身不触发新渐变。协议支持指定时长不等于 Apple Home 提供相应时长设置入口，也不证明家庭 App 会发送特定的非零时长；其实际命令选择在 review 阶段观察，缺少界面入口的标准命令按既定范围使用 Matter 调试客户端验证。

七个样本尚未确认可用于单次命令的原生渐变接口，本轮以控制器生成中间目标、米家属性写入执行的方式为基线。设备持久化的开灯、关灯或调节渐变设置不是单次过渡参数，不能通过改写这些设置模拟一次命令。

每盏灯保留一个发送协调入口，最多一个在途写操作；亮度和色温／彩色分别保留最新待发送目标。发送跟随控制器节拍及在途请求完成推进，不为每个中间值创建独立写任务。相同量化值去重，网络来不及处理的旧中间值直接合并。

例如正在发送 20%，期间收到 30%、40%、70%，下一次直接发送 70%。这不是等待整个拖动结束才发送一次：操作过程中仍发送最新目标，仍有效动作的最后一个目标不能因合并丢失。明确要求渐变或持续调整时，中间变化仍是功能的一部分，只跳过已经过时的未发送步骤。

合并不吞掉命令结果。尚未发送就被新目标取代的显式请求，以“已被取代”结束，不报告为设备已受理；协议调用方得到相应的非成功结果。内部生成的过渡步骤不各自生成新的外部命令应答。已经发出的请求仍由原回执或超时完成。

### 接管、停止与开关

- 新命令先通过能力、参数及关灯状态下是否执行的检查；无效或按规范忽略的命令不能先取消旧动作。
- 同一控制维度按操作先后接管，较新的有效操作取代旧动作。色温和彩色共用一个维度，互相接管；亮度可以独立调整。本轮支持命令中的开关、亮度及模式联动由同一灯具协调执行。
- 一次渐变、Move 或带过渡的 Step 及其生成的中间步骤属于同一条逻辑指令；后续节拍不能因为发送得更晚，就取得高于后来指令的执行权。按上述观察规则识别到后来的米家 App 或实体操作时，更新状态并丢弃同维度旧动作及全部未发送步骤，不再追赶原目标，也不在外部操作结束后恢复。米家操作已经由设备执行，MiGate 不为接管而重复下发该目标；之后新的有效 Matter 命令仍可再次接管。
- 外部亮度变化只接管亮度维度；外部有效色温、彩色或模式变化接管色温／彩色维度。仅更新非当前模式的缓存值不作为模式接管。外部关灯终止整盏灯的旧动作及未发送步骤。
- Stop 清除相应活动动作及未发送步骤，不跳到原目标终点。已发出的写入无法撤回，其回执或通知仍按观察规则收敛状态，因此不承诺 Stop 后物理灯光瞬时冻结。
- 普通关灯使旧渐变失效，旧任务不能再次开灯。Level 普通命令和 WithOnOff 变体遵循各自的开关联动规则，不能统一解释为“调亮即开灯”。
- 操作被替换、停止、删除设备或更新绑定后，旧回执不能重新启动动作。进程重启及全部控制路径失效后，不恢复已结束的动作或重放旧目标。

后续相对调整以已同步的有效状态为依据。缺少必要起点时返回状态未知，不能从虚构值开始；不依赖旧状态的明确目标仍可按有效路径执行。

### 受理与失败

发送前仍按现有规则选择路径；一次实际写入只提交到选定路径一次。结果不明、认证刷新、路径切换或调用者停止等待，都不能触发另一条路径补发。

需要设备写入的动作在启动所需写入获得明确受理后，才返回受理成功；无需写入的等值操作和纯本地动作取消可在完成对应处理后返回。成功不要求等待整个渐变结束，也不表示物理动作已确认完成。

多属性写入逐项检查结果。发生部分受理时保留已知结果、结束失败部分及依赖它的后续步骤，不自动回滚、不声称整次操作原子成功。渐变后续写入失败时终止相关动作，保留有效观察并报告失败原因；不能只因计划时间结束就把快照改成终点。

正常的新目标可以继续使用仍有效的路径。已有渐变因失败终止后不在路径恢复时自动续播；网络时限、退避及可用性判断沿用既有选路设计。

## Matter 端点

以当前依赖采用的 Matter 1.6 数据模型作为命令和属性语义依据。六种色温灯使用 Color Temperature Light，`devcea.light.ls2307` 使用 Extended Color Light；均复用桥接设备身份。设备类型用于灯具分类，不表示完整实现该版本的所有要求。Apple Home 的控件布局及具体命令选择由其版本和配件能力决定，不能据此增加自定义模式开关。

| 灯型 | 设备类型 | 颜色能力 |
| --- | --- | --- |
| 色温灯 | `0x010C`，revision 4 | CT |
| 扩展彩灯 | `0x010D`，revision 4 | CT + XY |

两者均沿用 Descriptor、Bridged Device Basic Information、Identify 和 Groups 的现有基础行为，并提供 OnOff、LevelControl、ColorControl。本轮支持的控制行为包括：

- On、Off、Toggle 的真实设备控制，以及开关状态和可用性报告。
- Level 的 MoveTo、Move、Step、Stop 及 WithOnOff 变体；正确处理有效亮度 1–254、量程、当前值、Options、OnLevel 和 RemainingTime 等支撑这些操作的属性。
- CT 的目标、Move、Step、Stop，以及彩灯 XY 的对应命令；正确处理当前模式、能力、物理色温边界、剩余时间及本轮命令所需的关联属性。
- 以上操作的属性读取、订阅报告、异步受理、失败及取消语义。所有改变设备状态的已启用路径都经过统一设备命令边界。

以下行为不作为本轮交付要求，不为补齐标准而新增相应状态机、存储或设备写入：

| 暂缓项 | 范围 |
| --- | --- |
| 协议场景 | Scenes Management、CopyScene，以及 OnWithRecallGlobalScene、GlobalSceneControl 等全局场景行为。 |
| 计时及特殊灯效 | OnWithTimedOff 及相关计时属性、OffWithEffect、Identify 的物理 TriggerEffect。普通关灯和已约定的渐变仍须支持。 |
| 启动值策略 | StartUpOnOff、StartUpCurrentLevel、StartUpColorTemperatureMireds 的完整协议策略。不影响现有身份恢复、重连读取和状态同步，也不改写灯具自身的上电设置。 |

上游已有且能正确复用的行为可以保留；如需额外建设则按上述边界暂缓。仅修改协议栈缓存、默认 hook 空操作或直接返回成功，不构成真实设备支持。本轮也不声明可选 HS、EnhancedHue、ColorLoop 或其他未实现特性。

部分暂缓项是所选标准灯型的强制要求，因此本轮仍有明确的符合性缺口；不能把它们称为标准可选项，也不宣称 Matter 认证。Apple Home 的基础使用、场景或自动化可用，均不能单独证明 Matter Scenes Management 已实现。不能预设 Apple Home 永不调用暂缓命令；如果缺项影响本轮约定的控制与同步，需定位实际依赖并补齐必要部分。

对外的特性位、属性和命令列表按实际支持范围裁剪，未支持操作如实返回不支持；不能为了满足设备类型要求而启用整组未实现功能。`rs-matter 0.4.1` 的生成基线及默认版本声明不代表完整符合性，其 Level 控制器与 Matter 1.6 模型存在 revision 6／7 差异。本轮检查影响实际灯光行为的量程、读写和状态语义，不以升级到最新 cluster revision 或消除所有版本差异为目标，也不人为提高版本号掩盖缺项。

协议依据见 [Color Temperature Light](https://github.com/project-chip/connectedhomeip/blob/master/data_model/1.6/device_types/ColorTemperatureLight.xml)、[Extended Color Light](https://github.com/project-chip/connectedhomeip/blob/master/data_model/1.6/device_types/ExtendedColorLight.xml)、[Color Control](https://github.com/project-chip/connectedhomeip/blob/master/data_model/1.6/clusters/ColorControl.xml) 和 [Level Control](https://github.com/project-chip/connectedhomeip/blob/master/data_model/1.6/clusters/LevelControl.xml)。

## 身份、持久化与诊断

单灯功能键固定为 `main`，即使属性来自多个 MIoT service，也不增加功能键或控制端点。复用现有单功能设备的端点、UniqueID、名称和发布记录。重启、路径变化及重新加入不重新分配身份。

持久化描述扩展为可恢复静态能力、范围、步长、单位、属性绑定及转换规则的格式。当前旧描述只保存开关绑定，不能假设已有完整 MIoT 原文可重新解析；旧插座通过确定性本地迁移保留原行为、身份和配对，不要求重新联网或重新配对。迁移继续使用现有存储事务与版本管理。

重启从已保存描述恢复已发布设备，运行值从未知开始异步读取，不持久化并恢复未完成渐变。绑定或转换规则更新使旧工作失效。未发布记录和已确认删除的设备不能因旧回调重新出现。

终端 `list`、`status` 按能力展示亮度、色温、颜色、有效模式及未知状态；既有 `on`、`off` 行为保留。诊断沿用实际路径、在途请求与最近结果，能够区分受理、失败、取代和停止。日志不把队列投递或理论插值写成已确认设备状态。

运行指南随功能更新说明支持能力、操作表现、路径与已知边界，不记录验收结果。日志及终端输出继续使用英文，设备名称原样显示。

## 验证标准

### 自动化

- 七个型号的完整描述解析、静态能力与绑定恢复；范围和步长换算，特别是 `light3` 的 1–65535 亮度，以及不同色温边界。拒绝非法或不完整描述，不从厂商场景推断 RGB。
- 单灯始终只有一个功能和控制端点；`devcea.light.ls2307` 色温／彩色命令的目标与模式处理、非当前模式数值通知及部分受理。
- 快照、Matter 读取、订阅报告和相对命令起点保持一致。外部更新后执行 Step 或渐变，不能从控制器旧缓存起步。
- 使用可控时间与传输测试直接目标、有限渐变、Move、Step、Stop 和 WithOnOff；覆盖中间值合并、最终值保留、同维度替换、跨维度协调、关灯以及在途写入后的停止。
- 较晚的有效外部操作接管同维度渐变或 Move，旧动作的后续节拍及迟到回执不能夺回控制；之后的新 Matter 命令可以再次接管。覆盖外部模式切换、关灯、无关维度继续、非当前模式缓存更新、同值通知及自身写入回声，补读与云端缓存不能被误当新指令。
- 本地及云端的数值读写、逐项受理、拒绝、超时、部分成功和来源切换；晚读、晚回执、同值通知、独立属性观察顺序，以及结果不明不跨路径重发。
- 新灯型按约定类型发布，特性位、属性和命令列表准确反映实际支持范围，未支持操作不假报成功；未知状态按协议合法表达，不伪造当前值。完整灯型符合性及暂缓功能不作为通过条件。
- 原数据目录迁移与恢复、身份和名称保留、删除与重新加入、任务退出及旧回调失效；现有插座和多路插座行为不回退。

检查使用现有 `cargo fmt --check`、`cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings`。测试遵循现有模块归属，不为测试扩大生产代码可见性。

### 真机通过条件

| 项目 | 覆盖与标准 |
| --- | --- |
| 基础能力 | 每台支持的开关、亮度、色温、彩色各一轮。量程内目标实际生效，亮度端点及色温边界方向正确。 |
| 外部状态 | 每台支持的能力由米家 App 或实体操作改变一轮；持续打开的 Apple Home 自动同步，无需手动刷新。 |
| 彩灯模式 | `devcea.light.ls2307` 代表设备完成色温与彩色双向切换；分别检查亮度调整保持模式，外部切换后显示和后续控制一致。 |
| 连续控制 | 每台各完成一轮连续调整、一轮新目标打断及一轮停止，选用其支持能力；三台合计覆盖亮度、色温与彩色。至少一轮打断由米家 App 或实体操作发起，确认后来的同维度操作接管、旧渐变被丢弃。灯在操作过程中跟随，结束后不补放旧目标；接管或停止允许已在途写入完成，但不能继续旧动作或跳到旧终点。 |
| 同步时限 | 正常网络且路径已就绪时，普通操作发起后或指定渐变结束后 3 秒内，Apple Home 与实际状态一致；外部操作从设备实际发生变化起计 3 秒。正常过渡时间本身不算同步延迟。 |
| 持续同步 | 结合上述操作观察 10 分钟，无需为观察反复操作；检查状态不反跳、不停留在已失效模式，其他设备继续工作。 |

Apple Home 没有直接入口、但属于本轮支持范围的标准命令可用 Matter 调试客户端触发，实际灯光与 Home 状态共同作为结果依据。验收聚焦本节约定的功能，不要求遍历暂缓命令或通过完整 Matter 符合性测试。路径恢复与拓扑变化的时限沿用已有边界，不把正常同步的 3 秒要求扩展成所有网络故障的恢复期限。七个型号的自动化覆盖不等于七个型号均通过真机验收。
