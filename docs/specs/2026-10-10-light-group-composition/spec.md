# 米家灯组的 Matter 组合接入

## 目标与范围

读取米家灯组的成员关系，沿用多路插座的 Matter 组合端点方式，将一组灯呈现为一个配件及多个灯光功能。目标是在 Apple Home 中每组只有一个入口，进入后可以单独控制成员，且彩灯保留颜色控制。

米家灯组只提供成员关系。每个成员继续使用自己的完整灯光能力、状态和控制路径；组合控制及其界面由 Apple Home 提供。MiGate 不建立可控制的总灯端点，不计算成员能力交集，也不生成整组开关、平均亮度、色温或颜色状态。

本轮支持当前家庭内扁平、互不重叠，且全部成员均为已支持单灯的灯组，包括米家物理灯组和虚拟灯组。成员数量不构成型号白名单或固定容量限制；单成员组可以保留组合关系，空组不发布父端点。成员暂时离线不影响组的成立。

沿用[单灯照明控制](../2026-10-08-single-light-control/spec.md)、[云端接入与统一选路](../2026-10-06-cloud-access-routing/spec.md)及[多设备多通道桥接](../2026-10-04-multi-device-channel-bridge/spec.md)的既有能力。运行范围继续为 macOS / Apple Silicon，保持 Rust 单包结构。

本轮不包含嵌套组、重叠组、非灯成员、由 MiGate 创建或修改米家灯组、厂商场景、Apple 自适应照明，以及新的协议栈或驱动框架。不增加用于试验展示的虚拟设备；真实效果按下述真机验收要求确认。

## 方案与协议边界

| 方案 | 取舍 |
| --- | --- |
| 把米家灯组当成一盏灯，直接使用组 DID 的属性 | 接入简单，但组描述可能没有成员具备的颜色能力，不能满足本轮目标。 |
| MiGate 创建总灯，按成员能力交集汇总状态并分发命令 | 可以定义自己的整组行为，但需实现状态聚合、部分失败及并发接管；本轮不采用。 |
| Matter 父端点包含成员灯端点，交由 Home 组合控制 | 沿用多路插座结构，保留成员能力与控制语义；采用此方案，Home 呈现作为真实验收要求。 |

以下三种“组”不能混为一谈：

- 米家灯组是本轮的成员关系来源，不是 MiGate 的控制对象。
- Matter `Descriptor.PartsList` 表达组合结构；`Groups` cluster 表达组地址与成员配置，不自动定义总灯状态，也不保证控制器 UI。
- Apple Home 的组合控件及整体操作由 Home 决定。Apple 文档中的手动编组能力不能证明它一定按预期展示此种 Matter 组合设备。

Matter 的组合设备与桥接模型允许多个功能端点共享顶层桥接身份；同一个桥接设备的 Bridged Device Basic Information 位于其层级顶端。本轮按这一模型组织灯组，而不是将多个带独立桥接身份的灯简单放进另一个父节点。参见 [Matter Core §9.12.2](https://csa-iot.org/wp-content/uploads/2024/05/matter-1-3-core-specification.pdf#page=533)及[设备数据模型](https://developers.home.google.com/matter/primer/device-data-model)。命令、属性及类型版本继续沿用当前依赖采用的 Matter 数据模型，不因引用结构说明而降级。

现有每盏灯的 `Groups` 基础行为继续保留，不映射米家 group DID 到 Matter group ID，不增加 Actions 组控制。Home 收到拓扑后是否产生预期控件，需要真机确认；不能以符合端点结构替代 UI 验收，也不预设手动编组或总灯端点作为失败后的自动替代方案。

## 成员目录与准入

### 成员数据来源

通过现有米家云端设备目录接口 `/app/v2/home/device_list_page` 获取组设备的 `extra.member_list`。已进行的只读目录检查确认当前样本存在下列形状，示例标识均为占位示意值：

```json
{
  "extra": {
    "member_list": {
      "group_did": "group.example",
      "status": "1",
      "display_member_switch": 0,
      "member_ship": { "member-a": "1", "member-b": "1" },
      "is_physical": true
    }
  }
}
```

`member_ship` 是接口实际字段名。以其键取得成员 DID，不按灯名、房间、连续编号或设备列表顺序推断成员。`display_member_switch` 不作为 Home 展示要求；`is_physical` 只描述米家组类别，两种类别采用相同接入规则。组自身 MIoT 描述中的亮度、色温、RGB 缺项和量程均不限制成员能力。

成员关系在云端协议边界解析，按当前已确认的组及成员状态 `"1"` 读取；未知状态或无法解析的响应沿用目录读取失败的处理，不过滤成有效空组。

目录读取复用现有认证、分页、周期同步、事件触发及重试。完整同步必须同时刷新组元数据，不能因为组目前未发布或成员已准入而漏查。保持现有约 5 分钟的成员周期，不新增高频轮询或独立组连接；拓扑变更的收敛按目录同步节奏，不适用灯光属性同步的 3 秒目标。

### 准入与同步

灯组由米家创建和维护，MiGate 直接采用其成员关系。沿用现有家庭范围及完整目录同步规则，成员均属于当前家庭、列表完整且全部为已支持单灯时，即可组合接入。成员离线或首读失败不影响准入，能力仍由各自的单灯描述决定。

组与普通单灯分别处理：`group.*` DID 或已知 `mijia.light.group3` 进入组关系解析，不作为普通单灯接入。当前型号是代表样本，不限制具体组 DID 或成员数量。

每次目录同步只发布完整且不冲突的组合关系。读取失败或信息未就绪时，保留旧关系，依赖该关系的跨组变更一并延后，无关组照常更新。沿用既有同步重试，不增加专门的恢复流程。

完整当前家庭目录确认的成员删除优先处理；受影响组没有完整有效的新关系时，撤销父端点，其余支持成员恢复独立灯，不自行删减旧成员表组成新组。详情缺记录本身不构成删除依据。

确认超出本轮支持范围的组不发布，支持的成员作为独立单灯保留，并说明未组合原因。不为这些情况增加关系修复或冲突协调流程。

## 模块边界与数据流

| 单元 | 职责 |
| --- | --- |
| `xiaomi/cloud` 与 `xiaomi/catalog` | 在协议边界解析组元数据，提供带账号、家庭及分页完整性约束的目录结果。 |
| `xiaomi/capability` | 继续解析成员自身能力与 MIoT 绑定，保留组与普通单灯的区别。 |
| `xiaomi/adapter` | 依据完整目录协调准入、成员关系及撤销；成员继续使用既有实例、选路、队列、通知和状态快照。 |
| `device` | 增加独立于成员运行状态的组合关系及修订，使注册表快照能一致地表达设备与组合；不携带 MIoT 属性或 Matter endpoint。 |
| `storage` | 保存组身份、名称、端点预留和已确认成员关系，处理旧组记录的角色迁移；网络操作不进入数据库事务。 |
| `matter` | 将组合关系映射为父子拓扑，复用成员灯处理器，报告拓扑与成员属性变化。 |
| `runtime` 与终端 | 沿用现有生命周期；展示组及成员关系、阻断原因、成员能力和实际路径，不另建整组灯光状态。 |

数据流为：完整家庭目录及组详情 → 成员描述准入与关系校验 → 持久化一致的关系版本 → 发布注册表拓扑 → Matter 更新父子端点。成员属性通知仍直接进入原单灯快照，再由原灯光处理器同步读取、订阅及计算状态。

组合记录引用成员的稳定设备键，不把多盏灯塞进同一 `PhysicalDeviceDescription`。当前单灯只允许一个 `main` 功能的校验继续成立。纯分组变化不得调用删除成员的路径，不能关闭其任务、重新创建命令消费者或复制一份灯光状态机。

Matter 调和不能仅凭 `PhysicalDevice.same_instance()` 跳过更新；组合关系有独立修订，同一个成员实例也可能从独立端点变为子端点。一次关系变更必须同时提交可见的父子集合及相应 Descriptor 信息，不能在中间状态重复发布成员或引用不存在的端点。

## Matter 端点与成员能力

根端点 `0`、Aggregator 端点 `1` 及既有插座结构保持现有职责。

| 对象 | 类型、身份与功能 |
| --- | --- |
| 灯组父端点 | Bridged Node；仅提供 Descriptor 与 Bridged Device Basic Information，承载组身份、名称和成员 PartsList，不含 OnOff、LevelControl 或 ColorControl。 |
| 色温灯成员 | Color Temperature Light；保留 Descriptor、Identify、Groups、OnOff、LevelControl、ColorControl 及既有 CT 能力。 |
| 彩灯成员 | Extended Color Light；保留相同灯光基础及完整 CT、XY、HS 能力，不受米家组缺少颜色属性影响。 |
| 未分组或退出组的单灯 | 沿用现有独立单灯结构，同一端点同时提供灯类型及 Bridged Node 身份。 |

组合内的成员端点不重复声明 Bridged Node 或 Bridged Device Basic Information，桥接身份位于父端点。子端点的实际灯类型、量程、命令和异步处理器来自成员能力；必须扩展当前仅面向插座的 Child 路径，不能套用 On/Off Plug-in Unit 或只保留开关。

同组多个同类灯通过 Descriptor 的 TagList 及成员标签区分。标签使用原成员已保存的设备名称，区分键绑定稳定成员身份；重排或移除其他成员不能重编号剩余成员，重名不能导致键碰撞。组首次名称使用已有保存名称或目录名称，之后沿用现有持久化命名规则；成员名称仍属于原设备，不改成统一的“灯”。Home 若未采用成员标签，允许首次逐灯核对后手动命名；这不免除 MiGate 正确发布标签的要求。

更新时保持父节点 PartsList、根与 Aggregator 的规范列表、成员角色、DeviceTypeList、ServerList、TagList 及对应数据版本一致，并通知订阅者。规范要求的祖先列表包含后代，不等于额外发布一份独立配件；每盏灯只有一个实际控制端点和一个组合归属。

父节点 Reachable 表示至少一个当前成员有可用控制路径；全部成员不可用时为 false，不用米家组自身的 online 字段代替。它不表示成员灯是否亮起，也不要求读到任何灯光值。子端点不另带 Bridged Device Basic Information，因此不承诺 Home 为每个子灯显示独立离线徽标；内部及终端继续保留逐成员可用性与错误。

## 身份、存储与动态变化

组以自身 DID 对应的来源设备键保存稳定身份与父端点分配；成员始终保留原 DID 设备键、`main` 功能键和 endpoint。加入或退出组只是发布角色变化，不能借此换成员身份或分配第二个控制端点。

当前存储会为旧灯组保留身份和 endpoint，但已撤销发布，历史上可能将其记为 `main` 单灯。需要显式迁移为“组合父节点”的记录或身份角色，复用原分配，不带出旧组灯功能和属性处理器。不能绕过普通设备严格的功能兼容检查，也不能把旧缓存的灯描述直接视为完整组关系；旧记录首次发布为组合前，必须获取完整有效的当前成员目录。

为成员定义明确的独立单灯 ↔ 组合子灯角色变更，保留控制能力及 endpoint，只按角色增减桥接身份相关类型和 cluster、调整 Descriptor。此处是本轮允许的结构变化，不放宽固件或 MIoT 描述不兼容时禁止悄悄更换控制功能的规则。灯光控制器和仍有效的成员操作生命周期应随原成员保留，纯组合变更不得取消或重放操作。

组身份、关系及必要的角色变化以一致事务保存，发布使用同一确认版本；异常不能导致一半成员独立、一半成员已归组。已撤销的组和成员继续保留原有身份预留，重新出现时按现有身份策略复用。

| 变化 | 处理 |
| --- | --- |
| 成员加入组 | 全组条件满足后一次性发布新关系，该成员由独立灯变为原 endpoint 的子灯。 |
| 成员退出组 | 当前家庭中仍存在且受支持的成员恢复独立灯；剩余非空有效组继续发布。 |
| 组明确解散或有效成员列表变空 | 撤销父端点，仍属于当前家庭的支持成员恢复独立灯，不删除米家设备。 |
| 单个成员暂时离线 | 关系、能力和端点不变；其命令按该成员路径返回结果，其他成员仍可用。 |
| 关系明确变为不支持的结构 | 该组不再组合，支持成员按普通单灯处理，并说明原因。 |
| 目录读取暂时失败或关系未确认 | 按准入与同步规则保留最后一致关系、延后相关变更；已确认的成员删除优先处理。 |
| 原数据目录重启 | 恢复当前账号及家庭最后已发布、已确认且成员描述兼容的组关系与分配；已撤销的历史组不能自行复活。再异步同步目录及成员状态，不重放旧命令，属性从未知开始恢复。 |

Apple Home 尚未投入真实使用，本轮不要求迁移既有 Home 场景、自动化、房间配置或自定义显示布局。MiGate 的内部身份、端点分配及网桥配对仍需稳定，不通过重置配对或清空运行目录实现分组。

## 控制、状态与失败语义

Home 无论通过组入口还是成员入口发出请求，MiGate 都只执行请求所指向成员端点的命令，不再次向整组分发，不读写或订阅组 DID 的灯光属性。一个成员失败或离线不能阻塞其他成员，也不能以一盏灯成功表示其余成员成功。

每盏灯继续使用单灯设计中的目标设置、渐变、Move、Step、Stop、开关联动、模式切换及后来有效操作接管规则。组入口没有额外优先级；实际命令按成员原有命令边界处理，已发送请求不因组变化或失败而跨路径重发。

MiGate 不构造统一整组完成、原子成功或回滚语义；请求按成员返回实际受理或错误，Home 如何汇总 UI 由 Home 决定。未读到成员状态仍为未知，不能用其他成员或米家组的值补齐。

通过米家 App 或实体操作改变成员时，更新该成员原快照及 Matter 报告，其他成员不随之伪造变化。颜色与色温切换、外部变化校正控制器计算状态及旧通知处理继续沿用单灯规则。

## 验证与完成条件

### 自动化验证

测试按主题放入所属模块的 `tests/`，跨模块流程放在根目录 `tests/`，不为测试扩大生产代码可见性。覆盖以下行为：

- 目录与准入：物理组和虚拟组均可接入，沿用家庭范围及完整目录规则；未确认删除时读取失败保留已有关系，详情缺记录不误判删除，超出支持范围的组不组合。
- 准入：组缺少 RGB 仍保留 RGB 成员能力；异构灯按各自能力发布；不支持或描述待定的成员不能造成部分组发布；离线和首读失败不阻止有效组准入。
- 拓扑：纯父节点、CT／RGB 子节点的类型和 cluster 完整；同名成员仍可区分；跨组变更信息未就绪时不重复归组、不阻塞无关组；关系变化即使成员实例不变也触发一致更新与报告，无重复控制端点或无效 PartsList。
- 身份及恢复：从旧未发布组灯记录迁移、已有成员加入及退出、组解散、重加、重新排序、原数据目录重启；组父端点和成员 endpoint 不冲突，桥接身份及配对保存，命名和标签稳定。
- 生命周期：确认成员删除后清理引用，缺少有效新关系时撤组并恢复其余支持成员为独立灯；存储失败不发布半套关系；成员角色变化不关闭原成员任务或重复控制器，不取消仍有效操作，不重放命令。
- 控制隔离：同组成员使用不同路径时仍各自选路，部分离线或失败不阻塞其他成员；无组 DID 属性操作或第二次命令分发；成员连续控制、接管、外部通知和颜色模式同步保持单灯语义。
- 回归：未分组单灯、单路插座及多路插座保留原控制、状态同步及恢复行为。

### 真机验收

真机验收覆盖代表组的呈现、控制与恢复，以及临时灯组的创建、成员增删和解散。临时组使用未分组的受支持单灯，现有米家组配置保持不变。代表组的目录关系已经通过只读查询确认；这仅是设计依据，不代表 Matter 展示或控制已经验证。

| 项目 | 范围与通过条件 |
| --- | --- |
| 代表组 | 二楼空间的两个色温灯组：6 盏筒灯组与 4 盏过道筒灯组，成员为 `yeelink.light.light3`；另选包含左右两盏 `devcea.light.ls2307` 彩灯的卧室床头灯组。前两组为米家物理组，后一组为虚拟组。 |
| Home 呈现 | 自动形成每组一个入口，进入后能够单控成员，成员不重复显示为独立配件；允许首次核对并手动命名，使名称足以区分。 |
| 组入口控制 | 各组完成开关、亮度、色温各一轮；床头灯组额外验证整组颜色控制及色温／彩色切换，实际成员按目标变化。 |
| 成员单控 | 每组选至少一盏单独调整，确认其他成员不被误控；床头灯验证成员颜色控制及模式切换。 |
| 外部状态同步 | 每组选一盏通过米家改变状态，Home 自动同步；床头灯包含颜色变化。正常网络下沿用 3 秒标准，整体持续观察 10 分钟，不能靠重启或手动刷新使值收敛。 |
| 恢复与回归 | 使用原数据目录重启一次，组关系和控制恢复、端点分配及配对保持；抽查未分组单灯、单路插座及多路插座。 |
| 临时组样本 | 准备至少三盏属于当前家庭、已按受支持单灯接入且未加入任何米家灯组的灯，确认米家 App 允许共同创建灯组及编辑成员。按各灯实际能力验证控制。米家目前不支持单成员灯组，成员增删期间组内至少保留两盏灯。 |
| 临时组创建与成员增删 | 先用两盏灯创建临时组，确认自动形成一个 Home 入口并可单控成员；加入第三盏，确认其转为组内成员且没有重复配件；移除一盏，确认其恢复独立灯、原组及其余两名成员保留。成员 endpoint 全程保持，同一组的 DID 和父 endpoint 保持；每步核对成员能力、控制及状态同步。 |
| 临时组解散 | 在米家解散临时组，确认 Home 撤销组入口，参与验收的灯均恢复独立入口及控制，成员 endpoint 保持；既有组配置及其控制不受影响。 |

临时组每一步均等待完整目录确认、MiGate 发布对应关系及 Home 拓扑收敛后再进行下一步，分别观察目录发现与 Home 更新，避免多步操作被一次同步合并；不通过重启、重新配对或手动刷新促使其通过。样本不足时，未执行的步骤保持待验，不能把解散后重建当作原组内的成员增删通过，也不改动既有组来补齐样本。

每个样本只验证当时实际使用的路径，并记录其本地／云端情况，不重复完整的本地／云端故障矩阵。目录拓扑恢复与灯光属性传播分开判断；3 秒沿用单灯同步标准，不作为周期目录发现新关系的期限。重启后的 Home 拓扑恢复沿用最长 20 分钟观察窗口，从 MiGate 重新提供 Matter 服务起计；未恢复即如实记录，不以重新配对掩盖问题。

真机验收只增删临时组的成员并最终解散临时组，不拆散既有米家灯组或改动其成员，以免影响米家自动化；不引入重叠组。部分离线、目录读取失败或信息未就绪，以及未提供界面入口的既有协议命令不纳入真机验收，本轮不要求完整灯协议符合性验收。

自动形成总入口、成员单控和整组／成员颜色控件均为交付要求。首次手动命名不影响通过判定；其余展示或控制不符合要求时，仍为未通过项，返回设计讨论，不能以手动编组、独立灯、仅色温组或额外总灯端点替代后宣布通过。
