# MiGate 温湿度传感器与附属电量接入

## 目标与范围

以 `45ecb22` 为代码基线，将当前家庭中符合能力条件的米家温湿度计通过现有来源接入 MiGate，并在 Apple Home 中提供自动更新的温度和相对湿度。接入范围按设备能力确定，不限定设备名称、型号或单台设备。

温度与湿度分别建模为只读功能，电量是整台物理设备的可选共享状态。读数遵循设备原生上报节奏；正常静默期间保留最后有效值，不设置统一的过期超时。成功标准包含真实通知到 Home 已打开页面的完整更新链路。

本次支持具有有效温度、相对湿度属性的温湿度计，以及其可选电量。通过 MIoT 标准设备、服务和属性语义识别能力，不以型号或固定 `siid`／`piid` 白名单代替解析。单独的其他传感器类别、其他设备的附属环境测量、照度、历史曲线和告警自动化不在范围内。

接入使用现有本地中枢和米家云端来源。设备只有云端路径可用时，可以仅通过云端交付；不引入主机蓝牙扫描、设备 IP 直连或新的网关协议。既有插座、独立灯和米家原生灯组行为继续成立。

## 能力边界与描述样例

以 `miaomiaoce.sensor_ht.t6` 的公开 MIoT 描述作为解析样例，其设备类型为：

`urn:miot-spec-v2:device:temperature-humidity-sensor:0000A00A:miaomiaoce-t6:1`

以下是该类型的静态属性定义，仅用于解析样例和测试夹具，不限定接入或真机验证对象，也不作为其他型号的编号约定：

| 角色 | 服务／属性 | 格式与单位 | 描述范围 | 权限 |
| --- | --- | --- | --- | --- |
| 温度 | `3 / 1001`，`temperature` | `float`，摄氏度 | `[-30, 100]`，步长 `0.1` | `read`、`notify` |
| 相对湿度 | `3 / 1008`，`relative-humidity` | `float`，百分比 | `[0, 100]`，步长 `0.1` | `read`、`notify` |
| 电量 | `2 / 1003`，`battery-level` | `uint8`，百分比 | `[0, 100]`，步长 `1` | `read`、`notify` |

温度和湿度的有效绑定、格式、单位、范围与读取／通知权限在原生描述边界确定。接纳范围要求两项测量都成立，均可读且声明通知能力，不要求写权限；描述中缺少必要测量与运行中暂未取得读数是不同情况。可选电量单独判断，同样要求可读且声明通知能力；缺失、不受支持或只有 `read` 时不发布电量，给出相应诊断，不阻止有效的温湿度能力接入。不为仅可读电量新增轮询。

本次支持摄氏度温度与百分比相对湿度，覆盖浮点测量和整数电量。范围必须有限、顺序正确且可表示为对应 Matter 属性；不猜测单位、不将越界值截断成合法读数。MIoT 步长描述来源分辨率，不等同于传感器精度，也不据此虚构 Matter `Tolerance`。

目录信息、缓存读取成功和属性支持 `notify`，均不能单独证明实际通知链路成立。蓝牙设备的云端在线字段不能独立作为测量新鲜度依据；实际使用的中枢或蓝牙网关依赖须在真机验证中确认。具体上报间隔由设备及其来源链路决定，不设置统一周期。

## 模型与职责

采用独立温度、湿度功能和设备共享电量的模型。相比将三项值封装成固定温湿度计功能，该模型让测量能力、更新时间和 Matter 端点分别对应；电量保留其整机属性，不产生第三个测量功能。

| 单元 | 本次职责 |
| --- | --- |
| `device` | 增加明确的只读温度、湿度功能及各自状态；物理设备持有可选电量状态和共享可用性。 |
| `xiaomi/capability` | 将 MIoT 描述构造为有效测量绑定与可选电量绑定，保留格式、单位、范围及真实访问权限。 |
| `xiaomi/adapter` | 按实际读取、通知资格选路，读取初值，接收带来源信息的观测，更新对应状态，并管理来源与连接生命周期。 |
| `configuration` | 纯数据规划身份、名称、端点和发布形状，比较配置变化，不执行读取或订阅。 |
| `app` | 沿用准备、原子保存、激活的配置应用机制，管理来源对象和 Matter 发布生命周期。 |
| `matter` | 接收显式发布条目，完成标准属性投影、单位换算、版本与订阅报告。 |
| `storage` | 编码和恢复身份、端点、名称、原生能力及绑定，在加载边界构造有效模型。 |
| `terminal` | 呈现测量、电量、可用性和更新时间，并明确拒绝传感器不支持的控制操作。 |

功能种类和快照使用明确的类型分支区分插座、灯、温度和湿度。传感器不携带虚构的开关值，不创建无用途的写入队列；读取绑定也不通过必有的 `power` 字段间接取得。电量绑定归属原生物理设备描述，电量状态归属逻辑物理设备，消费者观察同一份状态。

身份沿用来源与物理设备标识，温度和湿度使用稳定功能键 `temperature`、`humidity`。首次命名由物理设备名称派生，已有持久化名称优先。电量不分配功能键或独立端点。

调整限于接纳只读测量、可选整机电量所必需的类型和访问边界，不引入通用传感器插件、设备 actor 或统一事件总线。外部数据在网络、存储边界校验后，内部直接使用有效模型。既有来源权限、连接及退休状态检查继续保留。

## 读数、时间与恢复

### 独立状态

温度、湿度、电量各自保存最后有效值、该值可取得的来源更新时间，以及 MiGate 接收该观测的时间。三项数据可以不同步更新，不等待一次完整组合样本，也不使用温度或湿度更新时间代替电量更新时间。

| 情况 | 状态处理 |
| --- | --- |
| 尚未收到有效值 | 对应项目为未知，不补 `0`、`100%` 或其他初值。 |
| 收到有效观测 | 更新该项目及其时间信息，其他项目保持原值。 |
| 正常静默 | 保留最后有效值，不因统一时限而清空、离线或强制轮询。 |
| 单次读取失败、属性错误或非法值 | 记录必要诊断，保留该项目最后有效值；没有旧值时继续未知。 |
| 电量缺失、读取失败或属性订阅失败 | 不影响温度、湿度状态与可用性，也不撤销已成立的温湿度通知链路；有效电量能力已发布时，按未知或最后有效值处理，不因单次失败移除 Power Source。 |
| 所有测量获取路径失去资格或连接 | 设备不可用，已有读数仍保留；恢复后重新获取。 |

来源值在输入边界校验类型、有限性和合法范围。非法值不参与 Matter 换算，也不覆盖旧值。某项读数不因另一项数据有效而被推定有效。

### 更新时间

云端返回的 `updateTime` 等真实来源时间随观测传递，不能被 HTTP 完成时间替代。重复读取云端缓存可以产生新的接收时间，但不能把来源更新时间刷新为“现在”。协议未提供来源时间时明确为未知，也不将上一读数的来源时间挪给新值。

上游提供的属性更新时间须在网络边界保留，不能因现有接口只传递 `value` 而将其丢弃或视为协议未提供；消息发送或网关转发时间不当作设备采样时间。来源时间只用于诊断，不参与读数排序或来源选择。

接收时间用于诊断 MiGate 何时看见数据；来源更新时间用于说明设备数据的年龄，两者均不产生固定过期判定。终端能够区分两种时间，以及当前尚未知值、保留旧值或无获取路径等情况。

读请求与通知继续使用现有来源代际、连接身份和观测顺序约束，防止较早请求的完成覆盖较新的通知。已退休来源及旧连接的迟到数据不再更新当前设备。在这些约束内，采用当前有效来源收到的合法值；切换或恢复后取得的缓存可以覆盖此前保留值，接受缓存延迟造成的短暂读数回退。不新增基于时间戳的同源或跨来源排序、缓存仲裁及去重机制，也不要求读数按设备采样时间单调推进。

### 获取节奏与可用性

初次启动、连接恢复和有效来源切换时请求当前值，之后依靠原生属性通知同步。读取使用已有合并、去重与有限重试机制，不新增定时采样循环，也不为满足界面响应时间提高设备上报频率。

电量是可选观测，不作为温湿度通知来源准备就绪的必要条件。温湿度订阅成立后即可同步，不等待电量首值或订阅成功；电量属性的局部订阅失败单独诊断并沿用有限重试，不因此切断测量链路。账号或共享连接整体失效仍按真实生命周期处理。

可用性依据该设备实际可用的读取或测量通知路径，以及当前账号、家庭、权限与连接状态判断，不能要求存在可写控制路径。只有电量路径可用不足以让温湿度设备可用。单次读失败和长时间没有属性变化均不等于所有路径失效。

具有读取路径但没有有效通知链路时，可以展示读到的值并诊断同步受限，但不能据此满足自动更新目标。对于缺少可靠上下线信号的蓝牙温湿度计，云端 `isOnline=false` 不独立阻断读取或测量通知资格；仍须依据当前账号、家庭归属、权限及对应获取通道判断，授权失败、设备移除、来源退休等明确失效继续生效。

这类设备的共享可用性及 Matter `Reachable` 表示 MiGate 的数据获取通道可用，不保证传感器本体或蓝牙网关仍在工作。云端缓存仍可读或合格的测量通知连接仍成立时，即使设备断电或蓝牙网关停止转发，也可以继续可达并保留最后有效值；不以静默时长推断离线。终端明确区分通道可用与“设备物理在线状态未知”，不能将前者展示为已确认设备在线。

选路切换和连接恢复期间保留同一逻辑设备的最后有效值。读数不写入持久化存储；进程重启后先为未知，再从真实来源获取。身份、名称、端点和配对按既有机制恢复。

## Matter 发布

### 端点结构

一个温湿度计发布为一个物理父端点和两个测量子端点：

| 端点 | 设备类型与集群 | 归属 |
| --- | --- | --- |
| 物理父端点 | 既有 Bridged Node、Descriptor、Bridged Device Basic Information；有有效电量能力时增加 Power Source 设备类型与集群 | 物理身份、名称、共享 `Reachable`、可选电量 |
| 温度子端点 | Temperature Sensor `0x0302`，Descriptor、Identify、Temperature Measurement `0x0402` | 温度功能 |
| 湿度子端点 | Humidity Sensor `0x0307`，Descriptor、Identify、Relative Humidity Measurement `0x0405` | 湿度功能 |

父子关系、`PartsList`、设备类型列表和集群列表与真实发布结构一致。是否带电量不改变两个测量功能的身份；电量不产生独立传感器端点。

测量和电量均为只读，不声明 On/Off、Level、Color 或 Groups 控制能力。Identify 依协议处理，不能借此虚构设备支持物理闪烁或可写 MIoT 属性。未知值、不可用状态与保留读数分别表达，不用数值清零表示离线。

协议基线与当前固定的 `rs-matter` 版本所用 Matter 1.6 数据模型一致：Temperature Sensor 设备类型修订为 `3`，Humidity Sensor 为 `2`，Temperature Measurement 集群修订为 `4`，Relative Humidity Measurement 和 Power Source 集群修订均为 `3`。新增处理器必须提供所声明设备类型、特性对应的必需属性、全局属性及标准行为，不因现成处理器缺少支持而伪造能力。

### 测量属性

| 项目 | Matter 表示 | 未知与范围 |
| --- | --- | --- |
| 温度 | 摄氏度乘 `100`，换算为有符号整数 | `MeasuredValue` 可空；上下限由有效原生范围投影，满足标准限制。 |
| 相对湿度 | 百分比乘 `100`，换算为无符号整数 | `MeasuredValue` 可空；范围在 `0..10000` 内。 |

换算在 Matter 投影处统一完成，采用最近整数舍入，恰好半整数时远离零；边界检查在舍入前后均须成立，不能把非法原生值修正为边界值。上述描述样例对应温度上下限为 `-3000..10000`，湿度为 `0..10000`，其他设备使用其有效原生范围。标准要求的最小值、最大值和测量值必须彼此一致；不因可表示为百分之一单位而宣称来源具有百分之一的测量精度。

两项测量的 `FeatureMap` 为 `0`，不声明额外可选能力。有效读数、未知／已知转换和共享可用性变化按相关属性触发版本与订阅通知。仅接收时间变化不产生虚假的测量变化；原生值在投影后相同也不要求制造新测量报告。

### 共享电量

Power Source `0x002F` 使用 `BAT` 特性（`FeatureMap = 0x02`）。当前依赖中的有线电源处理器不能直接代替电池处理器；使用其数据模型和标准接口提供电池属性，不为此默认升级依赖。

| 属性 | 映射规则 |
| --- | --- |
| `BatPercentRemaining` | 百分比乘 `2`，范围 `0..200`；未知为 `null`，例如 `100%` 对应 `200`。 |
| `BatChargeLevel` | `p > 10%` 为 `OK`；`5% < p <= 10%` 为 `Warning`；`p <= 5%` 为 `Critical`。 |
| `BatReplacementNeeded` | 仅在已知电量 `p <= 5%` 时为 `true`，其他已知有效电量为 `false`。 |
| `BatReplaceability` | 没有可靠原生信息时为 `Unspecified`，不推断用户可更换或可充电。 |
| `Status` | 没有可靠电源状态信息时为 `Unspecified`；连接不可用不直接映射为电池故障。 |
| `Order`、`Description` | 单台物理设备的一项电源，使用顺序 `0` 和描述 `Battery`。 |
| `EndpointList` | 明确列出该物理父端点和两个测量子端点，不覆盖其他桥接设备。 |

阈值是 MiGate 根据百分比定义的提示策略，不声称等同于设备固件的低电量报警。原生描述中的低电量事件不用于另建无法解除的锁存状态。不声明可充电等缺乏依据的特性。

`BatChargeLevel` 和 `BatReplacementNeeded` 是非空属性。首次取得有效电量前，对这两项返回属性级 Matter `Failure` 状态，不能虚构 `OK` 或 `false`；`BatPercentRemaining` 同时保持 `null`。已有电量后遇到单次失败或静默，三项继续由同一份最后有效电量派生。一次电量更新需同步反映百分比与跨阈值变化，并产生相应报告。

电量属于整台设备只约束数据所有权与协议归属，不保证 Apple Home 必然显示百分比或采用特定分组样式。Home 的分组、温湿度入口和电池提示以实际客户端表现核验；协议属性正确性独立验证。

## 配置、存储与既有行为

温度、湿度、可选电量及测量范围进入明确的原生描述和固定发布形状。普通读数、更新时间和电量阈值变化不属于配置变化，不触发端点重建或 Matter 重启。

在当前 schema 8 的私有配置编码中增加测量功能分支和可选设备电量字段。测量范围需要表达有限小数与负温度，不能复用只允许无符号整数的灯光范围而损失语义。既有插座、灯编码继续可读；此前无电量字段表示未声明电量，不补造能力。保留严格的模型边界校验，不建立无实际需求的历史格式迁移框架。

当前有效数据库能够直接加载，新增能力不要求清库、重配对或重新命名。配置保存仍为原子事务；准备或保存失败时维持原有效配置，不留下部分传感器端点。首次发现、重启、移除后重新加入及描述版本更新，沿用既有身份与端点保留机制。

MIoT 新版以向后兼容为前提，通过既有完整配置应用机制接纳。不得为假设性的属性删除、重新编号或功能乱序增加兼容映射和测试。无实际形状变化的重复目录更新仍不重建运行对象。

终端应能查看温度、湿度、设备共享电量，以及来源和可用性诊断。向只读功能发送控制命令时在命令边界返回不支持，不生成原生写请求；既有插座和灯的控制、群组关系及隐藏成员行为保持原有语义。

## 验证要求

### 自动化覆盖

| 主题 | 必须覆盖的行为 |
| --- | --- |
| 能力解析 | 标准属性定义及公开描述样例；真实绑定、格式、单位、范围、访问权限；必要测量缺失与可选电量缺失；仅可读而无通知权限的电量不发布且不阻断温湿度；不误接入照度或其他设备的附属测量。 |
| 有效状态 | 首值未知；三项独立更新；非法类型、非有限数值、越界值与单次错误保留旧值；静默不清空；电量失败不影响测量。 |
| 时间与顺序 | 来源时间与接收时间区分；缓存读取不刷新来源时间；缺失来源时间保持未知；较早发起的读取不能覆盖后到通知，退休来源及旧连接不能更新当前状态；当前有效来源的合法缓存可覆盖此前保留值，不按时间戳排序。 |
| 来源获取 | 初次、重连、来源切换读取；读取合并及有限重试；无控制路径的只读设备可用；路径丢失和恢复；只有读取时正确呈现通知受限；电量属性订阅失败不阻断温湿度同步；缺少可靠在线信号的蓝牙设备不被云端离线字段单独阻断，仍保留明确失效检查，并区分通道可用与物理在线未知。 |
| Matter 测量 | 设备类型、父子拓扑、集群及修订；正负温度、湿度、舍入、范围与空值；拒绝写入；真实状态变化通过订阅产生报告。 |
| Matter 电量 | `BAT` 必需属性、半百分比单位、端点归属；未知电量的可空与非空属性处理；`0%`、`5%`、`10%`、`100%` 及阈值相邻值；百分比和派生属性同步报告。 |
| 配置与恢复 | 当前无传感器配置可读；传感器能力与绑定往返；多台符合条件的设备分别接入，身份、端点、读数与电量互不串用；身份、名称、端点和配对恢复；失败不部分激活；普通读数不触发配置应用。 |
| 回归 | 单路／多路插座、独立灯的已有能力、原生灯组及隐藏成员、本地与云端来源的既有权限和生命周期行为。 |

模块测试与辅助代码放在所属模块的 `tests/`，集成测试放在根目录 `tests/`。通过所属模块接口验证规则，不为测试扩大生产代码可见性。协议验证要检查属性读写和订阅输出，不能仅以内部“已变化”标记作为报告成功的证据。

### 真机与 Home

验证环境为 macOS Apple Silicon、现有账号与家庭。使用既有认证信息发现符合条件的温湿度计，从中选择可用设备作为真机样本，不预先指定名称或型号。温湿度与电量验证可使用同一台或不同设备；电量项目选择实际提供该能力的设备。确认所选设备的真实绑定，实际验证本地或云端获取路径、通知与网关依赖。只要求样本真实具备的路径成立，不将未提供的本地能力列为通过项。

| 项目 | 成功标准 |
| --- | --- |
| 发现与读取 | 当前家庭中符合条件的设备按能力接入；所选样本的温度、湿度及其支持的电量可通过对应真实属性取得，Matter 属性与单位一致。单次缓存读取仅证明读取链路。 |
| 温度自动更新 | 观察至少 `3` 次足以在 Home 中显示为不同值的真实温度变化。每次等待上游新上报最多 `20` 分钟。 |
| 湿度自动更新 | 观察至少 `3` 次足以在 Home 中显示为不同值的真实湿度变化。每次等待上游新上报最多 `20` 分钟。 |
| 页面响应 | Matter 订阅正常时，从 MiGate 接收新值起 `10` 秒内，已打开的 Home 页面自动显示对应变化；不以手动重新进入页面代替自动更新。 |
| 静默与单项更新 | 原生静默期间保留最后有效值；某项变化不清空其他项目，不制造统一更新时间。 |
| 重启 | 重启 MiGate `2` 次，身份、名称、端点、配对保持；启动先呈现未知，再获取真实读数并恢复同步。 |
| 连接恢复 | 中断并恢复 MiGate 的实际获取连接 `2` 次，正确表达可用性，保留有效读数并恢复同步，无需重新配对。 |
| 电量 | 核对实际百分比、Matter 电源归属和客户端可见表现；低电量阈值使用自动化验证，不要求人为耗尽电池。 |
| 原有设备 | 现有插座、独立灯和原生灯组的控制与状态同步继续正常。 |

原生上报等待与页面响应分别计时。超过 `20` 分钟没有新的有效上游变化，记录为上游／环境条件未满足，不能证明 MiGate 的通知与报告链路通过；MiGate 已收到满足显示条件的新值后超过 `10` 秒未反映到页面，则属于完整链路未达标。可通过正常环境变化获得样本，不提高设备采样频率，也不以缓存主动读取替代真实通知。

所选样本必须实际形成原生通知到 Matter 订阅再到 Home 的更新链路。现有路径均无法取得有效通知时，自动更新目标尚未达成，应明确具体缺口，再决定是否扩大接入范围，不能将纯缓存展示记为完成。
