# 独立环境测量能力与 CO₂、照度接入

## 目标与范围

以 `ec69888` 为代码基线，新增 CO₂ 与照度接入，并将温度、相对湿度、CO₂、照度统一为独立识别的只读能力，再按物理设备组合。温度与湿度不再强制成对；只有一项有效测量的设备也可以接入。CO₂ 不依附于温湿度计，照度不依附于人体或存在传感器。

温度仅接入语义明确的环境温度。插座、开关、电热毯等设备的本体或加热部件温度，不因属性名为 `temperature`、单位为摄氏度就作为室温发布。接入不限制宿主设备类别、型号或名称，也不以固定 `siid`／`piid` 作为能力白名单。

使用现有本地中枢与米家云端来源；读数依靠首次读取、连接恢复读取和真实通知更新，不增加定时轮询、新网关协议或主机蓝牙扫描。物理设备共享电量继续按有效能力提供。本轮不扩展电气测量、噪声、距离、占用状态、强弱光枚举、历史曲线、浓度告警或自动化规则。

## 设计选择

能力解析分别判断四项测量，将成立的功能交给物理设备组装；设备分类不再决定是否执行测量识别。MIoT 服务用于判断测量语义和属性归属，不直接成为新的物理设备。

传感器发布采用统一父子端点结构：一个物理父端点，加上每项功能对应的子端点。单项测量也采用该结构，电量始终属于物理父端点。相较单项时合并端点、多项时再拆分，这个方案多使用一个端点，但只需维护一种传感器布局。

既有受支持的控制功能和测量能力属于同一物理设备时，组合在同一设备中，各功能保留自身语义；不因增加测量而获得原本不支持的控制能力。纯控制设备采用其现有端点布局。

灯组只隐藏成员灯的控制功能；测量及共享电量仍由原物理设备发布。纯灯光成员沿用现有隐藏行为。

## 能力识别

信任中枢和云端提供的能力描述、属性绑定、单位、量程及读数。MiGate 完成必要的协议解码，按标准语义与声明权限选择本轮支持的能力，内部直接使用已构造的模型和读数。不为假设性的上游错误、异常数值或结构变化新增校验、修复、fallback 或测试。数值适配集中在 Matter 发布处；真实的访问权限、连接和来源生命周期检查继续保留。

### 语义与单位

按 MIoT 标准服务和属性类型识别测量。`environment` 服务为 `0x780A`，`temperature-humidity-sensor` 服务为 `0x7814`；两者的温度、湿度都是可选属性，不要求组合出现。

| 能力 | 标准属性 | 服务语义 | 原生单位 | 功能键 |
| --- | --- | --- | --- | --- |
| 环境温度 | `temperature`，`0x0020` | 标准 `environment` 或 `temperature-humidity-sensor` | `celsius` | `temperature` |
| 相对湿度 | `relative-humidity`，`0x000C` | 独立查找标准属性 | `percentage` | `humidity` |
| CO₂ | `co2-density`，`0x004B` | 独立查找标准属性，表示空气中的 CO₂ 浓度 | `ppm` | `co2` |
| 照度 | `illumination`，`0x004E` | 独立查找标准属性 | `lux` | `illuminance` |

环境温度判断采用上述明确的服务语义，不凭设备名称、属性描述文本或量程猜测测量对象。独立的环境温度可以位于任意类别设备的环境服务中，也可以单独存在于温湿度服务中。

本轮使用同时声明 `read` 与 `notify` 的数值测量，绑定、单位和量程直接取自描述。测量功能只读，不要求或使用写权限。

`value-range` 只取上下限，步长不使用、不持久化，也不参与读数处理和配置比较。

### 独立功能与组合

分别提取描述中存在的受支持测量，生成独立功能，再组合到所属物理设备。缺少某项测量不影响其他项；没有受支持功能时不发布设备。多个服务按各自属性处理，例如多个人体检测服务中有一项提供照度，就提取该照度属性。

每台物理设备每类测量取描述顺序中的第一个合格候选，使用上述固定功能键。

电量从标准 `battery` 服务的 `battery-level` 属性读取，使用其声明的百分比量程及读取、通知能力。电量属于整台设备，不占测量功能键，也不单独组成设备；缺少电量或电量订阅失败不影响测量功能。

## 模块职责与数据流

| 模块 | 本轮职责 |
| --- | --- |
| `xiaomi/capability` | 独立提取四项测量及共享电量，直接建立属性绑定；移除温湿度必须成对及传感器宿主类型限制。既有控制解析与测量提取分别完成后组装物理设备。 |
| `device` | 明确区分四种测量功能，复用私有测量状态；物理设备持有共享身份、可用性和电量。 |
| `xiaomi/adapter` | 按功能判断读取和通知就绪、选择来源、接收观测和恢复；连接、账号与家庭生命周期仍由既有来源管理。 |
| `configuration` | 根据当前功能集合及灯组隐藏规则规划名称、端点和实际发布形状；传感器统一父子结构，配置原子应用。 |
| `storage` | 编码并恢复功能、绑定和身份。 |
| `matter` | 为各功能提供独立集群、数值投影和变化报告；物理父端点提供共享设备信息和可选电量。 |
| 终端界面 | 显示各项原生读数、单位、来源时间、接收时间、通知状态和对应诊断。 |

数据流为：米家描述 → 独立能力识别 → 物理设备组装与配置提交 → 来源读取／订阅 → 单项观测 → 测量状态 → Matter 投影与报告。测量解析不依赖控制解析成功；功能组合也不要求产生一次完整的多项样本。

复用测量状态、数值转换和报告跟踪，继续使用当前锁定的 `rs-matter` 依赖及其生成的集群接口。

Matter 功能处理器统一承接控制与测量，通过集中分发适配各集群接口。测量处理器直接使用已匹配功能的原生量程构造，目标表示不支持仍在 Matter 投影处诊断。

## 运行状态与来源生命周期

每项测量分别保存最后有效原生值、可取得的来源更新时间和 MiGate 接收时间。启动时读数未知；读数不持久化。初次接入、连接恢复或该项来源切换时读取，然后按上游通知节奏更新。

| 情况 | 行为 |
| --- | --- |
| 某项首次读取尚未成功 | 仅该项保持未知，其他功能可以更新。 |
| 单项读取失败 | 保留该项最后有效值并记录诊断，其他功能继续。 |
| 某项通知订阅失败 | 仅该项标记同步受限；已经成功的订阅继续接收，失败项沿用有限恢复机制。 |
| 正常静默或重复读到缓存 | 不设置统一过期超时，不以此推断设备离线；来源时间缺失时保持未知。 |
| 共享账号、家庭权限或连接失效 | 依据真实失效范围更新可用性并恢复，不接受已退休来源的迟到结果。 |

读取与通知就绪按功能判断，不再等待整台设备所有测量都订阅成功。每项沿用既有来源优先级，在对该项有效的路径中选择；一个功能的来源准备失败不能撤销其他功能已经成立的链路。来源连接可以共享，观测归属、就绪状态与诊断必须能归到具体功能。

订阅成功与失败按实际属性绑定维护，设备及功能诊断按需从属性错误生成，不另存汇总错误。有限重试、来源代次和共享电量的独立诊断保持各自生命周期；通用属性绑定直接由能力模型提供。

读返回与通知之间的先后关系沿用来源代次和请求生命周期约束，不以来源时间戳作为排序或去重依据。普通有效缓存读取可以提供当前可得值，但缓存时间不能被接收时间替代成新的采样时间。

物理设备有至少一项测量的读取或通知路径可用，或存在有效的既有控制路径时，可作为设备可用的依据；其他功能的受限状态分别诊断。只有电量路径可用不使设备可用。可用不等于传感器刚刚采样；没有可靠在线信号的蓝牙或代理设备继续区分获取通道可用与本体在线未知。

## Matter 发布

### 端点与集群

含测量能力的物理设备发布一个父端点及各可见功能子端点。父端点包含 Bridged Node、Descriptor、Bridged Device Basic Information；有有效电量时增加 Power Source。单项测量设备同样有父端点和一个子端点。混合组合中的控制子端点按其真实功能发布设备类型和集群。

| 测量子端点 | 设备类型及修订 | 测量集群及修订 |
| --- | --- | --- |
| 温度 | Temperature Sensor `0x0302`，revision `3` | Temperature Measurement `0x0402`，revision `4` |
| 相对湿度 | Humidity Sensor `0x0307`，revision `2` | Relative Humidity Measurement `0x0405`，revision `3` |
| CO₂ | Air Quality Sensor `0x002C`，revision `1` | Air Quality `0x005B`，revision `1`；Carbon Dioxide Concentration Measurement `0x040D`，revision `5` |
| 照度 | Light Sensor `0x0106`，revision `3` | Illuminance Measurement `0x0400`，revision `3` |

每个测量子端点提供 Descriptor、当前依赖的 Identify 处理器及所选设备类型要求的接口，不虚构米家端的物理识别动作。父子关系、PartsList、TagList、设备类型、集群列表、特性及属性列表与真实发布内容一致。四种测量采用确定顺序 `temperature`、`humidity`、`co2`、`illuminance`，仅包含成立的功能，顺序不意味着前一项是后一项的依赖。

CO₂ 端点启用浓度集群的 `NumericMeasurement`，单位为 `PPM`，测量介质为 `Air`，提供必需的可空读数与上下限。Air Quality 是该设备类型的必需集群；本轮不从 ppm 推导综合空气质量等级，其 `AirQuality` 为 `Unknown`。不启用浓度等级、峰值、平均值，也不虚构不确定度。

### 数值投影与报告

| 测量 | Matter 表示 |
| --- | --- |
| 温度 | 摄氏度乘 `100`，按标准范围投影为有符号整数。 |
| 相对湿度 | 百分比乘 `100`，投影为 `0..10000` 的无符号整数。 |
| CO₂ | ppm 数值转换为单精度浮点数，原生上下限按同一规则转换。 |
| 照度 | 对 `lux >= 1` 使用 `round(10000 × log10(lux) + 1)`；有效的 `0 <= lux < 1` 映射为协议的低照度特殊值 `0`。 |

温度、湿度和照度的整数投影采用最近整数舍入，恰好半整数时远离零。未知读数以协议空值表示，与有效零值、低照度特殊值区分。只在 Matter 转换处处理目标类型和量程限制；无法表示时报告该项映射不支持，不改写原生读数。

照度的非零编码处于 `1..65534`；低于 1 lux 的精确原生值仍保留在 MiGate，协议 `0` 仅表示低于可表示的正照度范围。照度最小非零范围由 `max(原生下限, 1 lux)` 投影，最大范围由原生上限投影，满足集群的 `1 <= MinMeasuredValue < MaxMeasuredValue <= 65534` 约束。典型值 `1`、`10`、`1000 lux` 分别编码为 `1`、`10001`、`30001`。对数公式与零值语义参见 [Matter.js 标准照度接口说明](https://github.com/matter-js/matter.js/blob/main/packages/types/src/clusters/illuminance-measurement.d.ts)。

发布属性、上下限与读数使用相同投影。MIoT 步长不作为 Matter `Tolerance`；对数编码与 Home 显示位数均不代表来源精度。只有投影后的可见属性改变时才更新相关数据版本和报告；仅接收时间改变不产生伪测量变化。

共享电量继续使用 Power Source 的百分比与既有低电量规则，EndpointList 覆盖本物理设备实际发布的父端点与功能子端点。电量缺失、未知和变化不改变测量端点结构。

## 配置与持久化

功能集合、绑定、原生量程和共享电量进入配置。身份采用来源与物理设备标识；各项测量采用上述稳定功能键。普通读数、更新时间、连接状态和电量阈值变化不属于发布结构变化，不触发配置重建。

配置准备和保存保持原子性：提交成功后才切换到完整的新配置；准备或保存失败保持此前已提交的当前模型配置，不留下部分端点。当前模型生成的身份、名称、端点及配对在正常重启后恢复；测量读数重新获取。

配置只支持当前能力模型，不提供旧配置或旧端点布局的升级兼容。

### 真机验收

验收环境为 macOS Apple Silicon、现有账号和家庭，使用当前模型生成的配置，并记录实际 iOS／macOS 与家庭中枢版本。认证使用现有凭据；真实样本按有效能力选择，不预设设备名称。静态样例和一次缓存读取不能替代端到端验收。

真机验收在 `review` 阶段进行。当前没有灯光控制与环境测量混合的真实设备，该组合及其灯组行为由自动测试覆盖。

| 项目 | 通过条件 |
| --- | --- |
| CO₂ | 至少一台真实设备在 Apple Home 显示 ppm 数值，详情页可接受；页面保持打开时，核对真实变化自动更新，不要求固定次数。独立首页磁贴和 ppm 阈值自动化不是要求。 |
| 照度 | 至少两台来自不同服务语义的真实设备显示 lux 数值，并观察可见真实变化自动更新；其中至少一台具有有效电量能力，同时核对共享电量归属。不要求固定变化次数，也不要求 Home 显示与原生值完全相同的小数位。 |
| 更新时延 | 每次等待上游新上报最多 `20` 分钟；从 MiGate 收到有效变化到已打开的 Home 页面更新不超过 `10` 秒。没有新上报的观察不算通过，不用重复读取缓存补足次数。 |
| 温湿度回归 | 至少一台真实设备分别观察一次温度和湿度的可见变化，确认组合重构后正常更新。单项温度、单项湿度及其余组合由自动测试覆盖，不把不存在的真机样本记为通过。 |
| 重启与恢复 | 当前模型配置下重启 MiGate `2` 次、重建实际获取连接 `2` 次，确认正常恢复读数与通知，身份、名称、端点和配对保持。仅验收样本实际提供的获取路径。 |

[SONOFF 官方 Matter 平台功能表](https://help.sonoff.tech/docs/AirGuard-CO2-5BYO)明确列出 Apple Home 支持其 CO₂ 数值。MiGate 的桥接拓扑、Air Quality Unknown 与实时报告仍需实际验证；若客户端不能显示 ppm，不能以协议读取成功代替通过，也不通过虚构空气质量等级绕过。
