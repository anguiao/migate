# 风扇控制与状态同步

## 目标与范围

以 `7c8a495` 为代码基线，接入 `dmaker.fan.p5c` 风扇，提供标准 Matter 开关、百分比风速和水平摇头，将米家侧的相关状态变化同步到保持打开的 Apple Home 页面。代表固件为 `2.2.2.0010`。

采用一个标准风扇端点，继续使用现有设备发现、能力解析和本地／云端通信机制。自然风由米家管理；Home 调速接管为直吹。自然风运行时，Home 显示设备保留的直吹风速设定，接受它与自然风曲线当前风量不同。

本轮不提供自然风预设选择、自定义曲线、自然风开关、自动模式、摇头角度、手动转向、定时关闭、童锁、提示音或指示灯设置。不为这些功能增加额外开关、模式设备或厂商自定义 Matter 属性。

## 设备输入与能力准入

代表设备的 MIoT URN 为：

`urn:miot-spec-v2:device:fan:0000A005:dmaker-p5c:1`

依据[公开 MIoT 描述](https://miot-spec.org/miot-spec-v2/instance?type=urn%3Amiot-spec-v2%3Adevice%3Afan%3A0000A005%3Admaker-p5c%3A1)，使用以下输入：

| 输入 | 代表绑定 `siid / piid` | 类型、访问与用途 |
| --- | --- | --- |
| 标准 `fan` 服务（`0x7808`）的 `on`（`0x0006`） | `2 / 1` | 布尔，可读、写、通知；实际电源开关。 |
| 同服务的 `mode`（`0x0008`） | `2 / 3` | 整数枚举，可读、写、通知；`0: Straight Wind`、`1: Natural Wind`。用于诊断和调速接管。 |
| 同服务的 `horizontal-swing`（`0x0017`） | `2 / 4` | 布尔，可读、写、通知；水平摇头设置。 |
| `dmaker-spec` 的 `dm-service`（`0x7802`）中的 `speed-level`（`0x0001`） | `8 / 1` | `uint8`，范围 `1..100`、步长 `1`，可读、写、通知；直吹风速设定。 |

开关、百分比风速和可识别的直吹模式共同构成稳定功能键 `main` 的风扇功能。水平摇头按有效绑定决定是否发布；代表设备具备此能力。绑定编号与模式枚举值从描述构造，不能用显示名称猜测属性用途。

百分比风速采用上述已确认的厂商服务与属性语义组合，并校验它的数值范围和访问权限。不把任意厂商的同名属性当成百分比风速；本轮也不增加其他风扇的离散挡位换算。缺少必需输入时通过现有未支持原因诊断，不降级为一个掩盖能力缺失的插座。

标准 `fan-level`（`2 / 2`）在直吹时表示粗挡位，在自然风时表示预设槽位，不能作为统一风速来源。`status`（`2 / 6`）表示供电电压类别，不能当作正在运行或已停止。自然风列表和自定义曲线不参与本轮读写与订阅。

## 状态与用户行为

分别保存实际开关、原生模式、直吹风速设定和水平摇头设置。请求目标、请求回执与设备观测分开；回执成功不直接修改这些实际状态。这里的风速是设备报告的设定值，不是转速测量。

| 状态或操作 | 约定行为 |
| --- | --- |
| 直吹运行 | Home 显示最新有效的 `speed-level`。直吹模式下，最终设备设定与 Home 百分比一致。 |
| 自然风运行 | Home 同样显示最新有效的 `speed-level`；不跟踪曲线，不把 `fan-level` 的预设槽位换算为百分比。 |
| 米家切换自然风预设 | MiGate 不干预模式或预设。若直吹设定未改变，Home 百分比保持不变。 |
| 独立开机 | 只开启电源，保留设备记忆的模式和风速。 |
| 设置非零风速 | 确保开机，切回直吹，应用目标风速；即使目标恰好等于显示值，也必须能够退出自然风。 |
| 关机或设置 `0%` | 关闭电源，Home 显示关闭、当前风速为零；保留原生直吹设定，不向只接受 `1..100` 的属性写入零。 |
| 调整水平摇头 | 只修改摇头设置，不附带开机、调速或切换风模式。 |

例如设备保留直吹设定 `40`，米家切到自然风后 Home 仍显示 `40%`。不同自然风预设可以具有不同的实际风量，这项差异是本轮接受的显示折中，不代表读取到了自然风的瞬时速度。

首次尚无有效观测时，对应字段保持未知。单次读取失败保留最近有效值并记录诊断；来源中断时更新可用性与同步诊断，不把未知或离线推断成关机。各属性可以分次到达，已有一个字段不代表其余字段已经建立基线。

## 命令顺序与失败处理

风扇命令复用现有设备写入门控、传输、回执和生命周期，在同一设备上维护顺序。逻辑操作包含独立开关、设置风速和设置水平摇头。

非零调速按以下步骤执行：

1. 写 `on = true` 开机。如果最近一次有效读取或通知显示风扇开着，且 MiGate 此后没有发过关机，就省略这一步。
2. 写 `mode = Straight Wind`，切回直吹。
3. 写 `speed-level = p`，设置风速，其中 `p` 是 `1..100` 的整数百分比。

刚发过关机、尚未收到新的开机反馈时，即使缓存还显示开机，也应执行第一步。

前一步收到成功受理回执后才发送下一步；不把多属性批量写入当成具有执行顺序或原子性的事务。全部必需步骤均收到成功受理回执后，才向调用方返回本次调速成功。模式写入成功表示请求受理，不表示直吹状态已经回传。无需等待风叶达到某个物理转速，也不增加步骤间的固定延时。

连续调速只合并相邻且尚未发送的旧目标，保留最新目标，不跨越中间的开关或摇头操作。关机取消它之前待发的调速，并阻止旧调速继续发送剩余步骤；已经发出的步骤仍按现有机制结算，再发送关机。关机之后收到的新调速按新命令处理，可以再次开启风扇。旧回执只结算其所属操作，不恢复被取消的目标。

上述关机打断只针对 MiGate 收到的明确关机操作。调速期间米家侧的操作不打断已开始的调速；通知仅更新实际观测，不识别外部操作来源或增加抢占处理。多方同时操作时，后续调速步骤可能覆盖米家设置，最终显示仍跟随设备反馈。

各步沿用现有本地请求 `10` 秒、云端写入 `15` 秒的超时处理。关机仍等待当前已发送步骤结算；回执迟滞或超时时，不承诺立即关机。

每一步发送前仍检查命令所有权、设备生命周期和当前可用路径。只允许现有机制对明确未发送的尝试重新选路；已经可能发送的写入不得在另一条路径自动重放，也不能从头重做整组调速。

任一步骤失败或超时，结束本次操作并返回明确失败，不继续后续步骤，不自动回滚已经受理的步骤。例如开机成功、切直吹失败时，设备可能仍按原模式运行；切直吹成功、设置风速失败时，设备可能按原直吹风速运行。显示与诊断依赖实际反馈，不把部分成功伪装成目标已完成。

独立开关和摇头分别只写对应属性。`Toggle` 沿用现有开关语义，要求实际电源状态已知。非零调速不得仅因为百分比与缓存一致就整组省略，必须同时满足开机与直吹接管的语义。

## 同步、选路与恢复

控制、读取和通知继续分别使用现有选路、权限、重连及恢复规则。`pushAvailable` 是当前中枢对具体设备声明的通知能力，不是整个局域网的总开关，也不固化成型号特征。它为 `false` 时不据此排除本地读写；通知来源按既有规则选择。

启动、配置激活和来源恢复时，为开关、模式、风速以及已发布的摇头属性建立读取与通知基线。外部米家操作通过活动通知来源同步，复用已有的读取失效和补读机制，不增加风扇专用轮询或每条命令后的整组补读。

同一功能的属性保留各自观测元数据。迟到的旧读取不能覆盖较新的通知，旧会话、旧订阅和已退休实例不能更新当前设备。重复同值观测可以刷新诊断时间，MiGate 不因此主动通知属性变化；可见投影变化须更新对应 Matter 数据版本并正常通知。

属性写入成功后，协议栈可以重报当前保留值；这不表示目标已达成，也不触发重复原生命令，实际状态仍只由有效观测更新。DataVersion 不作为实际变化次数或请求完成的证据。详见[已知限制](../../known-limitations.md#风扇)。

恢复重新建立状态与通知，不重新排入旧开关、旧调速或旧摇头操作。重启恢复身份、名称、端点和配对，重新读取设备状态；不持久化待执行命令，也不因为恢复了协议状态而向风扇补发控制。

## Matter 表达

沿用现有单控制设备布局，在同一个端点上组合 Bridged Node 与 Fan（`0x002B`，revision `4`），提供 Descriptor、Bridged Device Basic Information、Identify、Groups、On/Off 和 Fan Control。状态及模式变化不改变端点身份或发布形状。[Matter Fan 设备定义](https://github.com/project-chip/connectedhomeip/blob/v1.6.0.0/data_model/1.6/device_types/Fan.xml)

Fan Control 使用 `0x0202`、revision `6`。发布 `MultiSpeed`，`SpeedMax = 100`；具备水平摇头时发布 `Rocking`，仅支持 `RockLeftRight`。不发布 `Auto`、`Wind`、`Step` 或 `AirflowDirection`，不将米家自然风映射为 Matter 自动模式。[Matter Fan Control 定义](https://github.com/project-chip/connectedhomeip/blob/v1.6.0.0/data_model/1.6/clusters/FanControl.xml)

| Matter 项目 | 映射与写入行为 |
| --- | --- |
| `OnOff` | 读取原生电源状态；`On`、`Off`、`Toggle` 使用独立开关语义。 |
| `PercentSetting`、`SpeedSetting` | 开机时使用最新原生直吹设定；关机时为 `0`。写 `1..100` 进入上述调速流程，写 `0` 关机。 |
| `PercentCurrent`、`SpeedCurrent` | 已确认关机时为 `0`；已确认开机时使用最新原生直吹设定。自然风下按已接受的折中表达。 |
| `FanModeSequence` | `OffLowMedHigh`。 |
| `FanMode` | 关机为 `Off`；开机按直吹设定分段：`1..33: Low`、`34..66: Medium`、`67..100: High`。 |
| 写入 `FanMode` | `Off` 关机；`Low`、`Medium`、`High` 分别设置 `33%`、`66%`、`100%`，进入同一调速流程。标准中已弃用的 `On` 按 `High` 处理；无 Auto 特性时 `Smart` 按 `High` 处理；`Auto` 拒绝。 |
| `RockSupport`、`RockSetting` | 仅水平位有效；读写原生 `horizontal-swing`。其他方向位拒绝，不静默忽略。 |

两种关闭入口统一呈现为 `FanMode = Off`、协议风速为零。原生直吹设定仍独立保留，之后独立开机只写电源，由设备恢复记忆的模式与风速，再按反馈恢复协议值。Matter 允许独立 On/Off 保留 Fan Control 的设定属性；本轮选择上述统一关机投影，不增加区分“由哪个入口关闭”的持久化状态。[Matter 风扇开关说明](https://csa-iot.org/wp-content/uploads/2026/06/23-27351-010_Matter-1.6-Device-Library-Specification.pdf#page=116)

电源未知时不推断当前风速为零。已确认开机但风速未知时，速度仍未知。速度属性及 `FanMode` 在所需输入未知时读取失败；本轮未发布 Auto，不用设定属性的 `null` 表达未知或自然风。客户端写入空速度时保持原值、不发送控制，并返回 `InvalidInState`；越界速度、未支持的模式或摇头位返回 `ConstraintError`。[Matter 风速与模式规则](https://csa-iot.org/wp-content/uploads/2025/08/3-27350_matter-1-4-2-adopted-application-cluster-specification.pdf#page=362)

自然风下以记忆的直吹设定表达 `PercentCurrent`／`SpeedCurrent` 是明确的近似，不能称为自然风瞬时速度，也不据此宣称完整风速语义一致性。正常直吹仍要求设备设定、模式分段和协议属性相互一致。

使用当前锁定的 `rs-matter` 生成接口，显式选择属性、命令及 FeatureMap。[锁定版本的 IDL](https://github.com/project-chip/rs-matter/blob/319c791044d9aac352ac5afbbe31c3aa623842be/rs-matter-codegen/src/idl/parser/controller-clusters-V1.6.0.0.matter) 中 Fan Control 默认仍为 revision `5`，处理器须显式设置为上述 revision `6`。风扇处理器接入项目的异步命令与实际观测模型，不直接采用会自行持久化设置并在恢复时驱动设备的默认处理逻辑。

Home 的开关应使用独立开关语义；若客户端实际写入明确的非零风速或风挡，则按调速处理，不能猜测它原本只是想开机。验证 Home 的实际入口和协议写入，不预先声称 Home 一定提供独立风挡或摇头控件。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `xiaomi/capability` | 识别标准风扇输入与已确认的厂商百分比风速组合，构造有效绑定及能力形状。 |
| `device` | 增加风扇功能、分离的观测快照和有顺序的开关／调速／摇头操作；保留直吹设定与模式。属性值与观测时间复用通用观测容器，电源确认与命令顺序仍由风扇逻辑维护。 |
| `xiaomi/adapter` | 将原生输入转换为风扇观测，编码逐步调速；复用共享属性传输、DID 写入门控和来源生命周期。 |
| `configuration`、`storage`、`app` | 接入风扇描述、能力形状、配置编解码与激活，沿用现有事务和稳定身份分配。旧的受支持设备配置仍能读取。 |
| `matter` | 发布风扇端点，转换协议操作，按实际状态投影属性并驱动订阅报告。 |
| 终端 | `list`／`status DID` 显示开关、直吹设定、原生模式、摇头、命令结果及各来源诊断；现有 `on`／`off` 操作适用于风扇。 |

数据流为：MIoT 描述 → 风扇能力与已提交配置 → 读取／通知 → 独立状态观测 → Matter 投影与报告。反向控制为：Matter 操作 → 风扇命令顺序 → 当前路径上的原生属性写入 → 回执与独立反馈。

## 验证要求

自动验证覆盖以下行为：

- 代表描述的绑定、访问权限、直吹枚举与百分比范围；`fan-level` 和供电 `status` 不参与错误的速度或运行状态映射；摇头能力决定发布形状。
- 开关、零速、非零调速、相同百分比退出自然风、摇头独立性；关机保留原生设定；模式分段边界 `33/34`、`66/67` 及端值 `0/1/100`。
- 逐步调速的顺序、全部必需步骤受理后才返回成功、逐步失败与超时、连续目标合并、关机打断未完成调速、关机反馈未到时的新调速仍能开机、旧回执隔离和可能已发送写入不重放。
- 初始未知、部分状态到达、自然风显示折中、重复报告、旧读取与新通知竞争；恢复基线不补发控制。
- 本地与云端既有控制／读取／通知组合，包括设备 `pushAvailable = false` 时读写与通知分别选路；来源及实例生命周期隔离。
- Matter 元数据、属性与命令约束、数据版本和订阅；配置往返、重启身份及现有插座、灯具、灯组、窗帘和传感器回归。

执行 `cargo fmt --check`、`cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 和当前 macOS 环境的 `cargo build --locked`。

真机验证使用 `dmaker.fan.p5c` 风扇，以米家 App、原生属性、实际动作及保持打开的 Home 页面相互对照：

| 场景 | 要求 |
| --- | --- |
| 基本控制 | 独立开关、`1%`、`40%`、`100%`、`0%` 及水平摇头开关各 `3` 轮。非零调速最终为直吹且原生风速等于目标；摇头不改变电源、模式或风速。观察 Home 写入后的显示、是否回弹及最终稳定时延，并与原生反馈对照。 |
| 自然风显示与接管 | 保留直吹 `40`，在米家选择两个不同自然风预设，Home 均显示记忆的 `40%`；随后从 Home 设置其他风速退出自然风。另验证写入相同 `40%` 仍会接管为直吹。 |
| 记忆与关闭 | 自然风和直吹各验证独立关机再开机，模式与设定由设备保留；零速关闭也保留原生直吹设定。关机期间协议当前风速为零。 |
| 外部操作 | 在米家改变电源、直吹风速、模式和摇头，完成 `3` 轮；Home 持续打开，无需重开页面或手动刷新。切换自然风预设不要求 Home 百分比变化。 |
| 连续控制 | 快速改变风速并立即关机，确认旧调速不会使风扇再次开启；关机后主动发送新风速可以重新开启。 |
| 重启与路径恢复 | 各 `1` 轮，确认状态与通知恢复、身份和配对保持，且旧命令不重放。实际使用的路径以诊断为准。 |

正常网络且来源已就绪时，影响 Home 投影的外部状态变化应在 `3` 秒内反映到 Home；中间属性按设备实际报告节奏处理，不推算风叶转速或自然风曲线。重启、断连与选路恢复沿用最长 `20` 分钟观察上限：断线从通信条件恢复起计，重启从 Matter 服务重新提供起计。

分别确认请求受理、设备实际行为与状态回传。通知验证必须看到新的属性报告；不能用重复读取缓存代替。Home 未提供某个入口时，用 Matter 调试客户端验证该协议操作，并分别记录 Home 能表达的实际行为，不把缺失入口当作已通过的 Home 控制。
