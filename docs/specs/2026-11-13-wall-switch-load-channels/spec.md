# 墙壁开关与负载通道接入

让 Apple Home 按回路控制墙壁开关。每条直控回路作为独立配件，可以分别命名、分配房间和加入场景。米家侧通过同一块物理面板读写各路继电器。以 `main` 的 `8aa85a0` 为基线，在 macOS 上沿用现有 Rust 单包。

## 设备与回路

## 从米家识别负载

在 MIoT 标准设备 `switch` 或 `control-panel` 下，按标准 `switch` 服务识别每路负载。同一服务的 `on` 须为可读、可写、可通知的布尔属性。可读的 `mode` 须能区分直控和无线，首批设备的枚举分别为 `0` 和 `1`。通断值来自该路 `on`，是否在 Home 发布由该路 `mode` 决定。指示灯的 `on`、`switch-sensor` 的点击事件以及 `xiaomi.switch.w3` 的单击／多击模式各有独立含义。缺少必要绑定或无法识别模式语义时，在诊断中说明受影响的回路，同机其他有效回路继续工作。

以**当前家庭、整机 DID 和继电器 SIID**定位回路。多键设备的米家分路目录记录提供名称，其中 `extra.split.parentId` 指向整机，`moduleId` 对应继电器 SIID。即使分路记录携带整机的完整描述，也只认领该路的目录信息。智能面板的整机记录没有子项列表，同样可用分路记录的父子关系归属名称。所有读取、写入和通知都定位到整机 DID 上的真实属性。

切换当前开发数据目录时，在应用外按米家目录一次性整理现有面板的整机记录和分路归属，保留已配对设备的身份与端点。应用只读写本轮存储格式。

四种墙壁开关在米家目录中均为 BLE Mesh（`pid=16`），智能面板为 Wi-Fi（`pid=0`）。同一面板的回路共享连接与访问资格。读写沿用可用的中枢或米家云端路径，云端使用 `datasource=2` 请求设备当前值。属性通知由具备资格且订阅就绪的中枢或云端提供。首批五个型号均使用标准 MIoT 属性。[小米属性读取接口](https://github.com/MiEcosystem/miot-plugin-sdk/blob/master/miot-sdk/service/spec.js#L32-L45) · [小米连接类型定义](https://github.com/XiaoMi/ha_xiaomi_home/blob/main/custom_components/xiaomi_home/miot/i18n/zh-Hans.json)

## 模式、通断与反馈

- 首次取得直控模式才发布该路。已知无线模式时隐藏该路电源，继续观察模式，转回直控后恢复原有名称、类型和身份。整块面板都隐藏时，原有属性读取和可用通知仍能发现模式变化。
- 模式复用启动读取、属性通知和普通属性约 60 秒的周期回读。首次读到模式前沿用已有的发布配置，无历史记录的回路等待有效读数。单次回读失败保留最近一次确认的模式。模式变化只调整发布，不向继电器写电源或向面板写模式。
- Home 命令从当前配件定位到一个继电器，只写该路的 `on`，按既有命令路径返回受理结果。Home 的通断读数和订阅报告取自该路真实通知或回读，在首个有效通断值到达前状态为未知。实体按键或米家 App 改变回路时，适配层将反馈送往对应配件，通知已就绪时即更新持续打开的 Home 页面。
- 终端的 `on DID FUNCTION` 和 `off DID FUNCTION` 按整机 DID 和回路标识直接操作继电器。已转无线的回路仍可手动控制，适用相同的设备访问资格和连接条件。
- 断连保留最近有效通断值。启动或重连时，已发布的直控回路随读写路径恢复即可接受新命令，模式和通断由正常补读及通知更新。冷启动时，即使米家家庭目录暂时不可用，只要当前家庭的中枢已确认该设备可读写，Home 即可控制已发布的直控回路。重启、改类型、转无线和恢复连接都不重放旧控制。对已撤权、移除或已确认转无线的回路，旧 Home 入口发来的新命令不得下发到设备。

## Home 配件、名称与稳定身份

配置层把每条可见回路派生为独立的桥接配件。每路有自己的 Matter 端点、唯一标识和可命名的 Bridged Device Basic Information。聚合器列出这些配件，每路直接承载它的开关或灯功能。现有多路插座继续以整机及其功能子端点发布，作为布局对照。[Matter 桥接端点示例](https://github.com/project-chip/connectedhomeip/blob/master/examples/bridge-app/linux/README.md)

| `TYPE` | Home 表达 | Matter 表达 |
| --- | --- | --- |
| `switch` | 普通开关，直控回路的默认类型 | On/Off Light Switch（`0x0103`）。沿用协议栈的 Switch 客户端声明和 Binding 服务，同一端点提供可读取、控制和订阅继电器的 On/Off Server。 |
| `light` | 只能开关的灯 | On/Off Light（`0x0100`），仅呈现回路实际拥有的通断能力。 |

两个类型共用一个继电器功能和反馈来源。普通开关的 Descriptor 同时声明 On/Off Client 和 Server，Home 通过 Server 操作负载。两种类型都应在 Home 实际可控，并报告真实通断。[Matter SDK 的 Apple Home 设备类型说明](https://github.com/project-chip/connectedhomeip/blob/master/docs/guides/darwin.md#supported-device-types-in-apple-home)

多键设备首次使用该路的米家名称。单键设备用米家整机名称。若多键分路缺名，使用面板名和稳定的回路号区分各路。控制器写入 `NodeLabel` 时，MiGate 按回路保存名称。配件身份和端点按整机 DID 与稳定功能标识 `relay:<SIID>` 保留。类型变更、隐藏后恢复、重启和重新读取描述均复用已分配的身份，其他回路的编号与名称不随之变化。Home 管理仅在客户端设置的名称、房间与场景，改类型后是否保留这些设置取决于 Home。

同一米家账号和家庭内，回路改型或转无线、端点增删、灯组关系、设备能力和来源实例变化按原规则重建 Matter 服务，保留控制器已保存的订阅。新实例用原订阅向同一控制器报告当前描述和状态，只展开当前可见且允许访问的路径。单设备撤权即退役该来源；即使新配置保存失败，恢复报告也须排除被撤设备，其他配件继续报告。切换米家账号或家庭时，新范围与旧订阅的清除同时提交。Matter 控制端的配对归属和访问权限由协议栈在报告时核对。

## 类型配置

终端提供通用命令 `map-type DID FUNCTION TYPE`。例如，将 `DID` 换成 `list` 中的面板标识后，`map-type DID relay:3 light` 将该路映射为灯，`map-type DID relay:3 switch` 恢复普通开关。命令要求目标是当前家庭已识别且有访问资格的回路。映射按其稳定功能标识持久化，在该路直控时生效。改类型只更新配置和 Matter 发布，两种类型共用原端点。重复指定同一类型没有额外效果。无效目标或不支持的类型报告原因。写入配置失败时继续使用上次生效的配置。

`list` 列出整机 DID、回路标识、名称、实际模式和映射类型。用 `status DID` 查看逐路通断、模式、读写绑定、当前读取与通知路径，以及可见或隐藏的原因。未显式配置类型的直控回路使用默认的 `switch`。

当前家庭已确认的 23 路直控照明按 `list` 中的整机 DID 和回路标识一次性映射为 `light`，其中代表样本的中路在完成默认普通开关检查后设定。以后新增的直控回路默认显示为普通开关。

## 验证标准

自动化使用五种型号的实际描述结构和可控通信对端，覆盖整机与分路去重、单键命名、按键模式与继电器反馈分别处理、全无线后恢复可见、同面板三路命令与订阅隔离。无线回路的旧 Matter 端点不可控制继电器，终端显式指定该路时仍可写入。通过正常终端和 Matter 入口验证未配置回路的默认类型、两种类型的控制、重复设置、持久化及失败后仍使用原配置。核对逐路独立端点的名称和稳定身份，以及 `cuco.plug.cp7pd` 的既有端点、三路控制与总控触发回读。执行 macOS 上的 `cargo fmt --check`、`cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 和 `cargo build --locked`。

Apple Home 真机验收以实际负载动作和持续打开的页面为准。代表开关每次只操作一路，其他两路的物理负载和 Home 读数都应正确。左、右路全程映射为灯。中路以默认普通开关完成 Home 和实体键各一次开、关，确认按键操作能更新普通开关读数。随后把中路映射为灯，核对其 Matter 端点、唯一标识和 MiGate 已保存的名称，再用米家 App 操作。三路合计 18 次动作。

| 场景 | 操作与判据 |
| --- | --- |
| Home 发起控制 | 三路直控样本的每路各开、关一次，共 6 次。每次从点击到对应灯实际动作不超过 **5 秒**。每路显示米家名称，在 Home 中可作为独立配件选择房间。 |
| 实体按键改变回路 | 三路各用对应实体键开、关一次，共 6 次。每次从灯实际动作到已打开的 Home 页面自动显示正确状态不超过 **10 秒**，全程无需刷新或重开页面。 |
| 米家 App 改变回路 | 三路各在米家开、关一次，共 6 次。采用相同的 **10 秒**时限，保留另外两路的状态。 |
| 转无线的回路 | 解耦样本只显示左路。`xiaomi.switch.w3` 和智能面板的三键均转无线时，Home 隐藏各自的全部电源入口。检查时让解耦样本的中、右两路持续供电。 |
| 重启与断连恢复 | 使用原数据目录，分别在普通重启和中路改型后立即重启时测试未改型的左路，再做一次通信断开与恢复。从进程启动或连接恢复起 **120 秒**内取得新的通断反馈并能控制。核对配对、各路名称、端点和已保存的灯映射，确认旧命令没有重放。 |
| 多路插座回归 | 选一台方便操作的 `cuco.plug.cp7pd`，两路插座和 USB 各开、关一次，再操作一次米家总控，核对三路按各自真实反馈更新，仍归属同一台插座。 |

运行指南补充如何通过 `list`、`status` 和 `map-type` 查找回路、指定类型及排查未显示或未同步。已知限制记录与本次接入相关的 Home 或协议能力边界。
