# 多终端管理与在线认证

MiGate 作为系统服务或前台进程运行时，用户可以从同一主机的其他终端连接它，包括通过 SSH 登录后的 shell。遇到设备无响应时，可以直接检查当时的连接路径、发出控制命令并核对反馈。设备连接、实时状态和持久化写入均由运行中的网桥负责。[开机自启设计中的多终端计划](../2026-11-19-linux-runtime-and-autostart/spec.md#后续计划)

## 命令入口

以下命令均按现有的 `--data-dir`、环境变量和默认目录规则选择实例。

| 命令 | 行为 |
| --- | --- |
| `migate` | 启动网桥，前台可直接输入命令。同一目录已有网桥时，提示使用 `migate attach`。systemd 和 launchd 继续使用这个启动入口。 |
| `migate attach` | 打开交互会话。可执行现有的全部查询、设备控制、映射和传感器绑定命令，以及 `auth` 和 `pairing` 命令。 |
| `migate <命令及参数>` | 在 shell 中执行一条相同的命令。比如 `migate status DID` 输出设备诊断后退出。命令执行成功返回零，失败返回非零。 |
| `migate auth login`、`migate auth check`、`migate auth logout` | 有网桥时由网桥执行。网桥未运行时可沿用独立认证流程，完成后退出。 |

`attach` 和需要在线网桥的单次命令遇到网桥未运行时，提示如何用同一数据目录启动。前台网桥收到 Ctrl-C 或 SIGTERM 时停止，标准输入结束后继续服务。在 `attach` 中按 Ctrl-C、结束输入或断开 SSH，只结束该客户端会话。

## 本机连接与命令执行

网桥取得 `instance.lock` 后，在运行用户的私有数据目录中创建 Unix 域套接字。套接字的生命周期覆盖等待登录、准备设备、正常服务和 Matter 实例重建。不同数据目录拥有各自的入口。在线客户端通过套接字访问网桥，数据库只由持锁进程打开。

认证命令先连接管理套接字。仅当套接字不存在或拒绝连接时，认证进程才尝试获取目录锁。取得锁后独立执行，锁已被占用则直接提示“数据目录正在使用，请稍后重试”并退出。权限错误和协议错误直接报告。持锁网桥负责回收套接字，包括崩溃残留的套接字文件。发现同名的其他类型文件时，报告路径冲突并保留该文件。

前台输入和客户端请求共用命令解析与执行逻辑。每个会话按输入顺序提交命令，输出和最终结果返回发起端。例如登录请求先显示二维码，再等待手机确认。来自不同终端的设备控制和配置修改可以逐条执行。一个终端等待扫码或设备回执时，其他终端仍能查询状态，已上线的网桥继续为 Apple Home 服务。单次命令的退出码取自执行结果，交互会话在命令失败后可以继续使用。

网桥收到并受理完整的设备控制命令后负责执行。发起终端断开时，已受理的命令即使还在排队也照常处理。执行时仍须具备原账号和家庭下的设备访问权限。退出账号后，该账号尚未发出的控制命令随之失效。已发送的控制沿用现有回执和反馈语义。客户端提交命令后若在收到最终结果前检测到断线，提示结果未知，单次命令以非零状态退出。用户可重连后用 `status DID` 核对。重连只建立新会话，重发控制需要用户再次下令。

## 网桥运行中的米家认证

缺少账号时，网桥保持管理入口可用并报告“等待米家登录”。此时可执行 `help`、`status` 和认证命令，需要设备的命令会显示等待原因。首次登录提交凭据后，同一进程自动进入现有网桥启动流程。准备家庭和设备期间，`status` 显示当前进度。若家庭尚待确认或目标设备尚未就绪，控制命令立即返回原因，单次命令以非零状态退出。设备就绪后由用户重新下令。

网桥一次只受理一个用户发起的认证操作，包括可能刷新令牌或续证的 `auth check`。其他终端同时发起认证命令时，立即提示正在进行的操作。如果后台已经在刷新同一份 HA OAuth 令牌，`auth check` 等待这次刷新，成功后用新凭据完成余下检查，失败时按现有规则报告各项状态。

等待同账号重新扫码期间，原有可用设备连接继续服务。新凭据提交后，运行中的适配器随即采用新记录。新凭据已提交或账号已成功退出时，网桥丢弃随后返回的旧凭据维护结果，保留当前的凭据记录与运行状态。

网桥在等待扫码时也监听发起会话的断开事件。该会话在凭据提交前断开时取消登录，已有账号可继续使用。提交后断开则采用已保存的新凭据，证书维护结果可通过 `auth check` 查看。已有账号时仍执行同账号校验，主动换号通过退出后重新登录完成。[现有认证的提交与恢复语义](../2026-11-04-unified-xiaomi-cloud-access/spec.md)

`auth logout` 成功返回时，原账号的设备连接和 Matter 服务已经停止。已连接的终端继续可用，管理进程重新等待登录。Home 中的网桥暂时离线，Apple Home 配对保存在数据目录中。同一账号重新登录后用原配对恢复。在同一目录登录其他账号时，网桥按新账号和家庭重新确认可访问的设备，原先配对的 Home 随后可以控制这些设备。清理失败时返回错误，并以实际保存的账号状态为准。

## 从终端查看和重开配对窗口

在 shell 中使用 `migate pairing` 和 `migate pairing open`，也可以在交互会话中直接输入以下命令。米家未登录时，两条命令都提示“等待米家登录”。已登录但 Matter 尚未就绪时，提示当前等待原因。配对详情由运行中的 Matter 实例提供。[现有 Home 配对流程](../../running.md#添加到-apple-home)

- `pairing` 在已配对时显示已配对。未配对时显示窗口是否开放，开放时显示二维码、手动配对码及剩余时间。
- `pairing open` 在未配对且窗口关闭时打开 15 分钟窗口，成功后返回配对信息。窗口仍开放时，重复调用返回当前配对码和原到期时间。已配对时直接报告已配对。

未配对的 Matter 实例启动时自动开放 15 分钟窗口。设备配置变化触发实例重建时，新的未配对实例也从启动时重新计时。`pairing` 显示当前实例的实际剩余时间。打开窗口的终端断开后，手机仍可在有效期内完成配对。

## 验收条件

| 场景 | 可观察结果 |
| --- | --- |
| 多终端排障 | 在 macOS 和 Linux 分别用两个独立客户端连接同一网桥。一个终端等待设备回执时，另一个能用 `status DID` 查看设备路径。前台、`attach` 和单次命令给出一致结果。同一条错误命令在单次执行时返回非零，在交互会话中显示原因后可以继续输入。 |
| 首次登录后等待家庭确认 | `status` 显示等待原因。单次控制命令立即返回原因并以非零状态退出。家庭和设备就绪后，只有用户重新下达的命令才会执行。 |
| 控制命令提交后断线 | 网桥已受理的控制命令仍在排队时断开发起端。设备可用且访问权限有效时，该命令照常执行一次，重连后可核对反馈。 |
| 登录和会话中断 | 一个终端等待扫码时，另一终端可查状态，同时发起的认证命令得到忙碌提示。凭据提交前断开发起端会取消登录，提交后断开仍采用新凭据。较早发出的后台维护请求随后返回时，网桥仍使用本次登录提交的凭据。 |
| 后台刷新与在线检查 | 后台正在刷新 HA OAuth 令牌时执行 `auth check`，小米只收到一次刷新请求。刷新成功后，命令用新凭据完成余下检查并报告结果。 |
| 在线退出和恢复 | 退出后 MiGate 拒绝针对旧账号设备的控制。即使旧请求随后返回，网桥仍处于等待登录状态。Home 暂时离线，已连接终端仍能登录。同账号恢复原配对。换账号后，原先配对的 Home 只能控制新账号和家庭已确认可访问的设备。 |
| 配对窗口 | 未登录时两条配对命令都提示等待登录。同一 Matter 实例的窗口开放期间，查看或重复开窗得到相同的配对码和到期时间。过期后可在原进程重开。未配对时因设备配置变化重建实例，会打开新的 15 分钟窗口。完成配对后显示已配对。 |
| 目录归属与异常退出 | 无网桥时独立认证可用。套接字未就绪且目录锁已被占用时，认证命令提示稍后重试并退出。权限错误直接报告。网桥异常退出后可用原目录重启，其他数据目录的实例独立运行。 |
| 用户设备上的操作 | 以现有系统服务启动网桥，通过 SSH 完成登录、查询、一次设备控制和反馈核对。退出并重新连接终端后，Home 仍可使用同一网桥。 |
